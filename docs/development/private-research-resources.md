# 私有工程资料管理

更新时间：2026-10-23

用途：规定非公开标准、图书、物性数据、参考模拟与工程依据的本地管理，以及公开仓库的提交和打包边界。

读者：项目所有者、维护资料索引或使用参考资料的协作者。

不包含：私有资料目录清单、出版物全文、已通过的工程验证、产品资料服务或 v3 格式扩展。

## 仓库与访问边界

- 独立资料仓库命名为 `RadishFlowResearch`，本地根目录为 `<RadishFlow>/private-resources/`，拥有自己的 `.git`；不采用 Git 子模块，主仓库不记录 gitlink 或远端地址。
- 当前仅限本地管理，不配置远端、不上传资料，也不配置 LFS、云同步或自动下载。今后共享、托管和备份方案按实际使用权限另行审定。
- 主项目源码许可证不适用于第三方资料。持有文件、能够阅读或存于私有目录，都不表示获得再分发许可；使用权限和技术审阅状态分别登记。
- 公开构建、基础测试、文档链接检查不得依赖该目录存在。私有验证缺资料时必须明确标为未执行，不能把缺失验证记为 B04 或其他验收通过。

## 分类、索引与入库

私有仓库的 `README.md` 和 `catalog/README.md` 是本地入口；机器可读索引为 `catalog/resources.json`。精确文件名、原始本地位置和校验值只放私有索引，不复制进公开周志或提交信息。

资料按 `standards/`、`literature/`、`calculations/` 分类；物性数据库、外部模拟文件和工程方法验证包到位时，再分别增加 `thermophysical/`、`simulations/` 与 `benchmarks/`。不为目录完整而预填工程数据。

1. 复制原件，保留原文件名和字节，下载目录中的原件不删除、不移动。
2. 为资料分配稳定编号，记录类别、版本、来源、字节数、SHA-256、使用权限和审阅范围；未知作者或版本明确留空，不根据文件名补造。
3. 新版使用新目录并保留旧版；模拟文件补充软件版本、物性方法、输入条件和复现步骤。
4. 在私有仓库运行 `python3 scripts/verify_catalog.py`，核对路径、身份、字节数与 SHA-256，再单独提交。
5. 宏工作簿归档不等于授权执行宏、刷新外部链接或运行计算。临时 OCR、截图、摘录与转换结果放私有 `derived/` / `.cache/`，默认忽略；长期保留的派生资料另行登记来源并审阅。

资料入库、文献审阅、工程方法验证、产品验收和实际设备性能验证是不同状态。G0 来源可以人工记录资料编号与章节定位，当前不增加文件解析器、自动引用解析或产品格式字段。公开文档只保留允许公开的引用和必要结论。

## 防误提交

- 主仓库 `.gitignore` 忽略整个 `/private-resources/`；`.gitattributes` 对该目录设置 `export-ignore`，作为 Git 源码归档的额外防线。
- `cargo run --locked --quiet -p xtask -- check-private-resources` 检查主仓库索引：拒绝私有路径、gitlink，以及指向私有目录的已暂存符号链接；同时确认忽略规则生效。检查在读取文件正文前停止，不打印私有文件名或内容。
- 正式 `check-repository-governance` / `check-repo` 自动执行该检查，公开 CI 不需要访问私有仓库。
- 当前维护工作区的 `.git/hooks/pre-commit` 调用版本化的 `scripts/hooks/pre-commit`。其他克隆需自行安装；若已有 hook，应合并调用，不覆盖原有规则。hook 使用离线锁定依赖的 xtask，缺少工具或缓存时提交失败，不自动下载。
- 私有仓库当前安装本地 `pre-push` 拒绝推送，并保持没有远端。该 hook 不随克隆自动安装；今后获准上传时应重新审定共享范围和许可。

这些措施防止常见误操作，不是加密或不可绕过的访问控制。`--no-verify`、改名后复制资料、手工压缩、硬链接或外部同步不由 Git 忽略规则自动防护；发布内容仍须审阅。不要把原始资料、提取数据或敏感结果复制到公开源码、测试、日志、PR 或报告中。

## 防误打包

`scripts/package.ps1` 保持显式选择入口文件和示例目录，不遍历整个工作区：

- 打包前执行私有资料边界检查；与正式构建一致使用 `--locked`，允许缓存不全的公开 CI 下载锁定依赖。只有依赖缓存齐全时才适合额外指定离线模式，本地提交 hook 的强制离线约束独立保留。
- 文档和示例只复制主仓库已跟踪文件；忽略示例目录里的未跟踪临时文件。
- 输入、输出及其祖先路径不能包含 `private-resources`，也不能通过符号链接或 junction 绕转。
- 拒绝复用已有 staging 目录；必须选择新输出位置，或显式传入原有 `-Clean` 参数清理，避免旧文件混入归档。
- Studio 二进制与脚本生成的清单仍为明确列出的构建产物；本规则不声称能够识别任意文件内容中的商业数据。

Git 的 `export-ignore` 只约束 Git archive，不约束任意 ZIP、文件管理器或第三方打包器。新增发布入口必须遵守相同的显式选择与隔离规则。
