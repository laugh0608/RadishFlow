## 产品任务与功能分区候选

功能分区先按用户任务组织，不按 crate、计算后端或 AI 实现组织。下表是必须找到承载位置的任务，不是已经冻结的顶层菜单数量与名称。

| 功能域 | 主任务 | 与其他域的关系 |
| --- | --- | --- |
| 项目与开始 | 新建 / 打开、最近项目、返回工作区、设计基础、工况与任务选择 | 项目基础可被案例显式覆盖；可以从流程、物性或设备开始 |
| 组分与物性 | 组分、方法、参数、来源及独立分析 | 物性有独立工作区入口；设备和流程共享所选数据 / 模型 |
| 流程建模 | 对象、连接、规格和案例 | 流程图为此任务的主区域，设备详情按身份关联 |
| 设备工程 | 独立或流程关联的尺寸估算、设计、校核与采纳 | 评估独立一级入口 / 工作区和对象上下文入口；不受旧“设备不作一级导航”约束 |
| 运行与研究 | 检查、目标反算、工况矩阵、未来批量与动态实验 | 运行控制与案例任务关联，仿真时间不等于软件脚本等待 |
| 结果与输出 | 当前结果、设备计算依据、后续比较和报告 | 只消费有来源的结果，统一单位转换；完整报告按功能阶段进入 |
| 工具与设置 | 单位集、显示偏好、变量浏览、录制 / 扩展入口 | 只展示可用能力；单位是跨任务规则，不在每页复制定义 |

确定性建模辅助应贴近当前对象、规格和诊断，并提供工作区汇总 / 定位，不默认建设孤立“智能中心”。未来 Agent 的交互位置待真实接入时评审，当前不增加无功能聊天入口。

## 首批必须评审的代表路径

1. **单位输入与显示**：固定显示单位→临时选择输入单位→校验并提交→回显；切换显示单位→结果 / 导出一致→保存重开。覆盖非法 / 未完成草稿、温差 / 温度、缺转换上下文和精度。
2. **规格与推荐**：缺项或规格冲突→查看依据→定位字段→修正 / 执行建议→重检→运行；覆盖未分析、不支持、建议过期、对象删除和撤销。
3. **分离器任务**：从独立设备或流程对象进入→引用工况 / 补准则→推荐尺寸→查看控制条件→采纳 / 撤销→保存；覆盖上游变化、单相 / 不适用、缺物性和无可行方案。
4. **换热器任务**：选择设计 / 校核→冷热侧输入和规格→给定 U 或几何→计算→审阅热负荷 / 温差 / 压降与依据；区分初步热工与详细设计能力。
5. **现有流程回归**：空白项目→物性→Feed / Mixer / Heater / Cooler / Valve / Flash 受控路径→结果→保存重开。新分区不能破坏现有功能可达性和错误恢复。
6. **工程基础与工况**：填写共享公用工程条件及来源→为不同工况显式覆盖→查看哪些设备引用→修改后识别失效结果；同几何跨工况比较需显示控制条件和失败 / 未运行行。
7. **目标与工程交付**：选择目标 / 可调变量及范围→试算→审阅残差和候选→采纳→查看分层检查与带来源计算表。数值失败、未找到解和规格冲突分别呈现。

本轮新增的 [工程基础 G0](../topics/engineering-basis-and-cases.md) 优先进入 R0，明确项目、共享基础、工况、设备及结果层级；来源详情就近展开，公共条件、原始输入 / 覆盖、未知来源和复现条件不足均有对应状态。

未来设备页面可展示标有规划状态的设计样例，但代码中没有真实能力的操作不能伪装可用。代表路径分别映射单位 U、辅助 A、设备 E / S / H 的实施阶段，不要求首版一次实现所有画板中的长期功能。

## 状态、命令与呈现边界

| 内容 | 事实来源与要求 |
| --- | --- |
| 工程输入、对象和连接 | 现有文档身份、输入事务与命令；新任务模型在所属专题定义 |
| 草稿与单位 | 草稿文本 / 输入单位、统一量元数据和显示单位集；转换后才提交工程值 |
| 设计基础 / 工况 / 来源 | 工程基础的稳定身份、共享条件、显式覆盖、来源和确认状态；不随页面各存副本 |
| 规格、自由度与建议 | 领域检查结果，带范围、方法、规则身份、修订和目标；未分析不画成“0” |
| 求解与任务 | 正式运行状态和诊断，当前同步求解不绘成已支持后台取消 |
| 流程结果 | 当前修订的 SolveSnapshot；stale / missing 不伪装为当前成功值 |
| 设备结果 | 未来独立设备任务的工况、方法和结果身份；候选与已采纳几何明确区分 |
| 输出与报告 | 引用结果、单位集、工况 / 方法版本和来源；显示分层检查、控制工况及未完成项，不重算或伪造总绿灯 |
| 显示偏好 | 独立呈现配置，不因显示切换使计算过期；保存需求与物理输入修订分别管理 |

所有新入口复用同一变量 / 动作与状态所有权，禁止在页面里维护第二份设备、组分、单位系数或可运行判断。现有 command 不存在时，设计可以标明所需能力和阶段，代码不能使用空回调充当完成。

## 重设计阶段与验收

| 阶段 | 产物 | 退出标准 |
| --- | --- | --- |
| R0 信息架构 | 任务地图、导航候选、页面 / 上下文边界、能力与状态矩阵 | 独立物性 / 设备、流程关联、单位、规格及工程基础 / 工况路径有清楚入口；记录保留、替换和待定的旧结构；项目所有者评审 |
| R1 代表交互与 Pencil 主稿 | 优先单位 / 规格局部交互，再设备任务与跨页流程；正常及失败状态画板 | 通过 Pencil 原生读取 / 截图 / 布局复核；无溢出、遮挡、失联入口；记录实现范围、规划态和评审结论 |
| R2 按功能切片落地 | 正式 presentation / command 映射、代码与指南 | 相应功能真实可用；主路径 / 失败 / 保存恢复验收；平台未测项明确，旧实现不退化 |

R0 与后续基础规划衔接；B3-5、纯单位转换和规则逻辑不等待全套新 UI。涉及新入口、布局或字段交互的实现需完成对应 R0 / R1 局部评审，不要求先画完所有未来设备。已有功能的小修仍按原已验证路径推进，重设计不成为全仓维护门禁。

## `.pen` 与文档规则

- 现有主文件为 `docs/architecture/designs/studio-client-main.pen`，设计输入为同目录 `studio-client-main-brief.md`。
- `.pen` 仅通过 Pencil MCP 读取、创建、修改、验证和导出，不用文本工具读取 / 改写。后续实际重绘前先通过 Pencil 核对真实画板与旧稿对应关系。
- 保留未受影响画板或明确历史标识；新分区画板应标注评审状态及目标能力，不把既有“定稿”标签沿用到新内容。
- 在同一主稿中先评审完整任务关系；确需拆分时按域使用稳定前缀，并在 brief 维护导航和共享组件来源，避免多份 Workbench 壳相互漂移。
- 设计进入代码前记录画板 / 版本、评审结论、实现范围、正式状态 / 命令映射及允许偏离项。设计通过不等于工程算法或代码验收通过。
- 控制面、移动端 / 只读端仍为后续独立端点，当前不与桌面重设计同时展开。

## 持续有效的视觉原则

浅色、清楚、紧凑、长时间可读；数值与单位相邻，密集工程数据允许使用可读表格，不强制全部卡片化。流程任务保持画布优先，设备 / 物性 / 结果任务让主内容占据主要空间。状态色表达真实状态，不能用整体绿色暗示未经验证的工程可信度。

保留对象身份、修改反馈、来源、草稿 / 当前 / 过期 / 缺失的可解释性；导航数量、侧栏 tabs 和画板数量均由新任务评审决定，不套用旧稿硬约束。禁止直接复制外部品牌或具体视觉资产。
