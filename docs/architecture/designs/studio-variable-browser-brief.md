# VB0 首片：只读变量工作区评审稿

更新时间：2026-11-11

用途：提出统一变量与对象浏览器首片的用户路径、覆盖、局部布局、身份边界、实现入口与验收，供项目所有者评审。
读者：项目所有者、Studio / `rf-ui` 开发与验证协作者。
不包含：已批准的实施安排、最终视觉画板、公开路径协议、关注项存储格式、表格编辑或新增物理模型。

状态：**首片方案已认可，局部画板待制作 / 评审；产品未实现，未宣称 VB0 / VB1 完成。** 2026-11-11 项目所有者认可本稿首片方案，并要求先提交文档、再完成局部画板供评审，暂不进入代码实现。唯一切片状态仍在[浏览器专题](../../topics/variable-and-object-browser.md)；本文件是其局部设计附件，不新建子专题。

## 目标与首片选择

用户目前可在模态浏览器中查询单元 / 流股，但不能保持变量表与工程编辑区对照；搜索后主要定位对象，无法稳定回到具体字段。AF4a 已有非画布对象查询，当前模态界面尚未消费这部分能力。

建议先交付一个可展开、可返回画布的**只读变量工作区**：找到对象与变量，辨别输入、流股模板和当前结果，查看单位与来源，并定位到已有编辑 / 结果入口。优先完成“发现 → 理解 → 定位 → 返回审阅”的真实路径，再在后续增量加入持久关注、路径解析和就地编辑。

本建议将 VB1 按可验收范围交付，首片通过不关闭整个 VB1。当前图、运行任务、结果所有者、项目格式和统一命令边界保持；新增能力仅为应用查询的呈现与导航。C2-A、AF1 故障跟踪和其他平台集中验收不作为本设计的统一前置。

### 首片范围与覆盖矩阵

| 对象 / 内容 | 首片展示与操作 | 真相源与明确限制 |
| --- | --- | --- |
| 流程单元 | 当前支持的单元（含 Splitter）的名称、已描述输入、端口引用；可定位支持的输入字段 | `VariableBrowser` / `VariableField`。按模型枚举真实字段；无出口温度规格的单元不补空规格。单元输出经端口定位真实流股结果，不复制一份“单元结果” |
| 流股输入 | 名称、T / P / F、登记组分摩尔分数；显式区分正式进料与 `StreamTemplate` | `VariableDescriptor`。模板不作为计算结果；未指定与数值零分开 |
| 流股结果 | 当前查询已有的温压、流量、组成、相分率及相属性；按已有字段枚举 | 工作区结果资格 + `VariableBrowser`。不补不存在的相、焓模型或派生量 |
| 设备任务 / 工况 / 共同几何 | 目录、任务与工况身份、已有数值输入和轴向段；打开对应设备页 | `ProjectQuery::objects / fields / record`。工况必须携带 task + case；共同几何不伪装为每行副本 |
| 设备结果 | 当前工况资格、拒绝原因、来源摘要及“查看设备结果”入口 | `equipment_result` 与既有设备结果页。首片不把设备所有输出列强制转换成 `VariableField`，也不增加第二份结果模型 |
| 工程基础 / 来源 | 基础条目的量值、单位、绑定来源；来源记录按现有只读元数据显示 | `ProjectField::BasisValue`、`record`。来源是记录卡，不伪造数值变量；无画布位置时进入正式设备 / 基础页面 |
| 物性 / 组分 | 保留现有物性页入口和工程上下文提示 | 首片不新增完整可寻址物性目录，也不放无功能变量树节点 |
| 动作描述 | 在详情中展示现有参数、前置条件与正式入口；运行状态只读引用 | 首片不从浏览器执行计算、采纳、写入或批量动作，不将 `write_via` 当作当前可编辑许可 |

工程分类采用“流程（单元 / 流股）—设备（任务 / 工况 / 几何）—工程基础—来源”。变量树是同一批对象的“对象 → 输入 / 结果 → 字段”投影，不复刻求解执行树。来源记录和设备结果卡没有通用字段身份时，明确作为记录 / 结果入口呈现。

首片不交付：可输入的路径地址栏、稳定引用导入 / 导出、关注列表持久化、表格写入、跨工况批量对比、历史运行切换、COM、录制、公开协议及新依赖。它们仍属原 VB1—VB3，不能被本片的“完成”核销。

## 局部布局提案（VB-D01）

入口沿用“工具 → 变量浏览器”和现有命令入口，不增加顶层产品区。保留原模态入口直至新路径验收完成；替换切换时避免两个独立选择状态。

### A：展开工作区，适合检索与表格审阅

```text
工程：当前工程                 输入修订：12   结果：当前 / 过期 / 缺失 / 失败
变量浏览器                    [返回流程图] [收起为侧区] [关闭]
[工程分类 | 变量树]  [搜索对象 / 字段 / 单位________] [全部 | 输入 | 结果]
┌─对象目录──────────┬─变量表───────────────────────────────┐
│ 流程              │ 对象     分区  字段       值   单位  状态 │
│   单元 / 流股     │ H-101    输入  出口温度   …    K     指定 │
│ 设备              │ Outlet   结果  温度       …    K     当前 │
│   任务 / 工况     │ 非当前结果：—；保留原因与来源入口        │
│ 工程基础 / 来源   ├─所选项详情─────────────────────────────┤
│                  │ 来源 / 约束 / 对象身份 / 只读原因         │
│                  │ [定位字段或对象] [复制当前值与单位]       │
└──────────────────┴──────────────────────────────────────┘
```

默认显示全部分区，分区列始终可见；搜索结果保留对象名和身份尾标，允许重名但不混行。“输入有效”与“结果当前”使用不同文本，不能用同一绿点代替。表中数值遵循项目显示单位；规范 SI 单位及原值放详情，不在主表并排制造第二套读数。

### B：与画布对照的侧区

```text
现有流程画布 / 编辑区                         变量浏览器（可收起）
用户正在编辑的对象                            搜索 / 输入或结果筛选
已有检查器与草稿保持                          当前对象与变量列表
                                              所选值、单位、来源、状态
                                              [展开工作区] [定位]
```

侧区采用同一个浏览器状态和选择，不新增可变数据副本。建议复用右侧区域的浏览标签；检查器与浏览器切换时先运行现有草稿导航保护。展开模式用于跨对象列表，侧区用于当前对象审阅，不要求窄窗口同时挤入目录、表格与详情三列。具体尺寸和标签承载位置须在局部画板评审后确定。

### C：窄窗口与异常

400 px 局部区按“上下文 / 搜索 → 列表 → 所选详情”纵向切换；显式“返回列表”恢复过滤与滚动。长对象名换行，状态与来源不只靠颜色；200% 字体允许纵向滚动。未找到、对象已删除、工程已切换、单位无法转换各有独立提示和返回入口。

键盘顺序为搜索、筛选、目录 / 结果列表、详情与定位。Enter 打开所选详情；定位使用独立按钮，不让 Enter 同时执行模型写入。Escape 退出详情 / 收起浏览器，不能取消计算或丢弃其他编辑器草稿；新结果到来只更新值与资格，不移动选择、排序或键盘焦点。

## 代表路径与失败行为

| 场景 | 预期行为与验收观察 |
| --- | --- |
| 搜索出口温度 | 单元输入显示实际规格；通过单元端口进入输出流股的温度结果，两者身份 / 分区不同；从结果跳回输入不能把结果覆盖到规格 |
| 定位并修改 | 从输入变量定位到 Inspector 对应字段，由原编辑器提交；返回浏览器后输入更新、旧结果失效；Undo / Redo 同样经正式事务 |
| 当前结果变旧 / 失败 | 表中当前值位置显示“—”及原因，禁用当前数值复制；可查看已有来源 / 诊断，不能回退到旧快照或输入模板。执行忙碌与结果资格独立，例如输入未变时上次 Current 可保留 |
| 缺失 / 零 / 不支持 | 真正零值显示 0；未指定显示未指定，缺少结果显示缺失，查询不支持的字段明确拒绝，不用 0 或空字符串填补 |
| 重名 / 重命名 / 删除 | 选择按类型化身份绑定；重名可辨、重命名保留选择；删除后给出失效提示，不能跳到同名对象。删除后重建不按名称恢复选择 |
| 导航时存在草稿 | 浏览已提交值，不吞草稿；定位进入原导航保护，取消导航保留当前编辑与浏览器选择。搜索 / 切换分区不提交输入 |
| 工程切换 / 重开 | 校验活动工作区和会话；丢弃旧查询结果与选择。相同 DocumentId / revision 的不同会话也不能沿用旧结果资格 |
| 设备多工况 | 选择 B 始终读取 B；共同几何显示共同身份；切换 C 不将 B 的结果改归 C，失效依据复用设备资格 |
| 设备 / 来源无画布节点 | 定位到已有正式页面；尚无精确字段入口时标明“定位对象”，不伪装已做到字段级定位 |
| 只读工程 | 可浏览可用的正式数据；写入仍由原页面的只读守卫拒绝；浏览器不创建新的可编辑通道 |

## 身份、路径、关注项（VB-D02 / D03）

建议本片先使用现有 `VariableId`、`ProjectObjectRef` 与 `ProjectField`；这些是应用内定位依据，不序列化会话凭据或将 `Debug` 字符串当协议。人类路径只作为由对象名称生成的面包屑，例如“流程 / 单元 / H-101 / 输入 / 出口温度”；它不是可执行地址，也不承诺可复制后跨工程解析。

首片不提供“复制稳定引用”按钮，避免在路径版本、转义和复制 / 导入身份尚未冻结时形成兼容负担。路径增量开工前，另行审定版本、保留字符与 Unicode、大小写、集合身份、歧义和结构化错误；解析后仍必须进入同一类型化查询入口。

首片的选择、展开和过滤只在当前会话保留，工程切换清理；不改变项目脏状态，也不新增 sidecar。关注列表不是本片隐含缓存。下一片再在项目资产与个人工作偏好之间明确归属，按“引用而非值”保存，并覆盖另存、同身份副本、删除 / 恢复、只读工程和迁移；未经审定不写入现有偏好文件或项目格式。

本方案请求的是 D02 / D03 的**首片边界决策**，不把它们的完整协议与持久化决策标为完成。若所有者要求首片同时交付可持久关注或路径跳转，应先扩充这两项设计及保存验收，再进入实现。

## 实现映射与需补的真实断点

| 职责 | 复用入口 | 拟新增范围 |
| --- | --- | --- |
| 对象与数值发现 | [`project_query`](../../../crates/rf-ui/src/project_query/mod.rs)、[`fields`](../../../crates/rf-ui/src/project_query/fields.rs)、[`variable_browser`](../../../crates/rf-ui/src/variable_browser/mod.rs) | Studio 分类 / 表格投影；不反射整个 Rust 对象、不新建工程数据仓库 |
| 结果与来源 | [`result_query`](../../../crates/rf-ui/src/result_query.rs)、设备 `query_case_result`、既有[结果审阅](../../../apps/radishflow-studio/src/studio_gui_shell/result_review.rs) | 浏览器显式消费结果状态；当前 `ValueState` 不含 Failed，不能用 Missing 文案覆盖真实失败，也不必扩成一个跨领域巨大枚举 |
| 显示单位 | `VariableDescriptor::display_value` 与统一单位目录；设备 `EngineeringQuantityRead::canonical_unit` | 工程量显示适配、转换失败与只读复制资格；SI 输入值不改写 |
| 导航 | 现有 [`variable_browser.rs`](../../../apps/radishflow-studio/src/studio_gui_shell/variable_browser.rs) 的对象定位、[`canvas_navigation`](../../../apps/radishflow-studio/src/studio_gui_shell/canvas_navigation.rs)、设备导航 | 为已支持输入增加有限、类型化字段目标；流股结果到既有结果视图；反向入口从受支持字段打开同一选择。不靠显示文案拼命令 |
| 输入与草稿 | 原 Inspector / 单位会话、`AppState::write_variable`、AF4b 正式动作 | 首片无新写入口；定位复用现有保护，保留事务、Undo / Redo 与资格失效语义 |
| 浏览状态与刷新 | 当前 `VariableBrowserState` 与活动工作区 | 单一选择身份、视图模式、过滤和可见范围；不保存求解快照副本 |

对象级目录可枚举，但不每帧重新枚举全部变量或复制结果；按输入 / 设备 checkpoint、实际结果身份、显示单位和过滤变化失效投影，只物化可见 / 选中数据。首次搜索可以遍历现有已描述字段，后续帧复用可失效的搜索投影；结果更新与输入变化分开，工程切换即清理。是否需要分页由实际大图测量决定，不提前建设订阅服务。

实现时以一个具体变量从查询、单位到定位的贯通为起点，再补目录和异常路径；现有单文件较小时不预先拆出框架。若有限字段导航发现必须改变领域写入契约或保存格式，返回评审，不藏在 UI 重排内。

## 建议实施顺序与退出标准

| 步骤 | 可独立核对的交付 | 退出要求 |
| --- | --- | --- |
| 设计确认 | 确认本稿覆盖与 D01—03 首片边界；补展开、侧区、窄区及失败 / 草稿四类局部画板 | 所有者认可局部交互与画板；全局 R0 不因此定稿 |
| 查询呈现 | 两种导航投影、只读字段表、上下文 / 来源 / 单位和记录入口 | 同一身份跨视图同值；Failed / Stale / Missing / 零值与模板分明；无求解 / 写盘副作用 |
| 导航联动 | 支持字段双向定位、端口到流股结果、设备 / 基础入口 | 草稿拒绝和取消导航可恢复；重名、删除、跨工程无误定位 |
| 局部验收 | 自动身份 / 状态 / 单位 / 导航测试，macOS 实窗、正式仓库基线 | 下列矩阵通过；未验平台与非首片能力单列 |

最小验收集：

1. 公开小流程覆盖输入 → 定位 → 原编辑器修改 → Undo / Redo → 运行 → 浏览当前结果；验证查询前后输入修订、脏状态、文件字节和运行计数不因浏览改变。
2. Current / Stale / Missing / Failed、零流量、缺组分、模板与结果、转换失败分别验证；复制结果时重新核对身份与资格，不只依赖按钮绘制时状态。
3. 同名对象、删除 / 重建、相同 DocumentId / revision 的重新打开、旧会话查询晚到，确认不串对象 / 结果。
4. 设备 B / C 工况及共同几何，工程基础与来源记录；无法精确定位的字段明确降为对象级入口。
5. 模态草稿保护、搜索与键盘、400 px 局部区和 200% 字体；真实 OS 倍率、读屏与 Windows / Linux 仍按原节点记录。
6. 使用已有 384 单元 / 512 流股公开构造检查首次搜索、结果更新与连续输入响应，记录构建、数据规模、耗时与分配 / 内存观察；具体性能门槛在实现前随局部 UI 冻结，不能用单次演示承诺容量。

代码完成后按影响面执行定向测试，跨模块交付执行正式 `check-repo`。本轮只生成设计文档并运行文档门禁，不将生命周期实窗或旧浏览器测试当作新 UI 已验收。

## 首片方案评审结论

1. 是否采用“展开工作区 + 可收起侧区”的单状态只读浏览器，沿用工具入口，不改全局导航？
2. 是否接受覆盖矩阵：流程字段精确定位；设备 / 基础 / 来源消费现有查询，设备结果先保留专用结果入口？
3. 是否同意首片采用类型化内部身份与只读面包屑，将公开路径、持久关注和就地编辑留在后续明确增量？
