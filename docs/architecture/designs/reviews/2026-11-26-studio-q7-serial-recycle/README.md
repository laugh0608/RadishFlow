# Q7 串联回流终态局部交互稿

2026-11-26 · R1 第一版 · 三处交互已获项目所有者认可 · Studio 已通过 macOS 实窗验收

[打开交互稿](boards.html)。先选 **0.60 / 0.25**，再切到 **0.60 / 0.99**。两次都从「流程运行 → 稳态运行计划 → 流程结果」开始。顶部的工况、来源、语言和字号用于评审。下方展示本次认可的局部界面。

## 两分钟评审路径

| 操作 | 0.60 / 0.25 · 运行 #1 | 0.60 / 0.99 · 运行 #2 |
| --- | --- | --- |
| 看整图摘要 | 运行来源旁显示一次 Current，10 股正式结果一起发布。下游 heater-1 执行 1 次。 | Failed，第 5 块耗尽迭代预算。摘要明确本次无正式结果，下游 heater-1 未执行。 |
| 从第 4 块读到第 5 块 | 第 4 块 48 次迭代、1 次独立复核通过。经 s-bleed 供料的第 5 块用 18 次迭代、1 次独立复核通过。 | 第 4 块的 48 次迭代与 1 次复核仍可查，标为「本块复核通过 · 仅诊断」。第 5 块停在试算 500，复核 0 次，两项末次残差均超限。 |
| 分别打开两行流股，再返回 | 「查看正式流股」进入同一快照。s-recycle 的生产端返回量是 7.499999999898964 mol/s，s-recycle-2 是 1.6666666666381513 mol/s。 | 「定位工程流股」分别选中两条撕裂的工程对象，显示源端口、汇端口及工程输入。对象中保存的总量分别为 79 和 13 mol/s。 |
| 查看末次组分与完整轨迹 | 可按块展开 49 和 19 个样本。每行有阶段、阶段内序号、绝对及缩放残差、容差和各自的判定。 | 已完成块保留 49 个样本，终止块保留 500 个样本。第 5 块最后的绝对残差为 0.01839735251849106 mol/s，缩放残差为 0.003679470503747779。 |

流股目标打开时，焦点落在对应流股名上。返回后，焦点回到发起定位的那一块按钮，已展开的证据保留。用 Tab 和 Enter 可展开明细，再按 Tab 进入轨迹滚动区。在流股详情内将「来源」切至修改输入、重开同一工程或新回执已接收，可检查旧详情关闭。同名流股在新会话或新回执中需要重新定位。

## 数据与接线

- [基准工程](../../../../../examples/flowsheets/fixed-tp-q7-serial-recycle.rfproj.json)中仅将第二个 Splitter 的分率从 0.25 改成 0.99 即得到失败工况。来源详情保留输入文件 SHA-256、修订、求解方法、计划配置指纹和 CLI 步骤。运行 #1／#2 取自[上一轮 Studio 实窗对照](../../../../devlogs/2026-11/2026-W48.md#2026-11-26-q7-串联回流的-cli-与-studio-对照)。
- [报告摘录](reports.js)保留每次运行的来源和流股目标。成功两行来自 CLI v4 的 `blocks[3].recycle` 与 `blocks[4].recycle`，正式值取该次 `streams`。失败两行来自 `diagnostic_evidence.completed_blocks[3].recycle` 与 `active_recycle`，终止块号取 `stage.block`。两份第 4 块摘录逐项相同，共用静态数据。定位资格按打开的工程及回执分别判断。
- [流程结果视图](../../../../../apps/radishflow-studio/src/studio_gui_shell/flow_plan/results.rs)负责整图资格、块顺序和末次求值。[流股导航](../../../../../apps/radishflow-studio/src/studio_gui_shell/flow_plan/recycle_review.rs)负责快照行、工程对象和返回焦点。原生失败定位同时覆盖已完成块与终止块，并复核当前工程绑定。[专题范围与验收条件](../../../../topics/runtime-messages/execution-trace-and-convergence.md#q7-串联双回流块的结果归属)
