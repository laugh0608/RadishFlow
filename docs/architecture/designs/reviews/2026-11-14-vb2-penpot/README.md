# Studio VB2 跨对象批量草稿核对

2026-11-14 · 局部设计 v1 · 首片已实施

从变量浏览器关注清单选取两个流股的摩尔流量，在 Studio 400 px 侧区核对草稿。两个流股及其值是评审样例。正式约束见 [变量与对象浏览器专题](../../../../topics/variable-and-object-browser.md#接下来事项)。

1. 草稿中分别列出每项的工程当前值与草稿值。示例当前值为 `5 mol/s` 和 `3 mol/s`，草稿为 `7.25 mol/s` 和 `1e- mol/s`。
2. 点击「检查 2 项草稿」后，第二项的指数不完整，整批阻断。状态提示「已应用 0 项」，保留两项原文，第一项标明已通过检查，第二项说明修正方式。
3. 点击「返回编辑第 2 项」可查看目标字段的高亮，第一项草稿继续可见。原型里的字段和工程值为静态样例；点击「返回草稿核对」可重复评审此路径。

## 首片实现提案

所有者确认从同一可编辑工程的关注清单选取至少两条不同的进料流股，只编辑由 Feed 物料出口提供的「输入／总摩尔流量」。批量入口只在适用行启用，按关注顺序列出所选项。关注清单的成员与顺序沿用现有保存规则。温度、压力、组分联动和其他对象待独立切片评审。

| 步骤 | 界面与行为 |
| --- | --- |
| 从关注清单选取 | 勾选适用行后进入「编辑所选流量」。各行显示对象名、已提交值、草稿原文和输入单位。已有草稿直接打开同一 U2 会话。 |
| 检查草稿 | 显式「检查 N 项草稿」，成功后显示「检查通过」及独立的「应用 N 项」按钮。检查后改动所选项、原文、单位或正式工程输入，需要重新检查。 |
| 修复失败项 | 显示「已应用 0 项」和逐项原因，焦点可回到首个失败字段，其他草稿仍可见。「返回编辑」和移出本批均保留 U2 草稿。已有 Inspector 单项写入后，旧检查失效。 |
| 应用与返回 | 点「应用 N 项」时再次检查。成功后回显实际变更数及正式值，清理本批已处理草稿。全部同值时显示「没有工程变更」。返回关注清单不提交；显式放弃沿用现有 U2 草稿取消动作。 |

现有画板供评审草稿、拒绝与返回编辑三态。上表补充选取、检查通过和应用后的行为。批量页内的 Enter 遵循 U2 的文本与输入法规则，应用由明确聚焦的批量按钮触发；单项「应用」仍在原来的单值入口。400 px 侧区沿用单列，展开视图保持相同步骤。首次评审同时核对表中补充状态和原型三态。

### 事务与兼容边界

- Studio 维护本批选择与检查回执，数值原文、单位、文本历史及字段基线仍存于共享 `NumericEditSession`。应用绑定当前工作区会话、正式输入修订、选中字段的 `VariableId` 与草稿代次。重开同一文件、切换只读、字段失效、Feed 出口连接变化、重复项或所选草稿变化均可明确拒绝旧动作。未选草稿保留并在成功后按 U2 规则重验。
- `rf-ui` 在同一正式工程基线上解读每项草稿，并在一份候选流程图上复用已有流量校验。检查返回可定位的逐项结果。应用重新执行这一准备过程，只有全批有效才提交一条能表达多个流股写入的内部 `DocumentCommand` 和一条历史。现有 Inspector「应用全部」会保留非法字段并提交有效字段，继续遵循原行为。 [U2 会话校验](../../../../../crates/rf-ui/src/state/numeric_edit/transaction.rs) · [正式输入事务](../../../../../crates/rf-ui/src/state/input_commands.rs) · [Inspector 批量入口](../../../../../crates/rf-ui/src/state/stream_inspector.rs)
- 真实修改推进一次正式修订并使已有流程结果变为 Stale，旧在途完成按 AF3 资格拒收。Active 与 Hold 继续使用原调度规则。空批、拒绝和同值批次不产生工程修订、历史或自动重算。批量应用沿用单值的工作区提交边界，工程保存只写正式输入；CLI、C ABI 与工程文件格式保持现行契约。

### 首片验收

使用公开双进料工程的 `stream-feed-a` 和 `stream-feed-b`，初值分别为 `2 mol/s` 与 `3 mol/s`。在旧结果为 Current 的同一工程执行下列用例。 [双进料算例](../../../../../examples/flowsheets/feed-mixer-flash-binary-hydrocarbon.rfproj.json)

| 用例 | 可观察的预期 |
| --- | --- |
| 整批拒绝与修复 | A 输入 `36 kmol/h`，B 输入 `1e-`。检查显示 A 可用、B 未完成，已应用 0 项，两个正式流量、修订、历史与旧快照均保持。B 的负值另测领域拒绝。返回 B 时 A 的原文和单位保留。 |
| 一次应用与历史 | B 修正为 `5 mol/s` 后重新检查并应用。正式值为 `10`、`5 mol/s`，只推进一次修订，旧流程结果 Stale。一条工程 Undo 恢复 `2`、`3 mol/s`，一条 Redo 恢复批量值。另测一个同值、另一个实际变化，以及整批同值。 |
| 过期与作用域 | 检查后改变其中一个草稿、断开 Feed 连接或重开相同工程，旧应用被拒。取消或返回不丢草稿。用第三个未选字段验证仅清理本批草稿，并覆盖跨工程、只读、结果项和重复项拒绝。 |
| 结果接收与磁盘 | 注入提交前请求的迟到完成，验证拒收。Hold 下手动重跑得到 Current，另测 Active 重算只用最新正式输入。保存重开核对两项 SI 值及关注引用，审阅旧 CLI 请求的逐步语义。 |
| 交互与平台 | 定向覆盖错误定位、Tab／Enter／Escape、非 SI、两语双字号和 400 px。正式仓库检查后，提前告知再做 macOS 真实窗口代表验证。系统级缩放、读屏、Windows／Linux 和完整 I5 继续按各自节点验收。 |

按「定向事务回归 → Studio 草稿核对与应用 → 正式检查和 macOS 代表实窗」验收。

实现以 U2 草稿供各入口共享，批量检查回执只保存在当前 Studio 工作区。定向回归验证整批拒绝、结果接收与 Active 重算，macOS 代表实窗验证非 SI 输入、失败定位、一次撤销／重做及保存重开。系统缩放、读屏及 Windows／Linux 的实窗保留为待验。 [实现与验收记录](../../../../devlogs/2026-11/2026-W46.md#2026-11-14-vb2-进料流量批量编辑首片)
