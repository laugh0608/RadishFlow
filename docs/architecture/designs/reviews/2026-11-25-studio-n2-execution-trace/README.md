# Studio N2 计算过程局部交互评审

2026-11-25 · R0／R1 局部评审 · v1 已认可。面向从稳态运行回看执行步骤、定位失败并复核运行归属的用户。工作范围、事件与容量见 [D-02](../../../../topics/runtime-messages/execution-trace-and-convergence.md#d-02-审阅提案稳态运行记录2026-11-25)，工作台长期布局见 [诊断专题](../../../../topics/runtime-messages/diagnostic-workbench-and-navigation.md)。

在浏览器中打开 [可编辑交互画板](boards.html)，可切换场景、语言和字号，选择运行、步骤及失败目标。源稿为 [HTML](boards.html)、[样式](styles.css) 和 [状态与交互](boards.js)。Mixer 读数与失败目标取自真实 v2 工程的跨端复核。运行编号、汇总历史和超限载荷用于演示，定位页面是原型内的导航预览。 [Mixer 验收](../../../../devlogs/2026-11/2026-W48.md#2026-11-25-af4--af5-进料组成错误定位修复)

## 评审范围

| 位置 | 设计和应用接线边界 |
| --- | --- |
| 入口 | 沿用「流程运行」及结果页的上下文，统一打开现有底部抽屉中的「计算过程」。提议复用现有「运行日志」的标签位置，把既有文本日志保留为计算过程中的单独入口，避免向当前问题注册第二份诊断。现有「当前问题」和「结果表」入口继续导航到各自数据。 |
| 运行选择 | 当前工程会话的最近运行可选择，每次显示提交时的修订、执行终态和接收处置。结果资格来自应用原有查询，只有选中的运行有当前结果才显示「查看结果」。保留旧 Current 时在运行选择附近标出其实际编号。 |
| 步骤与诊断 | 桌面左侧显示真实顺序，右侧默认显示首次失败详情或已选步骤。步骤未执行、证据未保留和未进入求解分开表达。只有结构化目标能在当前工作区精确解析时才给出定位动作。旧目标失效时仍可阅读来源和诊断。 |
| 反向导航 | 定位调用既有场景与输入导航，从目标回来重新选择同一运行和步骤，恢复触发控件焦点。定位不修改输入。已有草稿按现行离开规则保护，切换查看运行不会替用户应用草稿。 |
| 窄区和技术信息 | 400 px 下先显示步骤列表，选中后打开单列详情，支持返回和 Escape。状态同时显示文字与颜色，技术码按需展开。原生键盘与字号在产品接线后复核。 |

## 原型复核

- Playwright CLI 0.1.25 与 Chromium 158.0.8127.38 检查了 76 个布局组合，覆盖 400／1280 px、中英、14／20 px 及窄区列表／详情。未发现页面横向溢出、控件内容溢出或页面运行错误。两种字体均从 Studio 的 Inter Variable 与 Source Han Sans SC 资源载入。截图尺寸按画板内容裁切或取整页。
- 键盘复核定位后焦点移至目标、Escape 返回定位按钮、窄区再次返回所选步骤。另复核运行日志返回、历史选择与当前问题独立、结果按钮只随有资格的运行出现、结果表仍可独立打开实际 Current、删除对象后保留诊断。
- 现有 Studio 运行所有者 33 项定向回归通过。产品接线后的求解采集、边界负载、原生定位与草稿保护按 N2 场景验收。
