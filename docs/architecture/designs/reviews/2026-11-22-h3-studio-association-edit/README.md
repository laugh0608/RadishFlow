## 已确认的交互与事务

| 决策 | 已确认的行为 |
| --- | --- |
| 编辑入口 | 保留正常工程打开及独立／关联复核。从目标 H3 工况显式进入局部编辑，分别显示「建立流股关联」和「编辑流股关联」。支持的 v4 必须已有稳定对象身份、无回路计划及已评审纯水资格。混有独立及关联工况时，编辑入口可选择两类已保存工况，原复核入口沿各自支持范围。v3 独立复核与未知能力的整份原文只读继续按原契约。 |
| 选择和预览 | 同屏区分已保存来源与草稿。热侧和冷侧各选一条本工程流股，按流股 ID 与创建身份绑定；位号仅供查找。显式「运行流程并预览」冻结配对，在共享后台所有者中运行已保存的正式流程。预览展示实际接受快照的两侧 T／P／摩尔流量与资格。预览中的数值为入口，校核结果在保存后显式运行时产生。运行中冻结本次配对并保留取消，选项变动、更换工况、取消和关闭均使相应旧预览失效。 |
| 草稿与返回 | 编辑会话内保留草稿，提供「重置草稿」。退出有改动的编辑会话时默认聚焦「继续编辑」，显式舍弃仅丢草稿。保存生效后，恢复上一次配对通过再次编辑、预览及确认完成。前一工作区的 Undo／Redo 属于那个工作区。 |
| 保存、另存和生效 | 「保存关联」写回当前来源路径，「另存关联」选择新文件，原路径的变更始终走前一动作。已存在的另存目标引导另选；保留工作区当前持有的文件禁止由该面板覆盖，按宿主路径匹配规则识别。确认列出目标及变更配对，默认聚焦取消。首次原路径写入关联能力须接受旧读者整份只读的提示。保存后从正常打开入口建立新会话，结果从 `Missing` 起步。写入成功但重开失败时单独报告保存成功与重开错误，并提供打开已保存文件的入口。 |

### 结果与错误状态

- 草稿改变后隐藏编辑页中的旧校核值，并使上一份候选预览失效。返回原复核视图时，旧结果是否可继续显示，由原会话及原已保存配对的资格决定。编辑会话的预览和保存回执均带会话、工况与请求身份。
- 同一对稳定引用为无变更，保持文件与修订。两侧同股、创建身份不符、资格拒绝或流程失败均使保存不可用，并保留可定位的侧别及原因。重新运行后以新快照重做预览，即使两侧数值恰好相等。
- 源文件变化后保留选择作为草稿，要求显式重载、核对身份及重跑后再预览。同名重建的流股须重新选择。仅另存目标冲突时保留有资格的预览，另选目标后重新准备并确认；失败重试仍核对源与目标。取消和写失败保留当时的正式字节、草稿和可重试状态。
- 编辑期间，Cmd／Ctrl+S 与 Cmd／Ctrl+Shift+S 分别路由到本页保存及另存动作，与按钮共用资格门禁。确认期间 Escape 取消并回原动作；编辑页 Escape 走返回前的草稿保护。保留工作区的同名快捷键在编辑期间受宿主拦截。
- 复核使用本次实际接收的求解结果。50 mol/s 环隙压降超限为完整的当前结果，单独显示限值失败。进料温压／相态拒绝及求解失败沿用既有诊断。

## 应用接线与兼容范围

1. `H3FlowReview::preview` 对已关联工况要求配对等于保存值，`prepare_association_save` 遇到已有配对返回 `association_exists`。独立的编辑事务分别捕获旧保存模式或配对、新配对和同一目标的任务／几何／工况修订。复用两侧入口与物性资格验证。`preview_saved`、只读 Studio 工况、CLI v13／v14 继续使用各自现行入口和兼容保护。 [预览与校核](../../../../../apps/radishflow-studio/src/document_lifecycle_driver/h3_flow_review.rs) · [保存事务](../../../../../apps/radishflow-studio/src/document_lifecycle_driver/h3_flow_review/save.rs)
2. 准备与提交都核对源原字节指纹、是否仍为已保存流程输入、已接收运行和快照资格、旧保存配对、新流股创建身份及记录修订，提交时由 v4 writer 重验目标指纹及升级确认。取消或冲突后原准备记录撤销，申请重试时生成新记录。采用既有暂存写入，保持原文只读目标及关联移除保护。 [存储能力](../../../../topics/project-lifecycle-storage.md#h3-流程关联-v4-存储)
3. 按现有 v4 能力写入 `case.flowAssociation.hot`／`cold` 的两条引用。首次关联后，两侧独立 `inlet` 随现有互斥契约省略。保持同一工程 ID、目标几何修订及既有几何、来源、物性和限值。成功写入推进文档、任务和工况修订。预览、草稿、结果和运行身份留在内存，随会话结束回收。计算结果的出口和压降供校核审阅。
4. 编辑入口、保存权限和在途回执由宿主与有类型的应用动作共同守卫。局部页面只拥有选择和焦点。沿用既有共享 worker 的名额、停止及回收，保留原窗口的工程和草稿。保存新会话期间屏蔽旧请求更新；重开收到未知能力时按整份只读处理。

## 交付顺序与验收

先完成编辑事务和存储回归，再接 Studio 工况入口、预览、保存与重开，最后以真实进程、macOS 原生和仓库基线一起验收。确认保存和退出的键盘焦点、诊断定位及中英文 400 px／20 px 原生布局均属于交付范围。 [既有两档基准及容差](../../../../topics/equipment/heat-exchanger-design-and-rating.md#真实-cli-进程验收)

| 验收场景 | 预期 |
| --- | --- |
| 同一工程首次关联与重开 | 未关联的 H3 独立工况选择热侧 `hot-feed`、冷侧 `cold-feed`，运行并预览。取消首次覆盖确认后比对源字节与草稿，重新确认后保存。重开显示两条引用，结果为 `Missing`。显式复核 40 mol/s，三项限值通过。 |
| 同一工程更换冷侧并重跑 | 保持热侧，变更为 `cold-feed-50`。编辑阶段无上一份 40 mol/s 校核值；提交后的文档、任务、工况修订递增，几何修订与实际内容保持。重开从 `Missing` 显式复核 50 mol/s，按原容差核对热负荷、UA、出入口及压降，只有冷侧压降超限。 |
| 资格及身份 | 分别覆盖两侧同股、同名重建、相态／来源无资格、取消／新快照／重开使旧预览失效，以及同一配对重复提交。关联范围为同一工程；原工况 ID、来源及其他工况可复核。 |
| 保存保护 | 分别注入源变化、另存目标创建、写失败、只读目标、保留工作区路径别名、取消升级及重开失败。核对原字节和剩余草稿，检查恢复动作及成功回执归属。 |
| 实际消费者 | 使用 v14 只读执行比对同一工程不同保存阶段，v13 独立工程和关联整份保护仍适用。冻结不认识关联的读写器复核原文和写保护。Studio 原生覆盖取消、焦点、新会话、二次打开与迟到回执。 |
