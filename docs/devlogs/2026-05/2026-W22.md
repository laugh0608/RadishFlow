## 关键决策

- 当前没有达到正式 tag / release 标准；历史 staging 版本号不自动等同于 Git tag。
- 当前日常推进不再围绕便携包和版本节点，而是回到 MVP β 的用户可复现建模能力。
- 小案例作者入口是导航和检查清单，不是项目向导：状态必须从当前 flowsheet/canvas 推导，不写项目语义、不进 undo；不同案例只影响 shell-local 当前清单选择。
- 个人开发节奏下，不再把已经通过的阶段继续拆成 hover、按钮、提示、selector 等细颗粒度补口；已通过能力只修真实 blocker。
- 下阶段主线为 MVP β 第二刀：建模输入能力 v0，优先让用户能配置组分、选择内置物性方法 / package、输入 Feed 组成和单元参数，再用 official demo case 验收这组能力。
- 物性包选择必须成为项目模型的一部分，而不是运行按钮上的临时参数；运行时 `Preferred` 先尊重项目中保存的 package，再退回旧的单缓存包推断。
- 当前 Studio 物性包选择先采用受控内置列表，暂不引入第三方 Property Package 加载；后续项目组分选择应与该列表的适用组分边界对齐。
- 当前项目组分选择先采用与 `binary-hydrocarbon-lite-v1` 对齐的受控 methane / ethane 目录；不进入完整组分数据库，也不在移除项目组分时隐式迁移或补偿已有 stream composition。
- “选择能力”必须在空白项目中可见：空白项目只提供受控内置目录和本地缓存，不预写 `Flowsheet.thermo.property_package_id` 或 `Flowsheet.components`；示例项目仍可保留已配置好的演示输入。
- Unit Inspector 的参数输入页属于 β 第二刀建模输入主路径，不按普通 presentation 小瑕疵处理；字段标签、单位、状态和操作必须保持可读，长约束说明只能作为辅助文本，不能挤压输入控件。
- official demo case 验收必须以用户可输入的项目状态和最新 `SolveSnapshot` 为准；不能只依赖仓库内静态示例 JSON 说明能力已经具备。
- MVP β 第二刀已收口，后续应先定下一组能力包；默认优先评估结果核对与案例说明，不回到已通过阶段的零散 UI 小项。
- 结果核对说明也必须落到可执行对象：输入流股、非 flash 中间流股、unit step 的 consumed / produced stream、flash 分割、phase row、`H` 和 `bubble_dew_window`，不能只写“运行成功”。
- 小案例作者清单可以继续保持只读提示层，但必须覆盖主路径输入就绪状态；拓扑完成不等于案例可运行。
- 缺少进料组成属于流股输入未就绪，不应由下游 Heater / Mixer / Flash 的泛化执行失败来承载；这类错误需要稳定诊断码、相关流股和可聚焦入口端口。
- 受控连接恢复 v0 只收口 selected material stream 的单端修复闭环：断开、删除和唯一候选重连必须走正式 command / validation / undo / save / reopen / rerun；不引入任意端口选择器、自由连线或自动布线。
- 当前 UI 仍是草稿状态，`Cooler` / `Valve` 下一步只补内部 focused 验证和正式状态文档，不补用户操作 guide；等 UI 形态稳定后再统一治理面向用户的说明。
- 失败修复闭环 v0 已按能力包完成 focused 收口：它围绕真实 blocker 的诊断、定位、修复动作和修复后的保存 / 重开 / rerun，而不是新增 UI 教程或泛化错误兜底。
- MVP β 人工 smoke v0 只覆盖代表性主路径和代表性恢复路径；不把 focused tests 已覆盖的 12 条恢复生命周期全部手工重跑，也不借验收标准推进 tag、release notes、便携包或零散 UI 打磨。
- 人工 smoke 与仓库级阶段基线验证通过后，下一步推进通用小流程建模 v1；既有小案例清单只保留为导航提示，不再作为通用建模运行 gate。
- 通用小流程建模 v1 的运行前 readiness 以 `Flowsheet` 中的 stream state 与 unit parameters 为准；官方示例如果需要直接运行，也必须携带正式参数，而不是依赖 solver 对 outlet stream template 的隐式 fallback。
