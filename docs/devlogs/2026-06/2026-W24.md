## 关键决策

- 底部右侧 `状态汇总` 是 `window.status_summary` 的展示分栏，不是新的运行控制台、收敛曲线、结果报表或 snapshot 历史管理入口。
- 底部结果表仍是轻量结果审阅入口；完整报表、跨快照报表、模板、打印和批量导出继续留在暂不推进项。
- 底部结果表的单元区应消费 `snapshot.review_summary.unit_results`，不再在 shell renderer 内重新扫描 steps；`review_summary` 是 Module Results、结果表和状态汇总之间的 case-level 同源摘要，不是第二套结果计算。
- 底部结果表的定位只表达“把当前结果对象带到正确右侧消费面”：stream 使用 `inspector.focus_stream:*` 并进入 `检查器`，unit 使用 `inspector.focus_unit:*` 并进入 `模块结果`；结果表本身不维护第二套对象导航状态。
- 右侧 `模块结果` current 态只做选中单元的紧凑审阅，不复用完整 result inspector 的长 snapshot id 和完整执行句；完整步骤、诊断和结果表仍走现有折叠区、底部结果表和正式 focus command。
- 顶部 `结果工具栏` 只承担结果页入口和状态扫读，不承担当前 snapshot 所有 stream / unit 的对象导航清单；长列表导航继续走结果表、右侧相关 action、项目树或命令面板。
- 顶部 `运行工具栏` 只承担运行页控制和底部运行信息入口；Monitor 按钮旁不重复展示状态 chip，运行状态继续由下一行状态扫读和底部右侧状态汇总承担。
- `Status Summary` 可以展示从当前 review summary 派生的 unit result count；它只做扫读，不承担完整结果表、完整报表或跨快照历史。
- 对内容 renderer 的 focused test 与整体 Workbench 布局 focused test 分离，避免布局视口裁切误伤内容语义回归。
- `模块` 面板的筛选文本是临时 UI 状态，不是项目、命令、模块库或结果的真相源；分类依据来自现有 `StudioGuiCanvasPlaceUnitKind`。
- `模块` 面板的分类和选项说明不应回到首屏常驻文本；它们可以通过 hover / DTO 保留语义，首屏优先展示可执行放置入口。
- `项目` 面板分区只是现有项目 / canvas / snapshot 状态的职责组织，不新增完整项目浏览器、项目状态缓存或结果状态。
- 中央 Canvas 不再承担对象树 / 对象过滤导航；它只消费既有 canvas presentation 显示建模主舞台、轻量状态概览和受控建议，避免与左侧 `项目` 和右侧 `检查器` 重复。
- 右侧栏的 `画布选择` 是 Canvas presentation 的上下文提示，不是新的对象状态源；模块设置 / 模块结果仍只对 active unit DTO 生效，流股选择只进入检查器和现有 stream focus command。
- 中央 Canvas 顶部工具区只承接视图和 suggestion 工具；选中对象的移动 / 连接恢复等命令归入 `画布操作`，放置入口归入左侧 `模块` 面板，对象语义详情归入右侧 `画布选择`，避免首屏重复展示同一选择状态。
- 底部薄状态栏是窗口级扫读带，不再承担完整状态汇总；完整 case / convergence / steps / diagnostics 仍由底部右侧 `状态汇总` 卡片消费同一 `window.status_summary`。
- 中央 Canvas 顶部工具区不再承接放置 palette；左侧 `模块` 面板是受控单元放置入口，中央只保留视图命令、当前建议命令和选中对象操作。
- 顶部 `流程图工具栏` 是 screen-level 上下文入口，不是第三个画布工具条；Canvas 段只保留已有 suggestion / pending-edit command，放置入口归左侧 `模块`，选中对象移动 / 连接动作归中央 `画布操作`。
- 普通空白项目的正式建模顺序是先 `物性` 再 `流程图`；Home 的当前 workspace tile 是当前文档的返回入口，不是 recent projects 持久化项，也不是第二套项目状态。
- `物性` 到 `流程图` 的 readiness 只表达 UI 主路径是否选齐 package 和项目组分；它不替代正式 run package resolution，也不改变 modeling readiness 对缺项目组分、缺 composition、参数缺失等求解前输入缺口的拦截边界。
- 内部进入流程图建模入口也必须服从同一 Property readiness；按钮禁用、Home 返回和直接入口都不应绕过 `物性` 主路径。
- 普通空白项目进入空 Workbench 后的首屏职责按区域固定：放置入口归左侧 `模块`，对象树归左侧 `项目`，选择语义归右侧 `画布选择 / 检查器`，消息和状态汇总归底部，结果入口只表达当前缺少 snapshot，不提前展示完整报表。
- Home 显式 `返回工作区` 是当前已打开项目的继续入口；最近项目卡片仍可作为状态和选择列表，但不要求用户通过双击当前卡片来表达“回到工作区”。
- 当前 MVP 的 `物性` 页不渲染只有未来含义的二级导航；长期物性工作区空间仍保留在设计文档中，但当前实现只呈现受控 package / component 选择和摘要。
- `Cmd+Q` 与窗口关闭按钮必须共用同一关闭确认路径，避免在 macOS 退出入口绕过保存 / 另存为确认。
- macOS 默认 App 菜单的 `Quit` 项会绕过 egui shell 快捷键层；当前阶段禁用 winit 默认菜单，让 `Cmd+Q` 由 Studio 自己的关闭确认路径处理。
- `dev` 是日常开发分支，不自动触发 CI/CD；CI/CD 自动入口只放在 `dev -> master/main` 稳定化 PR，默认分支门禁同时覆盖 Rust workspace、Windows `.NET` CAPE-OPEN baseline 和 Windows staging package。
- `Release Checks` 当前只保留手动 staging preflight，不因 tag push 自动运行；正式 GitHub Release、安装包发布、COM 注册和 PME 自动化仍不进入当前阶段。
