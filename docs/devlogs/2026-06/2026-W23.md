## 关键决策

- 旧 `SolveSnapshot` 只保留为历史和 stale notice 来源，不成为第二套结果真相源。
- Results commands、轻量复制 / 导出、Result Inspector、底部结果表和 review summary 只消费当前 revision 的 latest snapshot。
- 编辑后旧结果失效属于建模正确性表达，不进入跨快照报表、差异比较或完整历史结果管理。
- `Resume` 是用户可触发的运行入口，不能因为它来自 Hold/pending 状态就绕过 readiness；`Recover failure` 命令本身仍只执行失败恢复动作，恢复后若产生新的 Feed source stream 输入缺口，后续 Resume 继续由 readiness 引导补齐。
- readiness 的单一判断源放在 GUI shell 之下、求解派发之前；物性包解析仍先走正式 run package resolution，结构性连接、拓扑、非法旧项目和求解阶段参数失败仍交给 Run Panel 诊断 / recovery。
