# 2026-W34 Development Log

周期：2026-08-17 至 2026-08-23

## 摘要

用途：记录 RadishFlow 社区健康文件与仓库治理门禁的阶段性完善。
读者：仓库维护者、审查者与后续 AI / Agent。
不包含：产品功能恢复计划、模拟能力扩张或对外支持承诺。

- 新增贡献、安全和社区行为准则，并保持与停止公开业务功能维护、source-available 许可和职业合规边界一致。
- 远程仓库已启用的 GitHub Private Vulnerability Reporting 已成为正式私密报告入口；Issue 选择器关闭普通空白 Issue，只保留安全联系入口。
- 现有 Rust `xtask` 扩展为统一仓库治理实现源，新增必需文件、Markdown 相对链接、JSON、协作文件同步、GitHub 配置契约和 diff whitespace 检查。

## 本周目标

- 参考 RadishAxiom 与 RadishLink 的社区治理实践，为 RadishFlow 补齐适合当前停更状态的仓库健康文件。
- 不照搬公开 Bug / 变更提案入口，不释放恢复外部贡献或产品维护的错误信号。
- 把新增治理规则接入现有 Rust `xtask` 与 CI，不建立平行 Python 检查器。

## 完成情况

- 新增根目录 `SECURITY.md`、`CONTRIBUTING.md` 与 `CODE_OF_CONDUCT.md`，并从根 README 和文档索引提供可点击入口。
- 新增 `.github/ISSUE_TEMPLATE/config.yml`：设置 `blank_issues_enabled: false`，安全联系链接直达 `security/advisories/new`。
- 更新 PR 模板，明确只接受经仓库所有者确认的外围维护，并增加业务范围、第三方材料、安全和回滚检查项。
- 新增 `xtask/src/repository_governance.rs`，由 `check-repository-governance` 与正式 `check-repo` 共同调用；检查范围包含未跟踪但未被忽略的仓库文件。
- PR `Repo Hygiene` 使用 base ref 执行完整 PR diff whitespace 检查；手动 `Release Checks` 执行同一治理基线。
- `xtask` 单元测试由 7 个增加到 12 个，新增 Markdown 链接提取、代码块排除、多链接收集、链接目标分类和百分号解码覆盖。
- 2026-08-20 正式执行 `./scripts/check-repo.sh` 通过：治理检查覆盖 3188 个文件，文本门禁、`cargo fmt --all --check`、`cargo check --workspace`、`cargo test --workspace` 与 `cargo clippy --workspace --all-targets -- -D warnings` 全部通过。

## 关键决策

- 不新增公开 Bug 或功能提案 Issue Form；项目当前停止公开产品问题处理，Issue 选择器只承担安全引导职责。
- Private vulnerability reporting 与 `SECURITY.md` 并行保留：前者提供私密传输渠道，后者定义安全范围、材料要求和协调披露边界。
- 继续以 Rust `xtask` 作为跨平台检查真相源；JSON 校验复用 workspace 已有并已锁定的 `serde_json`，不引入新的依赖包。

- 远程 ruleset 与仓库模板仍应按 `.github/rulesets/README.md` 独立核对；仓库内检查不能替代 GitHub Settings 的真实配置。
