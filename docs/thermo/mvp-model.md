## 职责与实际实现

- `rf-thermo` 定义 `ThermoComponent / ThermoSystem / ThermoProvider`，计算关联式、K 值、相焓和泡露点。
- `rf-flash` 定义 `TpFlashInput / TpFlashResult / TpFlashSolver`，执行 TP Flash 与相组成求解。
- `rf-model` 承载 `MaterialStreamState / PhaseState / BubbleDewWindow`，供单元、solver 和 UI 传递。
- `rf-types` 是相区 pressure / temperature tolerance 的真相源；flash 复用该容差调和边界附近的分类差异，远离边界的真实冲突仍报错。

目标上计算与 provider 接口不承担文件缓存、授权索引或网络编排。当前 `rf-thermo::CachedPropertyPackageProvider` 实际直接依赖 `rf-store` 并执行缓存装载与过期过滤，尚不满足完整的纯计算隔离；详见 [架构总览](../architecture/overview.md#core-与持久化)。2026-09-29 将职责分离纳入 [MC2](../topics/modeling/model-catalog-and-runtime.md#分阶段切片)，代码尚未迁移。

物性配置、包数据与运行上下文的规划归 [物性专题](../topics/property-basis-and-components.md#物性配置与运行上下文规划)。本篇继续拥有公式、近似和物理验证事实；替换装载器、建立工厂或通过 CAPE-OPEN 接口验收不会自动改善数值准确性。后续 PH / PS、焓基准、真实物性和守恒按 P3 的具体单元工况实施，不以先完成通用插件系统为前置。

现有具体实现仍命名为 `PlaceholderThermoProvider` 与 `PlaceholderTpFlashSolver`，但已执行以下算法；名称既不表示完全未实现，也不表示通用物性实现已经完成。

## 已实现公式与输入约定

| 部分 | 当前实现 | 解释限制 |
| --- | --- | --- |
| Antoine | `ln(P_sat / kPa) = A - B / (T[K] + C)` | 系数必须匹配该对数底与单位，不能直接套用其他单位制的 A/B/C |
| 理想 K 值 | `K_i = P_sat_i / P` | 理想溶液 / 理想气相近似；无逸度系数、活度系数和真实 EOS |
| TP Flash | Rachford-Rice、相区判别、相分率和相组成 | 限当前 MVP 样例假设 |
| 泡露点 | 定温 bubble/dew pressure，定压 bubble/dew temperature | 由同一关联式估算，不是完整 phase envelope tracing |
| 相摩尔焓 | `h_phase = sum_i(x_i,phase * Cp_i,phase) * (T - 298.15 K)` | 常热容显热近似，未建立完整相间参考态与相变潜热 |
| overall 摩尔焓 | liquid / vapor 相焓按 flash 相分率加权 | 是该简化模型的混合结果，不表示能量平衡已求解 |

表中 `x_i,phase` 是传入该相焓计算的组分摩尔分率。温度、压力和流量使用 K、Pa、mol/s；组成使用摩尔分率。直接 thermo / flash 数值 API 要求组成有限、非负并归一；TP Flash 总摩尔流量必须有限且非负，拒绝 NaN 和正负无穷，零流量保持允许；单元层会先归一化文档组成，Studio 运行 readiness 另行检查文档输入。

[AntoineCoefficients](../../crates/rf-thermo/src/lib.rs) 当前只保存 A/B/C，没有适用温区、临界性质或数据引用字段。数值有限、压力为正及求解成功，均不能替代关联式适用范围判断。

## 单元近似与能量解释

| 单元 | 当前行为 | 未完成的物理含义 |
| --- | --- | --- |
| Feed | 从已提交源流股物化状态与整体焓 | 不提供独立物性准确性证明 |
| Mixer | 合并流量和组成，按摩尔流量加权入口温度，限制出口压力 | 未通过总焓平衡求出口温度；热容、组成或相态变化时不保证绝热能量守恒 |
| Heater / Cooler | 使用指定出口 T/P，继承入口流量与组成，并物化焓与窗口 | 无指定热负荷反算温度的 PH 路径，不构成完整换热器模型 |
| Valve | 保持入口温度并降低压力，继承流量与组成 | 不等同于绝热等焓节流，未求解 PH Flash |
| Flash Drum | 在指定 T/P 下进行汽液分配，形成 liquid / vapor outlet | 固定 TP 分离不自动证明设备绝热能量平衡 |

当前相焓在 `298.15 K` 的液相与气相都回到零点，没有用相间参考焓差表达真实汽化潜热。因此 H 适合验证 DTO、单位和当前算法一致性，不能直接作为真实相变热负荷依据。

Mixer 的区别可对照 [IDAES Mixer 模型](https://idaes-pse.readthedocs.io/en/stable/reference_guides/model_libraries/generic/unit_models/mixer.html)：其能量混合使用总焓平衡。该引用用于说明物理模型差异，不表示本仓库采用该实现或与其完成对标。

## 样例身份与适用范围

`binary-hydrocarbon-lite-v1`、其 methane / ethane 组分名以及历史文档中的 `official hydrocarbon`，标识的是仓库标准演示与回归路径，不代表独立审核的真实物性数据。当前没有从样例追溯到独立参考输出、适用温区和工程误差的完整证据链；这些结果应按演示 / 合成模型解释。

例如 [300 K 黄金样例](../../tests/thermo-golden/binary-hydrocarbon-lite-v1-300k-650kpa.json) 把 methane 的 Antoine 计算结果记为饱和蒸气压。NIST 给出的甲烷临界温度约为 `190.6 K`，其 Antoine 数据也明确列出低于约 `190.5 K` 的适用温区；该样例在 `300 K` 的计算值不能作为真实甲烷纯组分汽液饱和蒸气压。这个判断针对纯组分关联式，不推导为含超临界组分的混合物一定不能形成两相。[NIST Chemistry WebBook: Methane](https://webbook.nist.gov/cgi/cbook.cgi?ID=C74828&Mask=4)

`water-ethanol-lite-v1` 的 PME 人工记录用于验证宿主识别、材料读写和调用闭环，也不构成独立物性准确性背书。

以后如获准引入真实数据，应先明确关联式形式与单位、组分身份、来源版本、适用温压区间、参考态、独立期望值和误差依据。当前 DTO 未实现这些元数据，本次不更改数据格式、样例名称或结果值。

## 结果传递契约

- TP Flash 输出携带 `phase_region` 与 `bubble_dew_window`，并物化 liquid / vapor 与 overall 摩尔焓。
- Flash Drum outlet 按各自组成重算边界窗口，不直接复用 feed 的窗口。
- Feed、Mixer、Heater / Cooler、Valve 的整体焓通过同一 TP Flash 路径物化；后续 consumer step 复用已物化流股。
- `rf-solver -> rf-ui -> Studio` 传递同一份 T/P/z/H/窗口结果；Result Inspector、Active Inspector 和导出不得分叉另一套数值求值逻辑。
- `Converged` 表示当前算法与执行契约成功，不包含物性适用域认证、能量守恒认证或工程精度等级。

结果状态、revision 与相缺席语义见 [SolveSnapshot 参考](../reference/solve-snapshot-results.md)。

## 多策略求解的热力学要求（规划）

2026-09-29 将以下要求纳入 [多策略求解](../topics/modeling/solver-strategies-and-assembly.md)。现有接口仍是简化物性和 TP Flash，没有通用导数或 EO 物性契约；下列是后续切片要求，不改变当前公式、数据或结果。

- 按模型提供状态函数与必要导数：明确温度、压力、组成等独立变量、固定条件、相态、单位及焓 / 熵参考态。组分归一约束下的独立变量和导数基准须一致，不能把不同定义的偏导直接拼入同一矩阵。
- 联立模块使用局部求解响应时，导数应包含内部收敛状态的变化。数值差分需验证扰动步长、缩放、内层误差和重复性；不在规划阶段强制全部使用解析导数或自动微分。
- EO 可按模型将相平衡关系纳入方程，也可调用局部收敛的隐式物性子问题；二者需要各自的导数和误差契约。不要求每次迭代先对所有流股做完整 Flash，也不把当前 TP 状态结构视为全部 EO 变量表达。
- 迭代状态可能尚未满足所有约束，必须与已收敛物流快照分开。物性适用域仍须校验；超域、局部不收敛、缺少性质与导数无效分别返回，不用裁剪或默认值隐藏失败。
- 相出现 / 消失、分支切换和非光滑行为由所选模型与求解策略显式处理，不能假定相界导数连续。具体固定相区、活动集或其他技术在案例切片审定。

验证覆盖适用域内性质与导数、不同差分步长、相界两侧、局部误差对外层残差的影响，以及同一物性 / 参考态下的跨策略结果和衡算。独立基准继续归本篇及具体模型专题，求解器比较不构成物性精度认证。

## 工程基准与数据可信度规划

2026-09-16 确认输入来源、适用范围和可分发验证案例进入后续工程能力建设。物性数据 / 方法版本与估算或外推状态进入 [工程来源](../topics/engineering-basis-and-cases.md)，不确定度与拟合误差、求解容差和显示小数位分开；当前 DTO 未携带完整元数据，本轮不迁移数据。

首个可信模型的验证包应明确组分身份、温压与组成基准、相态、参考态、数据来源 / 使用许可、计算方法 / 版本、独立期望值与容差，以及可运行输入和复现方式。算法解析或手算基准、公开实验、供应商和现场数据分别标识；不同证据支持不同范围，不能直接比较不一致的相态或焓参考态。

对标其他软件前先对齐物性方法、交互参数、相集合、参考态和工况；差异用于诊断，不把任一软件默认结果当唯一真值。原有 golden 继续用于实现回归，新增独立依据不能从同一实现再次生成。敏感性与不确定度传播以后在数据足够时实施，未知不确定度显示未知，不预先承诺工程精度。

### 推荐范围与选择理由

首个候选物系为丙烷（CAS `74-98-6`）/ 正丁烷（CAS `106-97-8`），规格限 TP、摩尔组成和总摩尔流量，目标为同一次平衡的气液组成、摩尔相分率、相质量密度与工况下实际相体积流量。先考察 `280–320 K`、`0.2–1.0 MPa`、丙烷总摩尔分率 `0.2–0.8`；这是待验证的候选范围，不能直接宣称整个区间有效。

| 路线 | 判断 |
| --- | --- |
| 延伸现有 Antoine / 理想 K 并另补液体密度 | 缺少现有演示数据的物理证据，且要另审密度混合规则，不推荐作为默认路线 |
| Rust 内实现有明确版本的 Peng–Robinson（PR） | 推荐候选；相平衡与相体积使用同一 EOS，但液体密度精度必须独立验证 |
| 直接将 CoolProp 接为产品运行时 | 可另评估，但引入 FFI、部署与版本边界；本次仅建议用作离线参考工具 |

PR 候选固定为标准 PR76、经典二次混合规则，不加体积平移。首轮显式取对称 `k_ij = 0`，记录为**待验证的模型假设**，不是查得的实验参数；不隐藏默认值，也不为通过验收临时拟合。CoolProp 的 [cubic 文档](https://coolprop.org/coolprop/Cubics.html)提供独立 PR 路径并说明交互参数需由使用者指定。若首轮无法达到下述目标，先报告失败和原因，再审定缩域、参数证据或模型改选，不自动叠加修正。

### C2-A：首批交付与退出条件

本批只建立可复现的验证包与数值决策，不改产品计算、DTO、项目格式或 UI；独立参考脚本、可分发 fixture 与 S1/S2 敏感性 harness 已完成，见 [验证包与结果](../../tests/thermo-validation/c2a-pr76/README.md)。

1. **冻结来源清单。** 每个组分保存身份、摩尔质量、临界性质、偏心因子、原单位 / 转换、原始来源、版本及使用许可。分别记录方程版本、混合规则、交互参数依据、参考工具精确版本 / commit、输入与输出摘要。数值从一个已核对的数据版本成套选取，不拼接不同版本的常数。
2. **冻结参考环境。** CoolProp PR 用于同模型独立实现对照，HEOS 用于不同模型的偏差筛查；两者都属于计算证据，不能标为实验。官方 [丙烷](https://coolprop.org/fluid_properties/fluids/n-Propane.html)与 [正丁烷](https://coolprop.org/fluid_properties/fluids/n-Butane.html)页面可追溯各自参考 EOS；混合物参数需另核对 [混合物模型与参数表](https://coolprop.org/fluid_properties/Mixtures.html)。禁止用缺参估算回退替代选定参考。工具安装限隔离验证环境，先告知，不加入产品依赖。
3. **补物理证据。** 至少取得覆盖候选两相区的可追溯二元 VLE 数据，以及纯组分 / 混合物密度依据，记录数据不确定度或明确未知。公开可读不等于可再分发；逐项核验许可，保留必要归属，不复制受限数据库。若只能取得参考 EOS 输出，报告只能是模型对照，不能核销工程准确性门禁。
4. **形成验证包。** 包含可运行输入、冻结的参考输出、来源 / 许可表、独立生成步骤、误差表、失败点和最后建议适用域。原始评估网格完整保留，缩域须给出可执行边界与理由，不只挑通过点；新增留出点验证边界内部，不能用稀疏点通过推导连续域通过。
5. **提交审定。** 对比相流量 / 密度偏差对既有 S1 / S2 算例的尺寸和负荷结论影响，交付 C2-B 的具体类型、能力和兼容变更清单。来源、有效域或误差目标未满足时，A 可交付失败报告，但不得宣布 C2 达标或启动 C3。

| 纯组分 | 两组分在 280 / 300 / 320 K 的饱和压力、气液密度；稳定单相点 | 与独立物理依据对照；初筛饱和压力误差 ≤2%、各相密度 ≤5%，并单列参考不确定度 |
| 二元相平衡 | T=280 / 300 / 320 K，P=0.2 / 0.5 / 1.0 MPa，z=0.2 / 0.5 / 0.8，共 27 点；参考泡露点两侧及留出点 | 先确认相态一致；两相内部的 β、x、y 绝对误差各 ≤0.02；两相密度相对误差各 ≤5% |
| 实际体积流量 | 上述两相中部点，固定总流量 10 mol/s；另做 0.1 / 1 / 10 倍缩放 | 当参考 β 在 0.1–0.9 时各相 Q 相对误差 ≤10%；近消失相另报绝对误差，不能用微小分母或排除点掩盖问题 |
| 同模型独立实现（B） | 与冻结参数的独立 PR 对照相态、β、x/y、Z、密度 | 非相界点：密度 / Z 相对差 ≤1e-6；β、x/y 绝对差 ≤1e-7；同模型一致不代替上两项物理对照 |
| 守恒与平衡（B） | 每个有效点检查组成归一、相 / 组分物料衡算、逸度一致性与稳定根 | 归一残差 ≤1e-10；组分流量残差 ≤max(1e-10 mol/s, 1e-8×总流量)；两相有效组分的绝对 ln 逸度比 ≤1e-8 |
| 鲁棒性（B） | 组分排列、重复执行、缩放、零流量、NaN/Inf、负流量、域外、缺参、相界与不收敛 | 置换 / 缩放不改热力学状态；失败分类明确，不返回伪造两相或旧结果；相界用单独绝对容差与相缺席约定 |
| 工程敏感性 | 将参考值与候选值分别送入同一组固定 S1 / S2 输入，其他工程参数相同 | 初筛尺寸差 ≤5%、负荷差 ≤10%；若准则结论翻转须标记并评审，不能仅凭数值接近放行 |

同模型与物理对照分别保存测试数据和来源；不得调用待测 Rust 实现生成其自身验收期望。参考工具若失败，记录参考缺口并找可追溯替代，不能把它自动当作被测实现错误。纯组分饱和 TP 不唯一确定相分率，不将任意 β 当参考答案；二元相界与单相结果也不能直接作为 C3 的有效气液工况。

### C2-A 实测结论（结果待审）

首轮结果已获认可并提交为 `196c5d54`；[完整报告与复现步骤](../../tests/thermo-validation/c2a-pr76/README.md)冻结 CoolProp 8.0.0、PR76 / k_ij=0、六篇 ThermoML 来源 / 2,882 条数值记录。84 个二元 TP（76 域内）、24 个纯组分状态、154 组实验比较和 276 次既有 S1/S2 计算均保留输出与失败。

- PR 对实验指定分支密度最大偏差 5.705%，超过 5% 目标；压力项通过不代表密度达标。所选 VLE 汽相组成对 PR 与 HEOS 都有明显偏差，需第二套 VLE 或原表核验；不删除失败数据，不把 HEOS 当实验真值。
- CoolProp PR 的 16 个二元、9 个纯组分 TP 标签与其自身饱和包络矛盾，单列参考异常，未伪装成产品算法错误；同模型 B 参考资格尚不完整。
- 工程直径最大差 2.693%，138 对均通过；负荷近相界超限，并有一个中部工况的液体负荷 / 综合结论翻转。首轮实测二元气相与正丁烷气相密度覆盖不足；第二轮补入正丁烷离散点，二元气相仍缺。
- **A 可按失败报告交付；目前没有可声明达标的连续适用域，B / C3 不进入实现。** 首轮证据与判据保持冻结；改参数、体积平移、换模型或缩域均需重新审定。原生保存异常仍未修复。

第二轮 [标签核验与证据补强](../../tests/thermo-validation/c2a-evidence-review/README.md)已获认可，提交为 `0bc33f59`：

- 102 个状态的版本 / 更新路径对照复现原 25 个入域标签异常；密度与独立 PR 均相根吻合，固定源码指向二元 reducing density 判据和纯物质赋值前相态重算。7.2.0 另有失败，未替换参考或改写原输出。
- 新增独立 Kayukawa 2005 VLE 来源，10 个入域配对点仍有 P / x / y / 构造 β 超差；新增 Glos 2004 正丁烷气相 PVT 5 点和饱和气相密度 3 点通过原密度判据。新比较 103 pass / 25 fail，不合并覆盖首轮统计，不宣称 HEOS 盲验。
- 二元气相密度仍缺可评分原表；VLE 冲突点尚需原期刊表核验。建议继续限 A 补证后再审参考资格 / 模型方案；原液体密度失败和工程结论翻转保持，B / C3 未实施。

第三轮仍仅推进 A 的 [VLE 原文与密度来源审计](../../tests/thermo-validation/c2a-source-audit/README.md)，结果待审。三个关键冲突点与论文公开预览文本一致，未发现支持修正原记录的证据；正式原文 PDF / 表图尚未取得，不能宣称全表认证。作者声明与 ThermoML 编目评定的不确定度已分开记录；54 次泡点扰动计算没有消除汽相组成冲突，原判据和失败不变。混合物气相密度新线索定位 GPA RR-147，但尚无合格逐点数据及不确定度；需取得合法原始材料后继续资格评定，B / C3 未实施。

### C2-A 后续方法对比与排期

2026-10-23 所有者认可新增离线方法对比，并明确工程基础优先。以下是已认可的专项验证范围，**尚未实现或取得新结果**；按 [AF 基础切片](../radishflow-mvp-roadmap.md#基础架构优先的实施切片) 安排，不以完整 C2-A 补证阻塞编辑、存储、装配或运行管理建设。

- 原 PR76、经典混合规则、`k_ij=0`、无体积平移、相平衡 / 密度同 EOS 的试验保持冻结，原失败和误差目标不变。新的独立候选允许将 PR 相平衡 / 气相密度与液体密度关联式分开比较；这是后续研究范围的扩展，不回写原 C2-D02 基线。
- PR76 继续作为相平衡候选；液体密度优先评估 COSTALD，以修正 Rackett 对照；PR 体积平移先审查具体公式、参数以及对平衡 / 其他性质的影响，再决定是否进入数值比较。COSTALD 需冻结特征体积、混合规则和压缩液体压力修正，不能直接将饱和密度用于全部 TP 状态。
- 先冻结方法 / alpha / 二元参数 / 参数来源与版本；缺参不静默估算。`k_ij=0` 保留为基线，有可追溯且匹配方法版本的参数时另列候选，本次不默认授权拟合。私有资料只作方法与来源核对，公开验证输入仍须满足来源和分发约束。
- 先在实验给定的 T / P / 液相组成下比较密度，再结合 PR 求得的实际相组成评估相流量与既有 S1 / S2 敏感性。VLE、参考工具稳定性资格和气相密度证据独立评定；密度改善不能核销相平衡冲突或缺失实验依据。
- 该组合只评估限定 TP、密度与体积流量，不推导焓熵一致性、PH / PS 或动态能力。混合物气相证据缺口不阻塞液体方法初筛，但仍约束工程放行。

本安排不增加产品依赖，不启动 C2-B / C3，也不将基础架构验收等同工程准确性通过。

### C2-B：拟议接口影响，须在 A 后审定

当前 `ThermoProvider` 依赖理想 K 的调用形态，`TpFlashSolver` 路径还强制物化相焓和四项泡露点；`PhaseState` 缺密度 / 流量与来源版本。因此 B 不是给 UI 增加两列：

- `rf-thermo` 拥有 PR 的相逸度 / 相摩尔体积与不可变参数，`rf-flash` 拥有稳定性判别和两相联立迭代；不能把组成相关的逸度平衡伪装成只算一次理想 K。`rf-model` 只承载结果和来源，不承载策略。
- 每一实际相由该相组成计算 `M_phase = Σ x_i M_i`，`rho = M_phase / v_m`，`n_phase = F_total × beta_phase`，`Q_actual = n_phase × v_m`。统一物化后传至单元、solver 快照、UI 和输出；相总流量不可与出口已分相流量重复相乘。Overall 不能冒充一份气相或液相密度。
- 结果携带方法 ID / revision、参数集版本 / 摘要、组分身份、适用域检查结论与来源引用；缺失、域外、单相、零流量和不收敛显式区分。旧演示结果保留缺性质状态，不因补字段自动取得 C3 资格。
- 首个产品消费者限指定 TP 的 `Feed -> Flash Drum`。新包不支持的焓与窗口保持明确不可用，不能调用演示 Cp / Antoine 填满；消费端按所需能力拒绝。PH / PS、能量闭环、Mixer / Valve 的物理升级、输运性质、完整相图与通用插件运行时另开切片。若现有消费链无法表达缺性质，应改清能力边界，不用数值零兜底。
- 包选择、数据版本和参数变化须使依赖结果失效。保存配置及版本身份，重开不恢复旧执行；旧项目不自动换包。存储、SolveSnapshot 与 CLI / 导出的具体兼容策略在 B 清单中冻结，不能静默增加字段破坏严格旧读者。
- B 验证包括从纯计算到正式快照再到输出的同源性、错误透传、版本失效、保存重开 / 旧文件兼容与完整 `check-repo`。如启用新包选择和性质展示，先完成局部 UI 审阅再做原生验收；不借此授权 C3 关联入口。
