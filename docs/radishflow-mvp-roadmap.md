# RadishFlow 开发路线图

更新时间：2026-09-16

## 用途

用途：记录第一阶段成果、基础功能优先的近期顺序与长期模拟平台的阶段退出标准。
读者：需要理解现有成果、历史目标和可能的投资顺序的项目所有者与维护者。
不包含：当前任务清单、逐日验证流水、完整 UI 设计和新的产品交付承诺。

## 维护状态

自 2026-09-12 起恢复正常开发和迭代。2026-09-13 项目所有者确定：先完善基础功能与使用闭环，再集中深化算法、数值准确性与鲁棒性；基本正确性和可靠性贯穿各阶段。长期扩展到稳态、动态、瞬态、间歇及多种求解组织方式，统一变量 / 动作树、COM 自动化和操作录制作为扩展目标，领域边界见 [模拟平台长期规划](architecture/simulation-platform.md)。当前优先级与下一切片以 [当前状态](status/current.md) 为准；旧 Sprint 保留为历史记录。

每个迭代切片应明确用户价值、范围、非目标和退出标准；架构、接口与依赖变化按正常协作流程确认，发布与部署按专门流程验收。

2026-09-16 确认新增 [单位系统](topics/units-and-quantity-system.md)、[规格分析与建模辅助](topics/modeling-assistance-and-specifications.md)、[设备设计与校核](topics/equipment-design-and-rating.md) 专题。现有 B3-5 仍为下一实现切片，其后优先单位和规格基础；UI 功能分区重新评审与非 UI 基础工作衔接。具体新增顺序见下文，不表示新能力已实现。

## 第一阶段目标与成果

第一阶段目标是验证 Rust Core、Rust Studio 与 `.NET 10` CAPE-OPEN PMC 能在最小稳态流程中协作。保留的能力见 [MVP 范围](mvp/scope.md)。

| 里程碑 | 历史目标 | 已有证据与限制 |
| --- | --- | --- |
| M1 | 仓库与基础骨架 | workspace、分层和治理检查已形成 |
| M2 | 二元 TP Flash | 算法、golden 与相边界回归已形成；不等于独立物性准确性验证 |
| M3 | 小流程与 Studio 闭环 | 受控建模、运行、结果审阅、保存 / 重开 / rerun 已有回归 |
| M4 | Rust FFI 与 .NET 适配 | JSON / error、native 装载与调用路径已有基线；生命周期保护已补齐，平台验证见周志 |
| M5 | PME 识别并调用 PMC | DWSIM / COFE 代表场景完成历史人工验证，不推导为任意宿主支持 |

MVP α、β 人工 smoke、失败恢复和通用小流程建模已阶段性收口。已通过范围不包含完整自由连线、真实 EOS、recycle 收敛、完整能量闭环、第三方模型加载或正式发布。历史 `v26.5.1-dev` 仅为内部 staging 记录。

## 后续迭代顺序

以下是按依赖推进的能力阶段，不是一次性实施清单或发布日期承诺。当前继续完善 P1，P2 已推进变量读写、受控动作和 B3-4 首个无界面参数化运行消费者；2026-09-15 经项目所有者确认，其他平台原生验收累积到阶段节点集中验证，P1 未测项不视为完成。跨领域的平台边界从现在开始遵守，但不要求先做完通用框架。已知数据安全和内存安全问题随时处理。

| 阶段 | 目标 | 主要工作 | 退出标准 |
| --- | --- | --- | --- |
| P1 基础功能闭环 | 普通用户可完成建模与修改，无需依赖固定演示流程 | 组分 / 物性选择、对象与连接编辑、参数、单位输入 / 显示、undo / redo、规格检查 / 诊断、结果、保存 / 重开；逐项补缺口 | 选定编辑任务从空白项目可完成；命令、revision、错误和结果一致；成功与失败路径有代码及真实窗口证据 |
| P2 运行与扩展基础 | 提供可观察运行和变量树式自动化入口 | 输入快照、任务 / 取消、变量 / 单位 / 动作元数据、浏览查询、命令写入、确定性工作流、COM / 无界面适配、录制回放 | GUI / API 操作语义一致；从创建对象到参数、诊断、运行与结果可自动化；录制脚本可参数化回放；取消不误提交旧结果 |
| P3 稳态数值与工程能力 | 对有限工况形成有独立依据的稳态计算闭环 | 物性与焓模型、规格 / 单元、能量闭环、设备尺寸与校核、递归分块及 recycle | 组合块 / 原子块 / 循环块的依赖、局部收敛与失败传播正确；守恒、独立基准和边界行为通过；设备任务有方法、适用域及可追溯工况 |
| P4 多求解策略 | 按问题特征使用序贯模块、联立模块、联立方程及混合分区 | 模型能力、变量 / 方程与耦合残差、导数、缩放、结构检查、初始化与可替换后端 | 同一物理问题在支持的策略间结果一致；不支持组合显式拒绝；诊断能回到领域对象 |
| P5 装置动态与间歇 | 支持有积存、控制、事件与操作阶段的时间相关工程模型 | 容积 / 压流关系、DAE、初值、稳态初始化、控制、间歇 / 半间歇配方、轨迹与检查点 | 动态基准、积存、初始化与时间步收敛通过；配方阶段切换、仿真时钟与批次收支正确 |
| P6 分布参数瞬态 | 逐步支持管道、井筒与网络的空间和时间变化 | 空间离散、输运与闭合关系、边界条件、热耦合、多相及协同仿真 | 先单相后复杂模型；空间 / 时间收敛、守恒、波传播与选定实验基准通过，耦合误差可评估 |
| P7 工程研究与生态扩展 | 将可信模型用于更完整的工程任务 | 参数估计、敏感性 / 优化、反应与行业包、APC / MPC 离线研究、数据协调、报告、能效 / 排放 / 经济分析及外部集成 | 每个扩展有明确消费者、独立验收和版本兼容要求，不以基础求解收敛代替专业结论 |

依赖按切片判断：P5 需要具备所用模型的物性、动态方程和时间积分能力，但不必等待 P3 的所有设备或 P4 的全部求解策略完成；P7 的基础报告和 API 可在 P1 / P2 随需求交付。高级算法和动态探索不能成为 P1 编辑 / 保存闭环的前置门禁，也不将数值正确性全部拖到 P3 后才检查。

递归分块与文献中的 Simultaneous Modular 分别处理：前者在 P3 演进执行计划，后者在 P4 按需要联立模块间耦合变量。模型树、变量浏览树与求解树不要求同构；不能把画布分组或重复运行循环块当作已经实现收敛算法。

P2 的自动化按可交付切片展开：先做变量 / 动作描述和只读浏览，再接入统一命令写入、创建 / 连接 / 运行与首个外部适配器（Windows COM 为明确目标），随后实现录制、参数化脚本和重复工况回放。运行任务与取消能力按其依赖同步完善；不以整个 P2 一次性交付为前提。

### 单位、辅助、设备与 UI 的实施顺序

下表细化 P1—P3 的近期与工程切片，不另建替代总路线。U / A / E / S / H 编号的完整验收由各专题拥有；R 编号由 UI 专题拥有。

| 顺序 | 能力切片 | 依赖与退出标准 |
| --- | --- | --- |
| 1 | B3-5 无界面创建与连接 | 复用已交付受控动作，明确返回身份的后续引用与逐步错误；完成创建→写入→连接→运行→结果，不顺带改造单位协议 |
| 2 | U1—U3 单位基础及首批接入 | 唯一元数据 / 转换、单位集与输入显示分离；温压流量和已有结果贯通，旧 SI 契约及结果有效性不变 |
| 3 | A1—A2 规格检查与推荐 | 现有单元缺项 / 互斥 / 合法操作可解释，规则与动作同源；完整结构自由度随模型能力补齐 |
| 4 | E0—E1 工程场景与首个设备任务 | 按设备明确物性 / 方法 / 基准；按 S0—S1 优先评估并交付分离器初步尺寸，换热器 H0—H2 随 P3 能量闭环推进；不得使用演示精度作工程依据 |
| 5 | E2—E3 设备深化与流程关联 | 推荐采纳、几何校核、源结果过期、多工况及热力 / 水力细化；与动态按真实依赖衔接 |
| 后续 | A3—A5 工作流 / 结构分析 / Agent | 固定工作流随运行能力交付；结构分析随方程模型推进；Agent 未排期且复用统一入口 |

[R0—R2 UI 重设计](architecture/studio-ui-topic-plan.md) 与上述顺序衔接：先整理任务与信息架构，优先评审单位输入 / 显示、规格检查、设备任务三类代表路径，再通过 Pencil 更新对应画板。影响用户入口、布局或字段交互的切片需先评审其相关设计；B3-5 和纯单位转换逻辑不等待整套 UI 完成。旧 `.pen` 的既有定稿仅保留历史范围，新功能分区尚未定稿，不据此直接进行全界面代码重写。

设备能力是独立稳态工程主线，不排在 P5 / P6 之后；数值依赖按所用方法补齐。单位定义、规格规则与工程结果由领域拥有，UI、脚本和未来 Agent 均作消费者。当前不接入大模型，不为未来预建空模块、聊天占位页或通用框架。

### 工程工作流的配套切片

2026-09-16 项目所有者进一步确认七项工程建议。它们补充既有 P1—P7；B3-5→单位→规格 / 推荐→首个可信设备任务的顺序保持。优先做 G0 设计基础、工况矩阵和数据来源的概念 / UI 设计，随后按依赖交付，避免一次增加整套工程平台。

| 主题 | 真相源与切片 | 进入时机与退出依据 |
| --- | --- | --- |
| 工程设计基础与来源 | [G0—G1](topics/engineering-basis-and-cases.md) | 随单位 / 规格设计细化；公共条件引用、局部覆盖与来源可追溯，旧工程兼容 |
| 多工况矩阵 | [G2](topics/engineering-basis-and-cases.md) / 设备 E2—E3 | 随可信稳态与设备任务；同几何逐工况校核，各约束控制工况及失败行完整；不阻塞首个单工况模型 |
| 设计规格求解 | [DS0—DS2](topics/flowsheet-modeling-and-solve.md#设计规格求解规划尚未实现) | P3 从真实单目标反算起步；目标 / 可调量独立，候选采纳和失败语义清楚；优化另验 |
| 分层工程检查 | [Q1](topics/results-review-diagnostics.md#工程检查与交付规划尚未实现) / 辅助 A | 先呈现已有检查和未支持范围；守恒、物性适用域及设备约束随模型建立，不用总绿灯代替 |
| 压力、公用工程与候选权衡 | [设备 E3](topics/equipment-design-and-rating.md) / S / H | 按压降、能量、供给及设备模型依赖推进；候选同条件可比、边界清楚，无数据不造成本或供需结论 |
| 工程交付与复现 | [Q2—Q3](topics/results-review-diagnostics.md#工程检查与交付规划尚未实现) / G3 | 先轻量计算表、来源 / 假设、位号和版本；完整报告、资产保存与历史比较逐项验收 |
| 最小可分发验证案例 | [物性验证](thermo/mvp-model.md#工程基准与数据可信度规划) / 各设备专题 | 首个可信模型同步建立；区分算法、实验、供应商和现场依据，记录许可、误差与复现条件 |

G0 纳入 UI R0 的项目→设计基础→工况→设备→结果关系；Q1 和目标反算须有正常 / 失败 / 未支持状态。近期做来源和适用范围提示，后续再评估不确定度传播、数据协调与现场标定，不把这些高级能力变成基础编辑的前置门禁。

### 插件与公共 API 的实施切片

2026-09-14 确认将插件系统、分层许可和公共 API 授权 / 配额纳入长期规划。以下按真实消费者和依赖进入 P2 / P7，不要求等到 P7 才能安装首个插件，也不作为 P1 基础编辑闭环的前置条件。

| 切片 | 主要工作 | 退出标准 |
| --- | --- | --- |
| 真实扩展点 | 选定物性、单元、导出或连接器场景，验证领域契约及 Host API | 内建与扩展消费者复用输入、错误、命令与结果语义；无空注册或成功占位 |
| 首个可安装插件 | Manifest、版本、授予权限、装载 / 禁用 / 升级、状态与资源隔离 | 真实插件完成正常操作及权限拒绝、故障、运行中禁用 / 升级；缺失插件重开不丢数据；数值插件另验开销与结果一致性 |
| 公共 API 访问控制 | 按 [专题 M0-M3](topics/platform/public-api-and-access-control.md#分阶段切片) 选定凭据、资源权限、key 生命周期与配额 | 首个实际调用方完成访问到撤销闭环；越权、超限、重复任务和旧结果提交被正确处理；本地接口不依赖云端 key |
| 许可与分发准备 | 按 [授权分层](architecture/auth-entitlement-architecture.md#软件许可产品授权与操作权限) 确认核心 / SDK / 插件边界、授权与评估路径 | 具体许可政策、组件许可证和必要模板已明确；软件使用许可、资产租约及 API 权限不混用 |
| 公开 SDK 与生态 | 稳定 Host API、示例、兼容测试及独立许可证，再按需求评估分发 / 市场 | 至少一个真实插件经过版本演进，兼容与生命周期证据齐全；没有实际需求时不提前建设完整市场或多语言 SDK |

插件运行时、首版 API 传输、免费 / 无席位许可、具体开放许可证及远端求解部署仍待相应切片决策。现有桌面 PKCE / Bearer 和资产离线租约不因本轮规划被替换，账户专题 M0 也不视为已经通过。

## 近期实施边界

- P1 从 [Studio 主路径的基础功能清单](topics/studio-main-workflow.md#基础功能完善切片) 开始，用代码入口、focused test 与 GUI 证据区分已实现、部分可用、待验证和缺失；不重复建设已有功能。
- 流程图基础编辑与连接管理已通过 B0 形成分层台账，并完成单元删除、重命名、导航修复和 macOS 原生项目保存切片；这不表示 P1 全部验收完成。后续切片与待补证路径见建模专题和当前状态；扩展端口选择或连接规则前先明确边界，不将自动布线和完整多文档同时并入。
- 组分查询添加、基础结果输出和运行反馈按主路径依赖顺序推进；组件拆分服务真实调用边界，不为了长期功能表立即重构全仓库。
- 新增基础动作时明确稳定对象身份、变量单位 / 读写条件、命令事务和失败语义，为变量浏览器与录制器复用；不要求先完成全量自动化系统才能交付基础编辑功能。
- P1 可继续使用明确标注的演示物性验证软件行为；真实工况、物性来源与独立误差要求，在对应数值模型切片实施前确定。既有 golden 和跨层回归继续保留，限制见 [热力学模型](thermo/mvp-model.md)。
- 每个切片包含目标、非目标、输入与状态所有权、接口影响、兼容性、成功 / 失败路径和退出标准。完成一次可独立验证的闭环后再扩展。

账户、控制面、云部署、完整多文档、完整报表和行业专用模型按实际依赖进入计划；动态与瞬态已纳入长期目标，仍不作为 P1 的同时实施任务。通用三维 CFD 保留为未来外部耦合评估方向，不默认建设完整自研 CFD 平台。
