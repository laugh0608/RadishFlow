## 归属与保存位置

**关注清单属于工程级审阅配置**，由当前工程的可编辑工作区持有。工程交付者可指定应检查的输入和结果，接收者打开文件即可看到同一清单。清单和它引用的对象身份在同一次 staged write 中写入 `.rfproj.json`，随工程移动、复制和另存。文件分叉后各自维护清单。

| 内容 | 归属与行为 |
| --- | --- |
| 关注项及其顺序 | 工程保存按用户顺序排列的 VB-D02 稳定引用。重复加入同一引用时选中已有行，清单及保存状态不变。 |
| 展开、筛选、选中、列宽等视图状态 | 属于使用者的浏览布局。首片沿用会话状态，切换工程清理。以后需要持久化时沿既有布局 / 偏好机制另审。 |
| 值、名称、单位、来源及状态 | 由当前工程查询投影。数值单位跟随项目现有显示单位。清单只持有引用及顺序，打开时按当前数据重建呈现。 |

现有布局 sidecar 在项目保存成功后单独写入，Studio preferences 当前保存最近项目路径。关注清单参与项目关闭确认及原子保存，应归工程文档。 [生命周期边界](../project-lifecycle-storage.md#设计边界) · [Studio 偏好存储](../../../crates/rf-store/src/studio_preferences.rs)

## v4 存储与兼容

外层采用 v4，清单字段为 `variableWatchList`，必需能力为 `radishflow.variable-watch-list` v1。能力与字段成对出现，依赖同一文件的 `radishflow.object-identity` v1。下例只列出新增字段。

```json
{
  "variableWatchList": [
    "rfvar:1/doc-demo/unit/heater-1/b91c614d-4a7a-4d0e-82ba-09c82da255ba/inputs/outlet_temperature"
  ]
}
```

- `rf-store` 校验有序字符串数组、非空白项及精确重复。格式层保留引用文本，由现有 VB-D02 解析器在工作区中判断引用能否定位。结构有效但解析失败的字符串可原样保存，防止普通保存抹掉待处理的项目数据。结构错误如显式 `null`、非字符串或重复项按已知格式错误处理。
- 无该字段的工程打开为空列表。首次保存非空清单时，经既有能力升级提示写入字段及标记。若首次保存前把清单改回空列表，保持原格式与保存基线。已保存过清单后，清空写 `[]`，沿用已声明能力。未启用对象身份的工程使用 VB-D02 的显式启用流程，保留当前字段选择。
- 能识别 v4 但缺少新能力的旧版整份原文只读，旧 writer 拒绝覆盖。新 writer 拒绝用缺少清单能力的内容覆盖已保存清单的目标。向不同文件另存时，如果目标已有另一份清单，覆盖确认须列明目标清单会被替换。保留外层版本规则与现有 CLI 能力边界。

## 操作与保存生命周期

首片提供加入、移除、调整顺序和定位。加入复用 VB-D02 的身份与字段校验。启用身份后，新建对象只要在当前工作区已有创建标识，即可加入关注，对象及清单在同一次保存中落盘。对外复制稳定引用仍沿用 VB-D02 的已保存身份门禁。

- 清单维护独立的当前状态和保存基线。加入、移除和重排可改变项目脏状态，参加打开其他工程、关闭与退出确认。回到已保存的内容和顺序时清除清单脏标记。清单操作不推进物理修订，不改变现有结果资格，也不进入建模 Undo / Redo。浏览、读取及定位本身不改变清单或文件。
- 保存和另存通过既有生命周期。准备时捕获清单内容及变更代次，连同工程输入、目标路径、能力和指纹一起校验。等待确认期间发生变化须重新准备。写成功后才推进清单保存基线。写失败、确认取消或目标变化时保留在内存中的清单、原路径及既有基线，并允许重试。
- 从关注清单选择两条或更多有效进料流股的总摩尔流量，可进入 VB2 批量核对。批次选择与检查回执属于 Studio 会话，表格继续投影正式值。失效引用保留在关注清单中，不能选入批次；移出批次保留 U2 草稿。显式应用后只更新正式建模输入。 [批量首片](../../architecture/designs/reviews/2026-11-14-vb2-penpot/README.md#首片实现提案)

| 场景 | 行为 |
| --- | --- |
| 保存重开或移动工程 | 恢复清单及顺序，解析当前打开工程的身份并重新读值。按现有规则重开时结果为 Missing，后续正式运行后刷新。 |
| 另存新副本 | 将当前清单与对象标识一起保存，含尚未保存的清单修改。成功后当前工作区切至副本，原工程保留上次成功保存的清单。文件系统复制继承的是磁盘已保存内容。 |
| 同 ID 副本分叉 | 只读当前打开分支的清单与值。添加、移除和重排各自保存。无自动合并，也无按 `DocumentId` 从其他路径加载清单的逻辑。 |
| 保存取消或失败 | 内存保留尚未保存的清单及其脏状态，沿已有 staged write 和恢复规则处理原文件。单独的布局保存失败不回退已成功保存的清单。 |
| 切换工程或只读检查 | 切换前照常询问未保存的清单修改。目标只读时沿原检查页处理，清理旧工作区的清单投影，禁止从保留的旧工作区显示或写入清单。 |

## 失效引用和结果资格

| 状态 | 界面与保存规则 |
| --- | --- |
| 重命名、改单位、重新排序 | 引用保持原身份，行更新当前名称、项目单位与显示顺序。 |
| 对象删除、对象 ID 重用、字段消失 | 原行与顺序保留，分别说明对象缺失、创建标识不匹配或字段缺失。禁用定位和当前值复制。撤销若恢复原对象及字段，重新解析后可用。删除后重建即使同名同 ID，也不得承接旧引用。 |
| 跨工程、格式错误、版本不受支持 | 保留原行与引用文本，标明原因，不按名称回退。加入入口只接受当前工程可验证的字段。用户可移除失效项，或定位到真实的替代字段后另行加入。 |
| 字段存在，值未指定或结果为 Stale / Missing / Failed | 引用仍可定位。按现有资格显示状态与可用来源。只有符合当前值条件的行才可复制数值。运行结束或视图刷新不改写清单。 |

## 验收与评审点

| 验收 | 代表证据 |
| --- | --- |
| 归属与保存 | 同一字段重复加入、重排、清空、首次保存确认与取消、重开及移动无 sidecar 工程。按保存基线验证未保存提示，观察物理修订和运行资格。 |
| 副本与写保护 | 同 ID 另存与操作系统复制，原件和副本独立修改。注入目标变更、写失败和已存在清单的覆盖确认。冻结 `809748b5` 验证整份只读、原字节保留及拒绝覆盖。 |
| 失效与恢复 | 重命名、删除、撤销、重开后 ID 重用、字段缺失、跨工程与未知引用版本。验证无效行不丢失，四种结果资格和定位独立。 |
