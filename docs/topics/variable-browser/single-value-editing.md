## 优先级

2026-11-12 所有者认可 **VB2 单值编辑**为变量浏览器下一片，确认首片字段、VB-A05 验收条件及复用 Inspector 的 U2 会话。VB1 已接通只读发现、字段定位、稳定引用和工程关注清单。用户能找到所需输入并追踪结果，修改仍需离开浏览器到 Inspector。首片将在同一工作区闭合「发现输入 → 单字段提交 → 撤销 / 重做 → 正式运行 → 查看关注项 → 保存重开」的路径。

这一步延续 P1 / P2 的基础闭环。B3-2 / AF4b 已有正式流程输入事务，U2 已有数值会话、单位转换和草稿保护，AF3 已有运行输入身份及旧完成拒绝。首片增加一个共享入口，验证这些基础能同时支撑浏览器和 Inspector。AF1 继续独立定因，I5 和平台原生验证按原阶段安排。 [路线图](../../radishflow-mvp-roadmap.md#变量与对象浏览器的配套切片) · [当前状态](../../status/current.md) · [变量浏览器专题](../variable-and-object-browser.md)

## 首片范围与界面

工程分类和变量树共用现有变量详情，在支持的输入上显示「编辑」。展开视图留在当前详情区，400 px 侧区使用既有详情页。进入编辑后显示已提交值、本次输入单位、草稿或拒绝原因，以及「应用」「取消」。返回、筛选或切换两种视图保留草稿；回到同一变量继续编辑。表格行和关注清单继续展示已提交输入及合格结果，关注清单可用现有定位入口。

| 对象和字段 | 接入边界 |
| --- | --- |
| 内建加热器 `heater` 的出口温度、出口压力 | 复用 Inspector 对缺省 / 继承、显式指定、入口压力约束和出口模板同步的处理。 |
| 由 Feed 出口提供的物料流股的温度、绝对压力、总摩尔流量 | 走已有流股规格事务。以当前连接和字段身份判断。设备生成的流股模板、所有结果及失效引用仍按只读语义呈现。 |

普通可编辑的旧工程也可使用本片。编辑以当前工作区内的 `VariableId` 和 U2 会话代次绑定；复制、粘贴稳定引用及关注清单继续遵循 VB-D02 / D03 的身份门禁。其他单元、名称、组分、设备任务、基础、来源、表格内逐格输入、批量粘贴及清单内编辑留待对应增量。工程格式、CLI 协议、单位目录、求解策略及依赖声明沿用现行契约。 [稳定引用](stable-references.md) · [工程关注清单](watch-list.md)

## 会话、提交与恢复

- 浏览器和 Inspector 对同一字段复用工作区的 `NumericEditSession`、`NumericFieldPresentation` 与 `NumericEditCommand`，共享原文、输入单位、校验、代次和文本撤销。当前编辑控件消费焦点和快捷键。开始编辑及命令执行时重验工作区、目标字段、首片适用条件和当前会话。只读工作区、退役控件和旧工作区的事件拒绝执行。删除、切工程或涉及该目标的工程历史沿用既有草稿离开保护。
- Enter 或「应用」显式提交；Tab、失焦、切对象、切视图和单位菜单均保留草稿。Escape 优先关闭弹层，再按现有数值会话规则取消编辑。输入法组字中的 Enter 只完成组字。按 U2 处理单位切换、显示变化、精度和未完成文本；保存只落已提交内容，有待提交草稿时保留现场并提示。
- 提交经 Studio 现有 `NumericEdit` 路由和正式流程输入事务。浏览器的 GUI 草稿与 Inspector 采用同一提交规则；无界面调用仍由 `write_variable` 检查 `expected_revision` 和 `PendingDrafts`。若其他正式变化使同字段基线改变，拒绝覆盖并保留原文与单位，用户可取消并从当前值重新开始。相关约束变化时按最新正式输入重验，其他无关字段变化沿用 U2 重验规则。
- 真实物理输入变化产生一次修订和一次工程历史，沿用结果旧化与在途接收资格规则。已指定且规范值相同的提交保持原修订、历史和结果资格；采用继承值为显式参数按现有正式事务处理。成功提交后刷新浏览与关注项，用户显式运行才能获得新结果。失败、取消和无变化提交不触发求解。

## VB-A05 首片验收

以 [二元烃 Feed–Heater–Flash 示例](../../../examples/flowsheets/feed-heater-flash-binary-hydrocarbon.rfproj.json) 的隔离副本为主路径。验证正式值、草稿、修订、工程历史、结果资格、运行身份与文件状态。表中结果为预期，实际证据随实施记录。

| 验收场景 | 通过条件 |
| --- | --- |
| 双入口、两类事务 | 从两个浏览目录进入同一字段；用 Inspector 与浏览器分别编辑独立副本。加热器出口温度从 `345 K` 改为 `350 K`，以 °C 显示约 `76.85 °C`，出口模板按正式事务同步；将进料总摩尔流量从 `5 mol/s` 改为 `36 kmol/h`，保存的值为 `10 mol/s`。对照正式 SI、事务作用范围与回显。压力和进料温度至少有定向覆盖。 |
| 草稿、精度与键盘 | 输入 `1e-` 后 Tab、筛选、切对象或到 Inspector，原文和输入单位保持；显示单位变化只改变呈现。验证同字段继续、文本 Undo / Redo、菜单 Escape 及显式取消，磁盘、输入修订、工程历史和运行身份保持。展开和 400 px 侧区可用键盘进入、编辑、应用及返回。 |
| 失败和权限 | 加热器入口为 `120000 Pa` 时提交出口 `1.3 bar`，按既有压力约束拒绝。验证无效或未完成文本、基线冲突、失效字段、只读工程，以及同 ID 重开后到达的旧会话事件。拒绝后正式值、模板、历史和结果资格保持，仍关联当前目标的失败草稿保留原文和原因。结果与设备生成流股模板在浏览器中无编辑入口。 |
| 历史、运行与关注 | 从 Current 结果开始，未提交草稿及无变化提交保留资格；实际提交一次修订、一次历史并旧化旧结果。无文本焦点时工程 Undo / Redo 恢复对应 SI 与模板。对旧任务注入迟到完成并确认拒收，正式重跑后关注清单按新结果更新，引用与排序保持。 |
| 保存、关闭与重开 | 草稿未提交时保存只写上次正式值并提示，取消关闭后还能继续编辑。成功应用后保存重开可读取新 SI，引用、关注顺序和 v4 能力集合保持，结果按既有重开规则为 Missing。未初始化身份的旧工程编辑和保存沿用原格式规则。 |

建议按「目标映射与事务定向测试 → 两视图 / Inspector 共用控件和失败回归 → 正式仓库检查与 macOS 代表实窗」交付。实窗至少验证非 SI 输入、400 px 键盘、错误后返回草稿、显式应用、重跑和保存重开。Windows / Linux 原生、完整 I5 以及 VB-A06 / A07 / A08 的验收沿用各自计划。
