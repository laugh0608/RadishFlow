## 用途与状态

## 值与草稿的边界

需要区分已提交 SI 值、原始草稿文本、草稿输入单位、全精度规范候选值和有效显示单位；这些是语义职责，不是冻结的数据结构。有效显示单位按 [单位集](unit-sets-and-persistence.md) 解析。字段来源、可编辑性和约束来自变量元数据与所属领域，切单位不改变规格模式。

| 草稿类别 | 判断与保留要求 |
| --- | --- |
| 未编辑 | 没有实际编辑，即使显示文本已舍入也保留原始 SI；不能重新解析显示文本制造编辑 |
| 有效 | 文本可解析、单位兼容、转换有限且通过领域约束；候选值尚未提交 |
| 未完成 | 例如正在输入的负号、指数前缀或被清空的编辑文本；保留原文 / 原输入单位，不猜缺失数字 |
| 非法 | 非法数值 / 单位、不兼容量、缺转换上下文、溢出或物理约束拒绝；保留具体原因与原文 |

可选空值、必填缺项和“清空一个已有值的草稿”不是同一状态；清除是否为正式动作由字段契约决定，不能一律转零。解析语法、小数点、本地化、粘贴单位后缀、空白归类及校验提示时机见 UD-05。未完成状态不自动等于已经提交的输入错误。

## 精度、事务与状态叠加

U1 转换不做显示舍入。当前正式事务使用既有精确同值判断；U2 未编辑文本保留原 SI，有效草稿从全精度规范候选重绘，不能反复解析舍入显示值导致漂移。实际编辑后的等价值、转换误差与历史分组见 UD-06；不得引入宽松阈值吞掉真实修改。

切换显示单位不重新求物性、不触发求解、不改变 `_k` / `_pa` 等字段含义。输入事务失败、来源修订冲突或对象失效均不得回写候选或转成成功；具体重验接口复用正式变量写入并在 UD-03 细化。

V0 叠加只消费事实，见 [状态组合](../color-state/semantics-and-composition.md)：草稿 + 焦点 + 错误可共存；纯显示切换可呈现“当前结果 / 呈现设置待保存”；未提交草稿不使旧工程值冒充本次已提交输入，也不由颜色决定能否保存 / 运行。

### 编辑会话与重验边界

UE-01—13 拥有触发与历史路由。草稿历史随编辑会话结束清理，普通文本输入按合理分组；项目显示切换不进入草稿历史，不允许控件旧缓冲跨对象或回显串用。

会话记录建议包含目标身份、开始时输入修订 / 来源、原 SI、文本是否被用户编辑、输入单位及其来源（初始显示或显式选择）、原文、可选全精度候选、解析 / 约束结果和本地历史。这里只界定职责，不冻结 Rust 类型或 DTO。来源修订改变时重验；同一字段工程值被其他命令修改后不得覆盖新值，展示冲突并让用户重新开始或显式重新采用草稿。

只读导航可跨对象保留草稿，不意味着任意写入都可保留：首版沿用非 Inspector 入口的 PendingDrafts 保护；Inspector 成功提交允许保留其他字段，重验受影响约束并标出同字段冲突。自动重验可以更新原因，不得改写用户原文 / 输入单位或静默清除尚未提交的编辑。

### 解析与精度规则

UD-05 已接受首版语法：点号小数、正负号、科学计数法、两端空白；使用界面中文不改变数值解析。无千分位或区域逗号自动猜测，无表达式求值。`-`、`+`、`.`、`1e`、`1e-`、清空中的文本作为未完成，提交时给出完成输入的提示；NaN / Inf、不兼容量、溢出、未知单位和领域约束失败为非法。空白不会创建“零”或清除已提交必填参数。

支持单个数值后带 U1 可解析单位的完整粘贴，例如 `300 K`：没有显式选过输入单位时，后缀作为本次输入单位；已显式选单位且后缀不一致时保留原文并提示冲突，要求用户统一二者。成功提交或显式切换输入单位后可规范化文本；输入过程中不重写用户原文。别名仍经 `resolve_unit` 按量解析，不扩展 U1 目录，也不开放上下文单位计算。批量粘贴和多值表达式不属于首版范围。

UD-06 已接受沿用正式事务的精确结构同值判断，不增加全局 epsilon。未编辑原值、仅切输入单位及候选重绘携带原始规范值，提交不重解析舍入显示串；用户真正改过文本则重新解析 / 换算，全精度候选始终是后续重绘来源。若实际重输的等价单位数值产生浮点微差，按真实 SI 差异处理并验收，不用容差吞掉它。

“没有数值变化”还需区分来源语义：当前单元可将未显式指定的继承 / 默认值通过应用转为显式参数。保留“采用为指定值”的正式事务，即使数字相同也不算纯显示操作；原本已指定且数值相同才应无新工程变更。具体 revision / 结果影响沿用正式事务，不由单位层覆盖。

## U2 编辑接口与接线边界

2026-09-28 项目所有者要求提交 I2 并继续下一项，按已接受 UD-03—06 实施 I3。行为仍只由 UE 表定义；下文区分已接通的领域接口与待 I4 接线，不改变对外 SI 写入协议。

### 编辑会话与解析结果

`rf-ui::NumericEditSession` 成为温度 / 压力 / 摩尔流量的唯一原文所有者，以 `DraftValue::Numeric` 存入既有 Inspector 字段索引；每个会话携带工程级 `VariableId`，事件和提交同时核对身份与代次，不以显示标签判断量。名称与组成仍使用原草稿类型，无第二份数值文本副本。

| 已实现类型 / 接口 | 职责与约束 |
| --- | --- |
| `NumericEditSession` | 字段身份、代次、基线 revision / 有效 SI / 指定性 / 继承流股身份、原文、输入单位及来源、规范候选和独立历史；普通浏览不清会话 |
| `NumericParseOutcome` / `NumericParseError` | 分开未完成、非法与全精度 SI 候选；后缀使用 U1 `resolve_unit`，无表达式 / 逗号猜测，未完成文本不能回退到前一次候选 |
| `InputUnitOrigin` / `NumericPrecisionSource` | 区分显示初始化、显式输入单位、后缀，以及原始 SI 直通 / 实际文本解析；纯单位换算的重绘不反向解析 |
| `NumericEditEvent` | ReplaceText、SelectInputUnit、Undo、Redo、Rebase、AdoptValue；每个事件为原子历史步骤，失败切换不改文本、单位、代次或历史 |
| `begin_numeric_edit` / `edit_numeric` / `commit_numeric_edit` / `cancel_numeric_edit` | 采用会话代次，拒绝延迟事件覆盖重开的会话；Rebase 是显式保留候选后按当前领域重新校验，取消后重新开始则取最新值 |
| `InspectorDraftState::pending_count()` | 名称 / 组成按原范围计数，数值仅计实际编辑或输入单位选择；仅获焦初始化不是待提交输入。工程保存摘要统一消费 |

纯解析 / 转换与会话事件分离；领域校验通过既有 `prepare_input_document_command` 与提交事务复用，不复制温压约束。不在文件中持久化会话、本地历史、光标或输入单位。

现有 SI 控件已迁入会话，但仍显式使用其标示的规范单位；不同单位后缀报冲突并保留原文，不能在 I4 本地历史路由前隐式改变标签解释。完整的新控件以 `begin_numeric_edit(..., None)` 采用项目显示单位，可使用后缀推断与切输入单位。非 SI 场景本轮在领域接口验证，不宣称原生菜单已接通。

### 提交与重验事务

I3 前 [共享输入事务](../../../crates/rf-ui/src/state/input_commands.rs) 已复用工程命令；[变量写入](../../../crates/rf-ui/src/variable_commands.rs) 对非 Inspector 请求保留 `PendingDrafts`。旧单元草稿重验会重建数字草稿；I3 已移除该路径。数值提交后按当前领域重验其他会话，保留其原文、单位和历史；通用工程变更保留数值会话并暴露冲突，不能只套在 TextEdit 外层。

已接通 Inspector 专用 `commit_numeric_edit(variable, session_generation, changed_at)` 入口，内部顺序如下：

1. 检查工程 / 对象 / 字段仍存在且可编辑、会话代次仍匹配；从当前领域读取正式字段语义。对照会话基线：同字段值、显式性或依赖的继承值变化即标冲突，保留编辑；不能用新 revision 自动覆盖旧值。
2. 仅其他字段改变时，保留原文 / 单位，按当前 revision 重验约束；通过后允许基线重定位。领域约束变化即使本字段数值未变也必须重新校验。冲突的“基于最新值重新编辑”与“保留候选重新应用”都须显式选择，后者也重新校验，不提供强写绕过。
3. 从当前解析状态取得有限 SI 候选，交给既有共享输入命令；复用变量到命令的内部映射和校验，不调用一个会拒绝自身草稿的公共写入入口，也不取消该公共入口的保护。
4. 正式事务成功（含确认为无变化）才结束本字段会话；有变化时仍由现有事务推进 revision / 历史 / 结果失效。其他会话只更新校验和冲突事实，保留原文、单位与本地历史；失败不清除任何编辑。

会话基线重定位不代表用户重新编辑；本地 Undo 恢复旧文本后必须在当前领域状态下再验，不能恢复历史中的“有效”标记冒充当前有效。作用域内精确相等仍采用正式结构比较；继承值变指定值交正式命令判定。非 Inspector 的 `VariableWriteRequest` 保持 SI、expected_revision 和 PendingDrafts 语义，不增加悄悄丢草稿的选项。

### 三类历史与离开保护接线

数值领域事件已进入同一会话历史，原生数值编辑器的事件路由仍待 I4。每个历史快照保存 raw text、输入单位、选择来源以及规范值的精度来源；不保存可直接复用的领域校验结果。单位换算、整段粘贴分别为原子步骤；连续普通键入按光标相邻的插入 / 删除合并，选区替换、焦点离开、菜单动作、输入法完成提交与显式命令结束分组。输入法组合串不进入正式工程事务，组合未结束时拒绝提交 / 切单位并保留现场；不能把 Enter 同时用于结束组合与提交字段。该原生接线须测试。

快捷键路由建议在现有 text focus 前识别“数值会话拥有焦点”：Undo / Redo 只消费该会话一次，不同时调用 egui 文本撤销和工程历史；普通名称等文本保持既有控件历史，无文本焦点才走工程命令。单位菜单关联原字段会话，Escape 先关闭弹出层；键位沿用现有平台 Primary 注册，不另造快捷键。呈现历史通过设置区独立入口消费；其作用域与保存比较归 [呈现状态提案](unit-sets-and-persistence.md#呈现状态与保存事务)。

对于会清草稿的删除、工程 Undo / Redo、切工程 / 关闭及其他写入，推荐共用操作前检查，返回受影响变量列表和工作区 revision / 草稿代次。确认后执行前再次校验上下文；期间若变化则重新提示。首版可保守要求处理该工程全部待提交草稿，不推测不存在的字段依赖图。明确“返回编辑 / 放弃受影响编辑后继续”，不增加隐式批量提交。

放弃意图不应先清空再执行：先准备并校验目标操作，成功时一并清理同意放弃的会话；取消、目标工程读入失败、删除拒绝、无可撤销项或保存失败均保留原工作区草稿。底层不能借 `drafts.clear()` 绕过检查。关闭 / 切工程分别处理未应用设置、字段会话与已提交内容的保存状态；普通保存本身仍不要求放弃草稿。

### 接口提案的验证补充

沿用 UA-08—12：双对象草稿提交一个后另一项原文 / 单位不变；另一个字段成功写入后重验约束，同字段语义变更明确冲突；返回编辑和失败操作不丢草稿；重复确认旧代次被拒绝。UA-11 增加输入法 Enter、Undo 跨粘贴 / 单位切换、失焦返回后本地历史、原生文本 Undo 不重复执行；UA-12 用独立高精度数值与继承同值采用覆盖精度来源。本轮完成其中领域与事务用例；输入法、原生快捷键、连续键入分组和视图覆盖仍待 I4 / I5。
