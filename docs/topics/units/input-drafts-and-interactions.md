## 值与草稿的边界

需要区分已提交 SI 值、原始草稿文本、草稿输入单位、全精度规范候选值和有效显示单位；这些是语义职责，不是冻结的数据结构。有效显示单位按 [单位集](unit-sets-and-persistence.md) 解析。字段来源、可编辑性和约束来自变量元数据与所属领域，切单位不改变规格模式。

| 草稿类别 | 判断与保留要求 |
| --- | --- |
| 未编辑 | 没有实际编辑，即使显示文本已舍入也保留原始 SI；不能重新解析显示文本制造编辑 |
| 有效 | 文本可解析、单位兼容、转换有限且通过领域约束；候选值尚未提交 |
| 未完成 | 例如正在输入的负号、指数前缀或被清空的编辑文本；保留原文 / 原输入单位，不猜缺失数字 |
| 非法 | 非法数值 / 单位、不兼容量、缺转换上下文、溢出或物理约束拒绝；保留具体原因与原文 |

可选空值、必填缺项和“清空一个已有值的草稿”不是同一状态；清除是否为正式动作由字段契约决定，不能一律转零。解析语法、小数点、本地化、粘贴单位后缀、空白归类及校验提示时机见 UD-05。未完成状态不自动等于已经提交的输入错误。

| UE-03 更换输入单位 | 非法 / 未完成草稿 | 拒绝会重新解释原文的切换，保留原文、原输入单位及原因；允许先修正或显式取消再选择 | 不产生物理历史；清空文本的具体分类见 UD-05 |

| UE-07 切换显示单位 | 非法 / 未完成草稿 | 原文与原输入单位无损；阻止任何重新解释该文本的字段切换，提示先修正 / 取消 | UD-03 已接受：项目 / 视图选择正常应用，其他无草稿字段重绘；当前草稿保留并标明输入与目标显示单位，不因单字段非法暂缓全项目选择 |

## 精度、事务与状态叠加

U1 转换不做显示舍入。当前正式事务使用既有精确同值判断；U2 未编辑文本保留原 SI，有效草稿从全精度规范候选重绘，不能反复解析舍入显示值导致漂移。实际编辑后的等价值、转换误差与历史分组见 UD-06；不得引入宽松阈值吞掉真实修改。

切换显示单位不重新求物性、不触发求解、不改变 `_k` / `_pa` 等字段含义。输入事务失败、来源修订冲突或对象失效均不得回写候选或转成成功；具体重验接口复用正式变量写入并在 UD-03 细化。

V0 叠加只消费事实，见 [状态组合](../color-state/semantics-and-composition.md)：草稿 + 焦点 + 错误可共存；纯显示切换可呈现“当前结果 / 呈现设置待保存”；未提交草稿不使旧工程值冒充本次已提交输入，也不由颜色决定能否保存 / 运行。

### 编辑会话与重验边界

UE-01—13 拥有触发与历史路由。草稿历史随编辑会话结束清理，普通文本输入按合理分组；项目显示切换不进入草稿历史，不允许控件旧缓冲跨对象或回显串用。

会话记录建议包含目标身份、开始时输入修订 / 来源、原 SI、文本是否被用户编辑、输入单位及其来源（初始显示或显式选择）、原文、可选全精度候选、解析 / 约束结果和本地历史。这里只界定职责，不冻结 Rust 类型或 DTO。来源修订改变时重验；同一字段工程值被其他命令修改后不得覆盖新值，展示冲突并让用户重新开始或显式重新采用草稿。

只读导航可跨对象保留草稿，不意味着任意写入都可保留：首版沿用非 Inspector 入口的 PendingDrafts 保护；Inspector 成功提交允许保留其他字段，重验受影响约束并标出同字段冲突。自动重验可以更新原因，不得改写用户原文 / 输入单位或静默清除尚未提交的编辑。

### 解析与精度规则

UD-05 已接受首版语法：点号小数、正负号、科学计数法、两端空白；使用界面中文不改变数值解析。无千分位或区域逗号自动猜测，无表达式求值。`-`、`+`、`.`、`1e`、`1e-`、清空中的文本作为未完成，提交时给出完成输入的提示；NaN / Inf、不兼容量、溢出、未知单位和领域约束失败为非法。空白不会创建“零”或清除已提交必填参数。

支持单个数值后带 U1 可解析单位的完整粘贴，例如 `300 K`：没有显式选过输入单位时，后缀作为本次输入单位；已显式选单位且后缀不一致时保留原文并提示冲突，要求用户统一二者。成功提交或显式切换输入单位后可规范化文本；输入过程中不重写用户原文。别名仍经 `resolve_unit` 按量解析，不扩展 U1 目录，也不开放上下文单位计算。批量粘贴和多值表达式不属于首版范围。

UD-06 已接受沿用正式事务的精确结构同值判断，不增加全局 epsilon。未编辑原值、仅切输入单位及候选重绘携带原始规范值，提交不重解析舍入显示串；用户真正改过文本则重新解析 / 换算，全精度候选始终是后续重绘来源。若实际重输的等价单位数值产生浮点微差，按真实 SI 差异处理并验收，不用容差吞掉它。

“没有数值变化”还需区分来源语义：当前单元可将未显式指定的继承 / 默认值通过应用转为显式参数。保留“采用为指定值”的正式事务，即使数字相同也不算纯显示操作；原本已指定且数值相同才应无新工程变更。具体 revision / 结果影响沿用正式事务，不由单位层覆盖。
