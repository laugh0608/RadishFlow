# 输入草稿与单位交互

更新时间：2026-09-23

## 用途与状态

用途：维护 U2 输入单位选择、显示单位切换及提交、取消、撤销、保存的事件契约。
读者：字段控件、输入事务、单位集、交互设计与验证维护者。
不包含：已冻结的控件 API、键盘绑定、持久化 schema 或已交付交互声明。

父专题：[单位系统](../units-and-quantity-system.md)。状态：Draft / U2 待实现；下表区分已确认约束和待决策策略，不将候选交互当现有行为。

## 值与草稿的边界

需要区分已提交 SI 值、原始草稿文本、草稿输入单位、全精度规范候选值和有效显示单位；这些是语义职责，不是冻结的数据结构。有效显示单位按 [单位集](unit-sets-and-persistence.md) 解析。字段来源、可编辑性和约束来自变量元数据与所属领域，切单位不改变规格模式。

| 草稿类别 | 判断与保留要求 |
| --- | --- |
| 未编辑 | 没有实际编辑，即使显示文本已舍入也保留原始 SI；不能重新解析显示文本制造编辑 |
| 有效 | 文本可解析、单位兼容、转换有限且通过领域约束；候选值尚未提交 |
| 未完成 | 例如正在输入的负号、指数前缀或被清空的编辑文本；保留原文 / 原输入单位，不猜缺失数字 |
| 非法 | 非法数值 / 单位、不兼容量、缺转换上下文、溢出或物理约束拒绝；保留具体原因与原文 |

可选空值、必填缺项和“清空一个已有值的草稿”不是同一状态；清除是否为正式动作由字段契约决定，不能一律转零。解析语法、小数点、本地化、粘贴单位后缀、空白归类及校验提示时机见 UD-05。未完成状态不自动等于已经提交的输入错误。

## U2 事件表

下表描述用户语义事件；菜单打开、失焦和快捷键如何映射事件仍须局部设计审定。所有未提交操作都不得推进求解输入修订；只有正式物理输入事务的实际变化按现有规则影响结果。各行需同时观察文本、输入单位、显示单位、SI、历史、保存脏标记与快照身份。

| 事件 | 前置 / 草稿状态 | 必须保留的行为 | 修订、历史与待决策 |
| --- | --- | --- | --- |
| UE-01 开始输入 / 选择本次输入单位 | 无值且无待解释文本，或新建草稿 | 可先选择兼容单位再输入；初始单位取当前有效显示选择；不把空值变成零 | 仅草稿变化；首批菜单范围 UD-01 |
| UE-02 更换输入单位 | 有效草稿，或未编辑的已有值 | 按同一全精度规范值换算到新输入单位，同时更新文本与输入单位；不是只换标签。例如 `300 K` 换为 °C 得 `26.85` | 不提交、不改项目显示单位；从未编辑值进入时保留原 SI |
| UE-03 更换输入单位 | 非法 / 未完成草稿 | 拒绝会重新解释原文的切换，保留原文、原输入单位及原因；允许先修正或显式取消再选择 | 不产生物理历史；清空文本的具体分类见 UD-05 |
| UE-04 更换输入单位 | 目标不兼容、未知或当前缺上下文 | 选择或转换失败时原草稿及原单位完整保留，不部分更新标签；不猜参考条件 | 沿用共享转换错误；不把“识别单位”当可用选项 |
| UE-05 切换显示单位 | 未编辑 / 无草稿，包括只读结果 | 从已提交 SI 或合格快照重绘；空值保持空值，来源和只读性不变 | 项目偏好产生独立保存需求；视图覆盖按其范围管理；不改输入历史或快照 |
| UE-06 切换显示单位 | 有效草稿 | 草稿仍指向同一候选物理量，不隐式提交；显示选择不能直接重标原草稿文本 | 编辑器继续用输入单位，还是以候选值重绘并同步输入单位，由 UD-03 审定；两者都需明确标签 |
| UE-07 切换显示单位 | 非法 / 未完成草稿 | 原文与原输入单位无损；阻止任何重新解释该文本的字段切换，提示先修正 / 取消 | 项目级切换整体暂缓还是保留编辑器原单位后更新其他视图，由 UD-03 审定；不默选策略或留下半更新配置 |
| UE-08 提交 | 有效草稿 | 以输入单位转换、校验，再走正式输入事务；成功才清草稿并回到当前显示单位；失败保留草稿、单位与具体原因 | 实际物理变化按既有事务影响历史 / 修订；同值和舍入边界见下节 |
| UE-09 提交 | 非法 / 未完成草稿 | 拒绝提交；不写默认值、零值或最后一次候选值替代用户当前文本 | SI、输入历史与快照均不变；提示可定位 |
| UE-10 取消编辑 | 任意草稿 | 丢弃本次草稿及临时输入单位，按最新已提交值和当前有效显示单位回显；缺项仍缺项 | 不撤销先前已成功的物理事务，也不顺带撤销项目单位偏好 |
| UE-11 Undo / Redo | 草稿、已提交输入或呈现偏好 | 草稿撤销必须恢复文本与输入单位的对应关系；正式输入撤销经原事务恢复 SI；显示偏好撤销不产生物理修订 | 焦点内文本历史、工程历史及偏好历史的路由与分组由 UD-04 审定；有草稿时不得静默跨历史丢失编辑 |
| UE-12 保存 / 重开 | 无草稿或任意草稿；偏好可能待保存 | 磁盘工程数值为已提交 SI；保存偏好不使快照 stale。草稿存在时不隐式提交、不谎称草稿已保存；失败保留待保存状态 | 先处理草稿还是只保存已提交内容见 UD-03；草稿是否恢复、配置兼容见 UD-02；安全保存归生命周期专题 |
| UE-13 失焦 / 切对象 / 单位菜单开关 | 任意草稿 | 不因标签切换、诊断定位或焦点变化静默舍弃 / 重解释文本；若映射提交或取消，必须遵循对应行的失败保护 | 具体触发、跨对象草稿保留与提示策略见 UD-03，不假定失焦必提交 |

## 精度、事务与状态叠加

U1 转换不做显示舍入。当前正式事务使用既有精确同值判断；U2 未编辑文本保留原 SI，有效草稿从全精度规范候选重绘，不能反复解析舍入显示值导致漂移。实际编辑后的等价值、转换误差与历史分组见 UD-06；不得引入宽松阈值吞掉真实修改。

切换显示单位不重新求物性、不触发求解、不改变 `_k` / `_pa` 等字段含义。输入事务失败、来源修订冲突或对象失效均不得回写候选或转成成功；具体重验接口复用正式变量写入并在 UD-03 细化。

V0 叠加只消费事实，见 [状态组合](../color-state/semantics-and-composition.md)：草稿 + 焦点 + 错误可共存；纯显示切换可呈现“当前结果 / 呈现设置待保存”；未提交草稿不使旧工程值冒充本次已提交输入，也不由颜色决定能否保存 / 运行。

### 推荐的事件选择

| 决策 / 事件 | 推荐方案 | 取舍及替代 |
| --- | --- | --- |
| UD-03；UE-06—07 显示切换 | 项目 / 视图显示选择可以更新；已有编辑会话始终保留原输入单位和文本，有效与非法草稿同样处理。其他无草稿字段重绘，编辑器注明“本次输入 K · 提交后显示 °C” | 无需因一个非法草稿阻塞全项目显示选择。替代是有草稿时暂缓整次切换，操作简单但影响其他字段；不采用只重标当前文本 |
| UD-03；UE-08—10、13 提交 / 取消 / 焦点 | Enter / 应用显式提交，普通失焦、Tab、开关单位菜单不提交；Escape 或“取消编辑”取消当前字段。弹出菜单打开时 Escape 先关闭菜单，再次才取消字段 | 保持现有显式提交习惯；失焦自动提交会让菜单、定位和保存引入隐含事务，不推荐 |
| UD-03；UE-13 切对象 | 同一工程内只读定位保留按稳定变量身份归属的草稿；回到对象可继续编辑，有工程级未提交数量 / 定位入口 | 删除对象、工程 Undo / Redo、切工程 / 关闭及其他会丢草稿的写入先要求处理受影响草稿；取消动作保留现场。不隐式批量提交，不默认设计跨工程草稿恢复 |
| UD-03；UE-12 保存 | 普通保存只写已提交 SI 和已应用的呈现配置，保留会话草稿；明确反馈“已保存已提交内容，仍有 N 项未提交输入”。关闭 / 切工程时单独处理草稿，不能用“工程已保存”自动放行 | 保留现有保存语义并消除误导；替代为草稿存在即阻止保存，会妨碍先保存其他已完成工作 |
| UD-04；UE-11 草稿 Undo / Redo | 文本焦点内以字段编辑会话为边界；文本与输入单位一同回退，单位转换为一个原子历史步骤；一轮普通输入仍按合理文本编辑分组 | 项目单位切换不进入草稿历史；会话结束清本地历史，不让控件旧缓冲跨对象或回显串用 |
| UD-04；UE-11 工程 / 呈现历史 | 无文本焦点时全局 Undo / Redo 只走工程历史，有待丢失草稿先提示处理；单位设置使用独立的“撤销显示设置 / 重做显示设置”入口，设置对话框未应用编辑可取消 | 不把偏好压进物理命令，也不按最近一次任意操作猜快捷键目标；独立呈现历史只保留当前项目会话，不持久化历史栈 |

会话记录建议包含目标身份、开始时输入修订 / 来源、原 SI、文本是否被用户编辑、输入单位及其来源（初始显示或显式选择）、原文、可选全精度候选、解析 / 约束结果和本地历史。这里只界定职责，不冻结 Rust 类型或 DTO。来源修订改变时重验；同一字段工程值被其他命令修改后不得覆盖新值，展示冲突并让用户重新开始或显式重新采用草稿。

只读导航可跨对象保留草稿，不意味着任意写入都可保留：首版建议沿用非 Inspector 入口的 PendingDrafts 保护；Inspector 成功提交允许保留其他字段，重验受影响约束并标出同字段冲突。自动重验可以更新原因，不得改写用户原文 / 输入单位或静默清除尚未提交的编辑。

### 解析与精度候选

UD-05 推荐首版接受点号小数、正负号、科学计数法、两端空白；使用界面中文不改变数值解析。无千分位或区域逗号自动猜测，无表达式求值。`-`、`+`、`.`、`1e`、`1e-`、清空中的文本作为未完成，提交时给出完成输入的提示；NaN / Inf、不兼容量、溢出、未知单位和领域约束失败为非法。空白不会创建“零”或清除已提交必填参数。

建议支持单个数值后带 U1 可解析单位的完整粘贴，例如 `300 K`：没有显式选过输入单位时，后缀作为本次输入单位；已显式选单位且后缀不一致时保留原文并提示冲突，要求用户统一二者。成功提交或显式切换输入单位后可规范化文本；输入过程中不重写用户原文。别名仍经 `resolve_unit` 按量解析，不扩展 U1 目录，也不开放上下文单位计算。批量粘贴和多值表达式不属于此候选。

UD-06 推荐沿用正式事务的精确结构同值判断，不增加全局 epsilon。未编辑原值、仅切输入单位及候选重绘携带原始规范值，提交不重解析舍入显示串；用户真正改过文本则重新解析 / 换算，全精度候选始终是后续重绘来源。若实际重输的等价单位数值产生浮点微差，按真实 SI 差异处理并验收，不用容差吞掉它。

“没有数值变化”还需区分来源语义：当前单元可将未显式指定的继承 / 默认值通过应用转为显式参数。推荐保留“采用为指定值”的正式事务，即使数字相同也不算纯显示操作；原本已指定且数值相同才应无新工程变更。具体 revision / 结果影响沿用正式事务，不由单位层覆盖。

不新增重复编号，下列是既有场景在候选方案下的细化，批准后再作为产品预期。

| 场景 | 追加步骤与判断 |
| --- | --- |
| UA-08 / UA-09 | `1e-` 草稿保留 K，项目改 °C；另一无草稿字段立即重绘，当前草稿不变且显示两个单位的作用范围；修改项目选择不代表部分应用失败 |
