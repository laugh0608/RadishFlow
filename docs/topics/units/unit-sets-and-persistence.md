读者：单位、变量元数据、Studio、存储与测试维护者。

## 显示偏好所有权与兼容设计（U2 待实现）

U1 确定以下边界，具体 DTO 和版本迁移在 U2 审定 / 实现；当前不新增持久化字段或空状态模块。

| 状态 | 所有者与持久化方向 | 生效规则 |
| --- | --- | --- |
| 项目显示单位集 | 项目呈现配置；拟与 document 并列随工程文件保存，独立于 flowsheet 输入及求解修订 | 保存量 ID → 单位 ID 和格式选择，不保存转换系数；不是机器专属布局 sidecar |
| 个人默认 | 应用偏好 | 仅初始化新工程的项目显示配置；不覆盖已打开工程，也不让旧工程随机器偏好漂移 |
| 临时输入单位 | 字段草稿 | 与原始文本一起保留到提交 / 取消，不改变项目显示单位；提交转换为 SI 后回到有效显示单位 |
| 临时显示覆盖 | 当前视图的显式呈现状态 | 仅在用户明确选择时覆盖该视图的项目默认；不进入求解输入，首版不承诺逐字段持久化 |
| 输出单位选择 | 输出任务配置 | 显式选择优先，否则捕获本次项目单位集；模板不自行定义系数，完整报告配置以后落地 |

有效显示为“明确的视图覆盖，否则项目单位集”；不叠加个人偏好作隐藏 fallback。旧工程没有呈现配置时按完整 SI 集解释，显式选用其他集后再保存；未知单位 ID / 不兼容量要提示并保留原信息，不能静默替换成 SI。具体旧版本读取和往返策略在 U2 格式变更前验证。

显示偏好变更有独立的保存脏标记，复用项目安全保存流程，不调用物理输入命令、不增加计算修订、不使快照过期。定义中的系数属于代码版本；工程只引用稳定身份，后续定义变化需兼容策略，不允许同名单位悄悄改变含义。

## 单位集解析与编辑边界

单位集引用目录中稳定量 / 单位身份；名称和本地化符号不能作为键。一个有效项目单位集必须为适用量给出可解释的显示选择；首版完整选择、内置集与逐量配置按下方已接受的 UD-01 范围执行，扩展格式选项后续审定。可解析和可支持是不同条件，需上下文但当前不支持的单位不得列成可用转换选项。

改变个人默认不批量改写现有工程。项目默认和视图覆盖需要明确作用范围与恢复入口；覆盖的生命周期、持久化以及输出是否显式继承某视图不能从界面位置猜测，分别见 UD-01、UD-07。项目单位集变更不修改来源标签、计算模式或快照身份。

## 保存、失败与撤销

呈现偏好可以独立要求保存，但不进入物理输入历史。安全写入、替换失败和工程关闭的共用流程归 [项目生命周期](../project-lifecycle-storage.md)；本文只拥有单位配置的保存语义。

- 保存成功后才能按实际写入内容更新保存基线；失败时保留待保存偏好和可重试路径，不因失败使求解结果 stale。
- 有字段草稿时执行保存不能静默提交、丢弃草稿或写入显示数字替代 SI；事件约束见 [UE-12](input-drafts-and-interactions.md#u2-事件表)。保存只写已提交内容并提示会话草稿；草稿不随工程恢复，关闭 / 切工程须另行保护。
- 撤销物理输入走正式历史；呈现偏好采用独立会话历史，路由见 UD-04 / UE-11，不能为了支持 Undo 而伪造物理输入变化。
- 旧工程无配置采用完整 SI 集；未知 / 不兼容配置按 UD-02 拒绝此次装载并保留原文件与当前工作区；新旧读取器验证及具体 DTO 仍须在文件格式实施前补齐。不能仅通过打开时回退 SI 掩盖数据丢失。

验收为 [UNIT-05—07 / UA-05—07](requirements-traceability.md)，未实施的兼容路径保持待验证。

### 首版单位集与适用范围

单位集配置可覆盖完整目录，消费者接入分批进行。U2 设置页需要明确首批生效范围；其他尚未接入消费者仍使用自身明确的 SI 标签，不能把 U3 提前宣称为已完成。视图覆盖如何被 U3 输出显式采用留在 UD-07。

### 保存基线与格式边界

静态核对发现：[项目 DTO](../../../crates/rf-store/src/project.rs) 当前外层版本为 1，只有 kind、schema_version 和 document；内层 metadata 校验也共用这个版本常量。[加载 / 保存驱动](../../../apps/radishflow-studio/src/document_lifecycle_driver.rs) 只装载 / 组装 document，保存成功后记录工程 revision；[WorkspaceState](../../../crates/rf-ui/src/state.rs) 尚无独立呈现保存基线。只改写盘函数不足以保存 / 恢复单位集，应用加载与保存状态投影也必须接入。

将当前呈现配置与最近成功保存的呈现配置作为独立状态比较，工程的既有 revision 脏判断保持。项目总体待保存为两者任一变化；草稿数量另外显示，不混入“已经保存的内容”。单位设置应用、撤销和恢复为已保存选择均不推进求解修订；写盘成功才同时更新对应保存基线，失败不清脏、不改快照资格，原数据保护与恢复证据沿用安全保存契约。另存为复用安全写入，成功才改变路径与基线。

格式采用新外层项目版本（实际版本值待 DTO 评审，原候选为 v2）保存与 document 并列的呈现块；块中保存稳定量 / 单位 ID 的完整选择，不保存系数、临时输入单位、视图覆盖、草稿或历史栈。缺失配置只在明确旧版本迁移时补完整 SI；新格式缺项、重复键、不兼容组合或未知 ID 不能静默补值。具体字段、格式选项如何演进、外层和 metadata 版本常量如何分离仍须 DTO 评审，不能把所有内层数据机械升级或更改工程数值语义。

升级外层版本的依据是：[JSON 版本分派](../../../crates/rf-store/src/json.rs) 当前会拒绝较新外层版本，但同版本数据会进入现有强类型反序列化。按当前 DTO 的静态结构推断，在旧版本信封中加可选单位字段不能保证旧程序重存时保留它；未做旧二进制实测，不能宣称向后无损。

| 文件路径 | 已接受处理与可观察结果 | 必须补的证据 |
| --- | --- | --- |
| 读取现有 v1 | 在内存补完整 SI，不因打开而产生呈现脏标记，不自动写回磁盘 | SI 数值、工程身份与原文件不变；旧工程不受个人默认影响 |
| 通过新版保存 | 新写入采用新版本；从 v1 首次保存前说明格式升级及旧版不可读，允许另存为保留原件 | 明确升级提示、取消不写盘；安全保存失败保留原数据 / 恢复证据及可重试状态 |
| 旧程序读取新版 | 利用版本门禁明确拒绝，不让旧程序读入后丢掉单位配置再保存 | 用旧读取器 / 固定 fixture 验证拒绝，不能只跑新版本自读 |
| 未知单位 / 新格式缺项 / 不兼容量 | 首版拒绝此次项目装载，提示量 / 单位身份，保留原文件与当前工作区；不自动改 SI 或部分装载 | 无原地重写；不能在“保留原信息”名义下把未知数据存成已知配置 |
| 可保留未知配置的只读打开 | 未选入首版；后续若扩展，需要独立的原始数据保留、只读状态与另存兼容设计 | 后续另行批准并补读取 / 往返 / 编辑禁用验收后再实施 |

新版文件的旧程序不可读这一兼容影响已获批准；本轮设计工作不升级任何用户工程。应用默认偏好另按 [现有偏好 DTO](../../../crates/rf-store/src/studio_preferences.rs) 评审版本与旧值保留，不因项目版本变化顺带重置最近项目记录。

### 保存验收细化

- UA-05：七类量配置完整、两个预设可解释；修改项目选择不改变个人默认；个人默认只影响新建；Inspector 覆盖跨对象保持、结束视图后跟随项目。
- UA-06：呈现 A→B→撤销回 A 后与保存基线一致；工程 revision / 快照全程不变。工程和呈现同时有变更时保存成功更新两者基线，有草稿仍显示未提交数量；注入写盘失败后两者均保持待保存。
- UA-07：旧 v1 打开不写盘、首次新版保存说明升级；新格式未知 ID / 缺项 / 较新版本拒绝且原件未变；旧读取器拒绝新版本。该预期已接受，实际兼容与安全保存仍待产品验证。

## U2 存储接口提案（待审定）

### 类型与版本分派

| 边界 | 推荐接口与职责 | 约束 / 验收 |
| --- | --- | --- |
| 共享单位选择 | 在 `rf-types::units` 增加经构造校验的 `DisplayUnitSet`；按现有量类型查单位，提供 SI / 工程预设和逐量替换 | 完整覆盖 U1 七类量，只接受已有且可转换的单位；不引入 serde、控件类型或新 crate；UA-05 |
| 存储 DTO | `rf-store` 定义 `StoredProjectPresentation`，项目外层新增 `presentation.displayUnits`；建议为 `{ quantityId, unitId }` 条目数组 | 使用目录稳定 ID，完整七项；读入检查缺项、重复量、未知 ID 和不兼容，写出固定量顺序；不保存系数 / 预设名 / 格式占位字段；UA-07 |
| 版本 | 建议项目外层版本升为 2，文档 metadata 仍为 1；拆成各自版本常量 | metadata 的语义和 SI 数据未变，不机械随外层升级；旧读取器拒绝外层 2；UA-07 |
| 读取分派 | 明确 `v1 -> 内存完整 SI` 与 `v2 -> 严格完整配置` 两支；较新版本拒绝 | 当前 `migrate_project_file_value` 不能仅改常量：原分派会把“当前版本”送入 v1 迁移函数，遗漏旧版；各版本独立 fixture 验证 |
| 应用桥接 | Studio 在 `rf-store` DTO 与 `rf-ui` 呈现状态间转换；装载同时保留原外层版本供升级提示 | 不给 `rf-ui` 增加正常 `rf-store` 依赖；读取来源版本属于装载上下文，不写入 flowsheet / metadata；UA-06 / 07 |

数组保留“重复量条目”供校验，但不能解决 JSON 对象重名键。现有解析先转 `serde_json::Value`，重名属性可能已经被覆盖；提案要求在原始 JSON 到 Value 之前检测重名键，至少覆盖项目信封及呈现块（含每个条目），再执行版本分派。新格式未知呈现属性也明确拒绝，避免无声丢失未来设置；不顺带重写布局、认证缓存等其他解析器。报错携带配置位置与量 / 单位身份，读取失败不替换当前工作区。

### 呈现状态与保存事务

推荐 `rf-ui` 工作区持有 `ProjectPresentationState { current, saved, history }`，视图按自身身份另持临时覆盖，设置弹层持未应用选择。`saved` 是最近成功写入的完整配置；读取 v1 后以 SI 同时初始化 current / saved，新工程仍沿用既有“尚未保存”的工程判断。呈现历史只记录已应用的项目选择与视图覆盖，条目注明作用域；个人默认写盘不进入该历史。视图关闭后清理所属覆盖及对应历史，不能撤销到已不存在的视图。项目和视图操作分别比较自身状态，无变化不记历史。

建议统一查询 `ProjectSaveState { document_dirty, presentation_dirty, pending_input_count }`，供标题、关闭提示、保存回执使用；第三项由草稿领域提供，不进入前两项的脏判断。现有 `DocumentLifecycleOutcome.has_unsaved_changes` 及所有调用方改为消费总体保存状态，不能仅改标题而让关闭路径仍只检查 revision。

保存顺序提案：获取当前已提交文档和已应用呈现快照 → 必要时取得旧格式升级选择 → 安全写入 → 成功后按实际写入的 revision / 配置更新路径、来源版本和两项基线。取消升级或写入失败不更新任何基线、不动草稿。当前同步写入不引入异步框架；将来异步时也必须以捕获快照而非回调时的“最新配置”标记已保存。另存为复用同一路径；底层替换 / 回滚失败的恢复行为仍归生命周期专题。

### 个人默认的兼容取舍

进一步核对 [偏好读写](../../../apps/radishflow-studio/src/studio_gui_preferences_store.rs) 和 [启动装载](../../../apps/radishflow-studio/src/studio_gui_shell/mod.rs)：旧版读取失败会退到空最近项目列表，之后 [最近项目写入](../../../apps/radishflow-studio/src/studio_gui_shell/app.rs) 会重新构造偏好文件。因此在原偏好文件加字段或升版本，均不足以保证旧程序运行后保留单位默认；不能把项目的“拒读保护”直接套到应用偏好。

**推荐待审定方案：**个人单位默认仍属于应用偏好，但单独保存到现有偏好路径同目录的 `unit-defaults.rfstudio-preferences.json`；使用独立 kind（建议 `radishflow.studio-unit-defaults`）、版本 1 和同一完整 displayUnits DTO。既有最近项目文件及其版本保持；新文件路径从已解析的偏好路径派生，包含环境变量覆盖的目录，不另建隐蔽存储根。该拆分避免旧版最近项目写入覆盖单位默认，代价是增加一个应用偏好文件。

- 文件不存在时新工程用 SI；新程序不会只因启动而创建默认文件。显式“设为新工程默认”以当前已应用项目选择为源，成功才更新内存默认；失败保留此前默认和项目选择，并报告可重试错误。
- 文件损坏、未知 ID / 版本时保留原件并提示，禁止自动覆盖；用户仍可显式选择以 SI 或本次有效单位集新建，不能声称成功读取个人默认。替换损坏默认需要明确恢复操作，其界面和确认文案在实施该切片前复核。
- 最近项目更新与单位默认保存互不重写对方文件；不承诺两文件原子事务，也无此业务需求。独立文件的路径、kind 和失败恢复策略属于本次新增 UD-02 决策，尚未获批准。

### 接口提案的验证补充

沿用 UA 编号追加产品用例：UA-05 覆盖个人默认写入失败、损坏文件保护及环境路径隔离；UA-06 覆盖仅呈现变化的关闭提示、回执和失败基线；UA-07 覆盖 v1 / v2 显式分派、metadata 仍为 1、原始 JSON 重名属性、重复量条目及旧读取器拒读。旧读取器须来自固定旧实现或可复现旧二进制，不能用新读取器模拟通过；另核对旧程序最近项目写入不触碰独立默认文件。新增产品测试均尚未执行。
