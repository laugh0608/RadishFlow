有效显示为“明确的视图覆盖，否则项目单位集”；不叠加个人偏好作隐藏 fallback。旧工程没有呈现配置时按完整 SI 集解释，显式选用其他集后再保存；未知单位 ID / 不兼容量要提示并保留原信息，不能静默替换成 SI。I1 文件读取和往返已验证，I2 已接入显式升级确认。

显示偏好变更有独立的保存脏标记，复用项目安全保存流程，不调用物理输入命令、不增加计算修订、不使快照过期。定义中的系数属于代码版本；工程只引用稳定身份，后续定义变化需兼容策略，不允许同名单位悄悄改变含义。

## 单位集解析与编辑边界

单位集引用目录中稳定量 / 单位身份；名称和本地化符号不能作为键。一个有效项目单位集必须为适用量给出可解释的显示选择；首版完整选择、内置集与逐量配置按下方已接受的 UD-01 范围执行，扩展格式选项后续审定。可解析和可支持是不同条件，需上下文但当前不支持的单位不得列成可用转换选项。

改变个人默认不批量改写现有工程。项目默认和视图覆盖需要明确作用范围与恢复入口；覆盖的生命周期、持久化以及输出是否显式继承某视图不能从界面位置猜测，分别见 UD-01、UD-07。项目单位集变更不修改来源标签、计算模式或快照身份。

## 保存、失败与撤销

呈现偏好可以独立要求保存，但不进入物理输入历史。安全写入、替换失败和工程关闭的共用流程归 [项目生命周期](../project-lifecycle-storage.md)；本文只拥有单位配置的保存语义。

- 保存成功后才能按实际写入内容更新保存基线；失败时保留待保存偏好和可重试路径，不因失败使求解结果 stale。
- 有字段草稿时执行保存不能静默提交、丢弃草稿或写入显示数字替代 SI；事件约束见 [UE-12](input-drafts-and-interactions.md#u2-事件表)。保存只写已提交内容并提示会话草稿；草稿不随工程恢复，关闭 / 切工程须另行保护。
- 撤销物理输入走正式历史；呈现偏好采用独立会话历史，路由见 UD-04 / UE-11，不能为了支持 Undo 而伪造物理输入变化。
- 旧工程无配置采用完整 SI 集；未知 / 不兼容配置按 UD-02 拒绝此次装载并保留原文件与当前工作区；I1 已补齐 DTO 和固定旧版本门禁证据，I2 已接入升级提示。不能仅通过打开时回退 SI 掩盖数据丢失。

验收为 [UNIT-05—07 / UA-05—07](requirements-traceability.md)，未实施的兼容路径保持待验证。

### 保存基线与格式边界

I1 前静态核对发现：[项目 DTO](../../../crates/rf-store/src/project.rs) 当时外层版本为 1，只有 kind、schema_version 和 document；内层 metadata 校验也共用这个版本常量。[加载 / 保存驱动](../../../apps/radishflow-studio/src/document_lifecycle_driver.rs) 当时只装载 / 组装 document，保存成功后记录工程 revision；[WorkspaceState](../../../crates/rf-ui/src/state.rs) 尚无独立呈现保存基线。只改写盘函数不足以保存 / 恢复单位集，应用加载与保存状态投影也必须接入。

I2 已将当前呈现配置与最近成功保存的呈现配置作为独立状态比较，工程的既有 revision 脏判断保持。项目总体待保存为两者任一变化；草稿数量另外显示，不混入“已经保存的内容”。单位设置应用、撤销和恢复为已保存选择均不推进求解修订；写盘成功才同时更新对应保存基线，失败不清脏、不改快照资格，原数据保护与恢复证据沿用安全保存契约。另存为复用安全写入，成功才改变路径与基线。

I1 格式采用外层项目版本 2 保存与 document 并列的呈现块；块中保存稳定量 / 单位 ID 的完整选择，不保存系数、临时输入单位、视图覆盖、草稿或历史栈。缺失配置只在明确旧版本迁移时补完整 SI；新格式缺项、重复键、不兼容组合或未知 ID 不能静默补值。具体字段与版本常量见下方已实现接口；metadata 仍为 1，未改变工程数值语义。新增格式选项继续另行评审。

升级外层版本的依据是：[JSON 版本分派](../../../crates/rf-store/src/json.rs) 当前会拒绝较新外层版本，但同版本数据会进入现有强类型反序列化。按 I1 前 DTO 的静态结构推断，在旧版本信封中加可选单位字段不能保证旧程序重存时保留它；未做旧二进制实测，不能宣称向后无损。

| 文件路径 | 已接受处理与可观察结果 | 必须补的证据 |
| --- | --- | --- |
| 读取现有 v1 | 在内存补完整 SI，不因打开而产生呈现脏标记，不自动写回磁盘 | SI 数值、工程身份与原文件不变；旧工程不受个人默认影响 |
| I2 启用格式升级后保存 | 新写入采用新版本；从 v1 首次保存前说明格式升级及旧版不可读，允许另存为保留原件 | 明确升级提示、取消不写盘；安全保存失败保留原数据 / 恢复证据及可重试状态 |
| 旧程序读取新版 | 利用版本门禁明确拒绝，不让旧程序读入后丢掉单位配置再保存 | 用旧读取器 / 固定 fixture 验证拒绝，不能只跑新版本自读 |
| 未知单位 / 新格式缺项 / 不兼容量 | 首版拒绝此次项目装载，提示量 / 单位身份，保留原文件与当前工作区；不自动改 SI 或部分装载 | 无原地重写；不能在“保留原信息”名义下把未知数据存成已知配置 |
| 可保留未知配置的只读打开 | 未选入首版；后续若扩展，需要独立的原始数据保留、只读状态与另存兼容设计 | 后续另行批准并补读取 / 往返 / 编辑禁用验收后再实施 |

新版文件的旧程序不可读这一兼容影响已获批准；I2 新建工程保存 v2，来源 v1 须显式确认升级，来源 v2 保持 v2。个人默认独立保存，[既有偏好 DTO](../../../crates/rf-store/src/studio_preferences.rs) 与最近项目记录格式不变。

- UA-05：七类量配置完整、两个预设可解释；修改项目选择不改变个人默认；个人默认只影响新建；Inspector 覆盖跨对象保持、结束视图后跟随项目。
- UA-06：呈现 A→B→撤销回 A 后与保存基线一致；工程 revision / 快照全程不变。工程和呈现同时有变更时保存成功更新两者基线，有草稿仍显示未提交数量；注入写盘失败后两者均保持待保存。

### 类型与版本分派

| 边界 | I1 已实现接口与职责 | 约束 / 验收 |
| --- | --- | --- |

解析先从原始 JSON 探测 kind / schemaVersion，再从同一原文按版本校验 DTO；直接 serde 调用也复用两版校验，不经过会覆盖重名属性的 Value。项目信封、呈现块及条目重名属性拒绝；两版信封的未知顶层属性、v2 未知呈现属性和条目属性也拒绝。v1 不接受伪装为旧版的 presentation 块。量 / 单位只匹配稳定 ID，不接受界面符号或别名。数组重复量、缺项、不兼容和需上下文单位均拒绝；序列化按目录顺序输出。布局 / 认证缓存解析器保持原行为。

### 呈现状态与保存事务

[ProjectPresentationState](../../../crates/rf-ui/src/state/project_presentation.rs) 持有项目 current / saved、临时视图覆盖、独立 undo / redo 和来源版本。`Apply` / `RestoreSaved` 只替换项目单位，`ApplyView` 只替换指定视图；Undo / Redo 按作用范围恢复逆向变更。无变化不创建历史，保存不清空历史；保存后撤销项目选择会重新计算呈现脏状态，视图历史不影响保存比较。关闭视图移除其 Undo / Redo 条目，工程历史仍独立。设置弹层未应用选择由 shell 持有，个人默认写盘不进历史。

`WorkspaceState::project_save_state()` 统一返回 `ProjectSaveState { document_dirty, presentation_dirty, pending_input_count }`。前两项合成总体待保存，草稿数量另列；窗口标题、打开 / 新建 / 关闭保护和保存回执消费该摘要。保存不会提交或丢弃草稿；有未提交输入时，“保存并关闭”仍保留窗口，用户须返回处理或明确放弃。

[加载 / 保存驱动](../../../apps/radishflow-studio/src/document_lifecycle_driver.rs) 捕获已提交文档与已应用配置，复用安全写入，成功后才更新路径、来源版本和两项基线。失败 / 取消不动基线、历史、草稿或结果。新建工程保存 v2；v1 普通 Save / SaveAs 明确拒绝，shell 先展示升级 / 另存为 / 取消选择，再派发 `SaveUpgraded { path }`。该命令是应用层显式同意标记，不进入工程模型或 CLI SI 协议。

最小设置入口位于“设置 → 项目显示单位”，提供 SI / 工程预设、七类量逐项选择、应用 / 取消、呈现撤销 / 重做、恢复已保存项目选择和新工程默认。此时只持久化单位选择；I4 首批数值字段按项目 / 视图选择换算；结果等未接入消费者仍以自身 SI 标签为准，按 U3 推进。

### 个人默认的兼容取舍

进一步核对 [偏好读写](../../../apps/radishflow-studio/src/studio_gui_preferences_store.rs) 和 [启动装载](../../../apps/radishflow-studio/src/studio_gui_shell/mod.rs)：旧版读取失败会退到空最近项目列表，之后 [最近项目写入](../../../apps/radishflow-studio/src/studio_gui_shell/app.rs) 会重新构造偏好文件。因此在原偏好文件加字段或升版本，均不足以保证旧程序运行后保留单位默认；不能把项目的“拒读保护”直接套到应用偏好。

**2026-09-28 已授权并实现：**个人单位默认仍属于应用偏好，但单独保存到现有偏好路径同目录的 `unit-defaults.rfstudio-preferences.json`；使用独立 kind（`radishflow.studio-unit-defaults`）、版本 1 和同一完整 displayUnits DTO。既有最近项目文件及其版本保持；新文件路径从已解析的偏好路径派生，包含环境变量覆盖的目录，不另建隐蔽存储根。该拆分避免旧版最近项目写入覆盖单位默认，代价是增加一个应用偏好文件。

- 文件不存在时新工程用 SI；新程序不会只因启动而创建默认文件。显式“设为新工程默认”以当前已应用项目选择为源，成功才更新内存默认；失败保留此前默认和项目选择，并报告可重试错误。
- 文件损坏、未知 ID / 版本时保留原件并提示，禁止自动覆盖；用户可显式选择本次以 SI 新建，不能声称成功读取个人默认。替换损坏默认须再次确认；先独占创建同目录备份并写入原始字节，再安全替换默认。备份失败不替换；替换失败保留备份路径，内存默认只在成功后更新。
- 最近项目更新与单位默认保存互不重写对方文件；不承诺两文件原子事务，也无此业务需求。独立文件的路径、kind 和失败恢复策略属于本次新增 UD-02 决策，已在 I2 获授权实施。

### I4 视图覆盖与历史生命周期

2026-09-28 继续实现已接受的 UD-01 / UD-04：

- `ViewDisplayUnits` 是经共享单位目录验证的稀疏按量覆盖，未覆盖量实时跟随项目，显式选中与项目相同的单位仍是覆盖。`DisplayUnitViewId` 是视图所有者提供的临时身份，不序列化。首批 UI 只列已接入编辑的温度、压力与摩尔流量。
- 每个逻辑窗口的 Inspector 是一个视图上下文，侧栏和 Runtime 的 Inspector 共用；模块设置采用项目显示。切对象、标签页或暂离工作台保留上下文。“关闭检查器”隐藏内容并结束该上下文，重开从跟随项目开始；窗口成功退役在 host 层清对应覆盖与历史，工程成功替换清所有上下文。取消 / 打开失败保留旧上下文，不能因隐藏或重绘误清覆盖。
- 项目与视图编辑进入同一呈现历史，但条目只持有所属范围的逆向变更，不能使用包含所有视图的整份快照。视图结束时双栈仅移除该视图条目，保留项目 / 其他视图历史，避免之后 Undo / Redo 恢复已关闭覆盖。无变化不创建历史或清 Redo；恢复已保存设置只改项目。设置入口说明历史作用范围。
- `numeric_field_presentation_in_view` 与 `BeginInView` 分别按显式视图读取和初始化。已有同字段会话仍是唯一输入所有者：从另一视图打开或关闭原视图都不重写原文 / 输入单位；各视图的“提交后显示”按各自有效单位呈现。单位选择仍走 `NumericEditCommand`，不因显示覆盖而误标为用户显式选择输入单位。
- 保存脏判断、工程 DTO 与个人默认仅消费项目 `display_units()`；视图覆盖不改变 revision、SI、快照或保存基线，不写入工程文件 / 布局 sidecar。跨窗口带视图身份的命令在窗口分派处拒绝错误作用域。

[领域回归](../../../crates/rf-ui/src/state/project_presentation.rs) 覆盖非法组合原子拒绝、逐量跟随、同值显式覆盖、混合 Undo / Redo 和退役双栈裁剪；[编辑回归](../../../crates/rf-ui/src/state/numeric_edit/tests.rs) 覆盖原始 SI 精度与共享会话；[Studio 回归](../../../apps/radishflow-studio/src/studio_gui_shell/tests/view_units.rs) 覆盖跨对象、跨窗口、关闭、取消、保存重开和装载失败 / 成功。原生渲染测试区分 Inspector °C 与模块设置 K。真实窗口、键盘菜单、读屏与跨平台验收仍待 I5，不以合成事件和绘制文本代替。
