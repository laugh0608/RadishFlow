# 单位输出与跨端一致性

更新时间：2026-10-07

## 用途与状态

用途：维护结果、复制 / 导出与自动化消费者的表示一致性，以及输出验收场景。
读者：结果界面、CLI / API、输出、消息与测试维护者。
不包含：完整报告、带单位新协议或上下文换算已经实现的声明。

父专题：[单位系统](../units-and-quantity-system.md)。状态：Draft / U3 待实现；U1 已接通变量浏览和 CLI 的规范单位标签，当前 CLI v1 / v2 数值仍为 SI。

## 消费与输出约束

| 消费者 | 转换与身份边界 |
| --- | --- |
| Inspector / 变量浏览 / 结果表 | 共用目录、量语义和有效显示选择；同一量、SI 值和格式设置产生一致表示，不在控件复制公式 |
| 已有复制与文本导出 | 先遵守当前结果门禁，再转换；单位、基准及结果身份明确。显式输出选择优先，否则捕获本次项目单位集，不在输出中途随界面偏好漂移 |
| CLI v1 / v2 | 保持已有 SI 数字、JSON 字段和规范 unit 标签；不随 GUI 单位集改变数值解释 |
| 未来带单位 API / 自动化 | 写入带稳定单位身份，读取带单位与基准；兼容扩展或版本化在 UD-07 决定，不能只替换 JSON 数字而沿用 SI 字段口径 |
| 未来录制 / 回放与报告 | 保存足以复现的单位身份及必要上下文；不依赖录制时界面偏好，模板不私存系数；范围随对应能力推进 |
| 消息、条件观察与图例 | 共用量 / 单位转换；显示不更改物理阈值、触发条件或结果身份；消息不从显示文本反推工程值 |

结果资格由 [结果专题](../results-review-diagnostics.md) 决定：stale / missing 仍拒绝当前正式输出，不借单位转换开放旧结果或调试中间值；表示转换不重算物性。格式精度不等于核心精度，跨消费者比较需同一量、基准、有效单位、格式和快照，不能只比较字符串。

输出任务捕获配置的时点、视图覆盖是否作为显式输出选择、格式与小数点规则、错误回执及协议扩展见 UD-07。完整报告与 API 单位输入不是 U3 退出的默认前置。

[运行条件 N4](../runtime-messages/run-control-and-watch-conditions.md#监视条件与运行控制) 的阈值与观察值复用规范 SI 转换，保留用户输入单位解释；缺上下文、非有限与不兼容需明确拒绝，不能解释为条件未满足。V1—V4 的图例和阈值消费方式归结果可视化；U4 逐项提供上下文能力，不默认已支持质量 / 摩尔或标准体积换算。

## UD-07 首批输出方案草案

2026-10-07 根据现有结果输出入口整理，**待项目所有者审定，未实现**。本草案不改变 U2→U3 顺序；I5 仍按已有范围补验，不以草案替代退出门禁。

| 决策点 | 首批建议与影响 |
| --- | --- |
| 消费者范围 | 接入当前结果表 / 详情、变量只读浏览及已有复制 / 轻量文本导出；只转换目录中已支持的量。诊断文本、完整报告、API 单位输入、录制 / 回放和 N4 阈值另随对应阶段实施 |
| 捕获时点 | 用户发起复制 / 导出时先核对当前结果，再一次性捕获结果身份、快照与项目单位集；导出在打开文件选择器之前捕获，覆盖确认继续持有同一配置 |
| 视图覆盖 | 结果视图按该视图有效选择呈现；首批输出固定使用捕获的项目单位集，按钮旁说明此作用域。临时视图覆盖不自动成为输出选择；未来明确的输出选择可优先，届时另审 UI |
| 格式 | 首批只读结果与输出建议统一为 6 位有效数字、点号小数、去掉无意义尾零；非零绝对值小于 `1e-4` 或大于等于 `1e6` 时用科学计数法，舍入跨越边界时按舍入后值选择形式，负零显示为 `0`。这会替换现有各量固定小数位和变量浏览的直接字符串化；不修改可编辑原文、SI 或 CLI 数字，也不新增用户可配置精度。值与目录单位标签成对生成，比例量明确基准；显示文本不用于无损回放 |
| 配置与身份分离 | 仅切项目 / 视图单位不使结果失效，也不更改已发起任务的配置；工程修改、结果被替换或工程切换后，写出 / 覆盖前重验当前结果资格并拒绝过期任务 |
| 失败与保存 | 转换全部成功后才提交剪贴板或文件写入；缺上下文、不兼容、非有限 / 溢出明确失败，不生成错标单位的成功产物；复用既有文件写入与覆盖策略，失败不改求解状态 |
| 协议兼容 | 核心快照、工程物理值及 CLI v1 / v2 保持 SI；不修改 SI 字段标签来承载非 SI 数字，不新增项目 schema、依赖或对外带单位协议 |

接线建议：在现有 [结果输出入口](../../../apps/radishflow-studio/src/studio_gui_shell/result_export.rs) 的当前结果检查之后形成一次输出所需的不可变数据；`PendingResultExport` 随待确认路径保存该数据，最终写入仍复验身份。共享转换 / 格式位于呈现层，结果表、变量浏览和文本输出消费同一表示逻辑，壳层只负责捕获作用域、对话框、剪贴板和文件操作。具体类型名和接口签名在审定范围后制定，不预建通用报告框架。

首批验收应覆盖 UA-13—15：`300 K / 100000 Pa / 1 mol/s` 对应 `26.85 °C / 1 bar / 3.6 kmol/h`；比例与焓按量语义另取独立期望值；同项目配置下各消费者一致。另检查捕获后切单位、覆盖等待期间新结果 / 新修订 / 工程切换、stale / missing 拒绝、转换失败时原文件和剪贴板保留，以及旧 CLI SI 回归。视图覆盖与输出项目单位不同时应有明确提示，不以字符串相等掩盖作用域差异。

### 开工切片与接线核对（待审）

现有 [结果模型](../../../apps/radishflow-studio/src/studio_gui_window_model/mod.rs) 同时保留 SI 数值和格式化文本；[文本导出](../../../apps/radishflow-studio/src/studio_gui_window_model/snapshot_export.rs) 直接使用后者，[变量浏览](../../../apps/radishflow-studio/src/studio_gui_shell/variable_browser.rs) 直接字符串化数值。因此首批从 SI 数值生成共享呈现，不能解析已舍入的文本再换算，也不能仅替换单位标签。现有模型中的泡露点与相结果同步覆盖，缺失值保持缺失，不补零。

| 顺序 | 实施范围 | 最小验收 |
| --- | --- | --- |
| U3 首批 A：共享结果呈现 | 在现有呈现层复用 `QuantityKind`、`DisplayUnitSet` 和转换错误；接入流股温压流量 / 摩尔焓、组成 / 相分率、相流量 / 焓、泡露点、结果详情与已有比较。结果浏览默认跟随项目；仅消费实际存在的视图覆盖，不新增覆盖选择 UI | SI / 工程集 / 自定义选择一致；`0.35 → 35 mol%`、`-2500 J/mol → -2.5 kJ/mol`；绝对温度 `300 K → 26.85 °C`，温差 `10 K → 10 °C`，比较不得套用绝对温度偏移；缺失与转换错误不伪装有效数值 |
| U3 首批 B：输出捕获与重验 | 复制 / 文件选择器之前捕获项目单位集和完整转换结果；覆盖等待保存同一输出数据及工程 / 快照身份；写入前重验身份，不能用当前偏好重建已发起任务 | 发起后切项目 / 视图单位不改变任务；工程切换、修订变化或重新运行均拒绝旧任务；任何转换失败不更改原文件 / 剪贴板；保留取消、覆盖与写入失败行为 |
| U3 首批 C：贯通复验 | GUI 变量只读浏览接入同一呈现，保留来源 / 有效性；输出入口显示“使用项目单位”。检查输入、运行、结果、复制 / 导出及保存重开，保持 CLI v1 / v2 原协议 | 同一快照与配置下消费者一致；项目只改显示选择不导致重算 / stale；旧 CLI SI 回归、macOS 文件读回及原生代表路径通过，跨平台按既定节点记录 |

格式独立用例至少包含 `1.234567 → 1.23457`、`0.00001234567 → 1.23457e-5`、`1234567 → 1.23457e6`、`999999.6 → 1e6`、零 / 负零及极小非零；转换失败和数值缺失分开表示。6 位有效数字仅是本草案的只读显示建议，不修改 U2 编辑精度或新增项目格式字段。

实施复用现有结果输出、变量浏览、结果比较与 CLI 回归；先运行对应模块测试，再执行受影响 crate、严格 clippy 及仓库规定的集成检查，原生 smoke 事前告知。上述 A / B / C 是同一首批范围的执行顺序，局部完成不代表 U3 退出。开工还需审定 [I5 受控延期提案](requirements-traceability.md#i5-受控延期与-u3-开工提案待审)；当前未改产品代码或批准阶段例外。

目录场景见 [转换验收](catalog-and-conversion.md#目录与转换验收场景)，保存场景见 [偏好验收](unit-sets-and-persistence.md#单位集与保存验收场景)，输入场景见 [交互验收](input-drafts-and-interactions.md#交互验收场景)。本表只维护可观察预期，状态和证据见 [追踪表](requirements-traceability.md)。

## 分阶段验证

U1 已有代码与历史测试证据，但本轮只整理文档；U2 / U3 需贯通输入→切换→提交→运行→输出→保存重开及失败路径。各切片实施前审定数据集、精度与平台范围，验证通过后才回填状态。GUI 等价输入、撤销重做、当前结果身份和偏好独立保存须一起观察，不能以换算单元测试代替真实交互验收。
