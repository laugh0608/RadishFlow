## 专题目标

- 用户可从 Studio 经系统浏览器使用 Radish 身份登录，返回后看到真实账户与 RadishFlow 授权状态。
- 控制面能够明确回答“外部认证的是谁”“对应哪个产品账户”“当前允许访问哪些资源”，避免把登录成功直接当作业务授权。
- 用户可以退出、切换账户，并理解服务离线、授权过期与本地可用能力之间的差别。
- 为未来独立账户、团队权限与管理入口预留清楚的决策位置，不提前承诺注册、密码登录或团队协作功能。

## 候选方案与现行架构关系

建议未来首版采用“Radish 统一认证 + RadishFlow 产品账户映射与独立业务授权”。这里的产品账户位于服务端，不是桌面本机账号，也不必拥有独立密码。

| 事项 | 首版候选方向 | M0 必须确认的影响 |
| --- | --- | --- |
| 身份源 | 继续使用 `Radish.Auth`，桌面保持 Authorization Code + PKCE | 核实原生客户端注册、issuer、audience、scope、回调与登出策略 |
| 产品账户 | 参考 RadishMind，由外部 `(issuer, subject)` 映射稳定 `user_id` | 现行“不自建第二套用户系统”的表述需明确是否允许无密码的产品账户记录；尚未视为批准变更 |
| 本地注册与密码登录 | 作为备选扩展，首版建议不纳入 | 若选择完整 RadishMind 模式，须另行确认凭据、找回、MFA、滥用防护和运营责任，并替换现行账号边界 |
| 业务授权 | 控制面按产品账户、资源及本地授权事实作决定 | Radish scope、email、tenant 或同名 role 不自动成为产品权限；未来组织成员模型需独立确认 |
| 桌面凭据 | 首版优先延续现有 Bearer 客户端契约，由控制面验证 access token 并解析账户绑定 | 不用 ID token 访问 API；若改为产品 session / token 交换，需重新设计协议、续期、撤销及客户端兼容 |
| 后端与持久化 | 延续现有 `ASP.NET Core / .NET 10` 建议 | 数据库、迁移与部署归属在控制面专题确定；不照搬 RadishMind 的开发测试存储矩阵 |

上述均为可评审建议。M0 可以选择保留纯统一身份模式，但必须记录未采纳产品账户映射的理由，并据此调整后续阶段，不能同时维护两套互相冲突的账户真相。

## 范围

首版候选纳入：Radish 登录、首次准入与账户映射、账户摘要、续期 / 退出 / 切换、账户禁用与授权衔接、安全凭据存储、已有资产租约的账户隔离、脱敏审计和真实集成验收。

首版候选不纳入：独立密码注册、身份数据库复制、多身份提供方、成为 OIDC issuer、完整团队成员管理、计费订阅、管理台全面实现、项目云同步、在线求解或 COM 认证语义。若今后引入多登录方式，再加入显式绑定 / 解绑、绑定冲突和最后登录方式保护，不在单一身份源首版提供会使账户失去访问方式的解绑入口。

## 用户路径

1. 未登录时仍可新建、打开和运行允许本地使用的项目；Home 明确展示本地环境和远端授权两类状态。
2. 点击登录，Studio 创建一次性登录事务，拉起系统浏览器到经确认的 Radish 授权端点。
3. 用户完成认证并返回 loopback 回调；取消、超时、重复回调或校验失败均结束本次事务，允许重新发起。
4. Studio 完成协议校验与换 token 后调用控制面；控制面验证访问凭据，按外部身份查找产品账户，仅在准入策略允许时原子创建账户与绑定。
5. 控制面从本地授权事实返回账户摘要、授权与可访问资源；认证成功但未获准入或没有资产权限时显示对应状态，不显示虚构授权。
6. 重启后通过系统安全存储恢复凭据并检查有效性；联网时刷新授权，离线时仅按已有有效租约使用对应受控缓存。
7. 退出或切换账户时清理当前认证状态和凭据引用，阻止新账户继承旧账户授权；本地项目文档保留。远端撤销失败需明确提示，不能把本地退出描述为全设备会话已撤销。

## 设计边界

### 数据与授权

- Radish 拥有外部认证身份；候选 RadishFlow 账户服务拥有 `user_id`、账户状态和外部身份绑定，控制面拥有产品授权与租约。外部绑定唯一键为 `(issuer, subject)`，不能以 email 或显示名自动合并账户。
- 首次准入、重复 callback 和并发首登必须保证账户 / 绑定写入原子性与唯一性；拒绝准入不能留下半成品账户或资产授权。
- 后端在每次受保护请求中检查账户有效性与相应业务权限。登录结果、缓存 UI 状态和外部 role 字符串不替代资源访问判断。
- `AppState` 只消费账户摘要、认证状态、授权状态和安全凭据引用；身份凭据、session 和云端成员关系不进入 `FlowsheetDocument`、项目文件、Rust 求解热路径或 `.NET` COM 适配层。
- 现有缓存 schema 为 v1；若新增产品 `user_id`，必须先定义外部主体与产品主体的分离、缓存作用域、版本迁移或失效策略，不静默复用旧 `subject_id`。无有效租约或主体不匹配时不加载受控资产。
- 离线撤销存在可见性时差，须确认最长离线期限、重连后的禁用 / 撤销处理及本地退出行为；不承诺离线即时感知服务器撤销，也不把基础本地能力变成登录硬依赖。

### 协议、命令与会话

- 实施前固定 issuer / discovery / JWKS 策略、签名与受众校验、PKCE、state、nonce、redirect、时间窗口、重放防护、刷新轮换及撤销口径；ID token 与 API access token 分开校验职责。
- 桌面不持有长期 `client_secret`，token 仅存系统安全存储，不能进入普通 JSON、日志、URL 参数留档或错误截图。安全存储不可用时给出明确失败，不回退明文文件。
- 现有 `/api/radishflow/entitlements/current`、资产 manifest 和租约客户端契约继续作为兼容评估输入；账户查询、准入和账户禁用接口先定义语义，M0 / M1 再冻结路径、DTO、错误码与版本。
- 客户端命令应区分发起 / 取消登录、完成回调、刷新、退出、切换与授权同步，并处理并发刷新、晚到回调和退出后旧请求写回，保持唯一认证状态源。
- 浏览器登录事务、桌面持久凭据与未来管理台 Web Session 分别定义生命周期。若建设管理台，参考 RadishMind 的服务端会话、HttpOnly / Secure cookie 与 CSRF 做法，由管理台专题承接；桌面不照搬 cookie 会话。

### UI 与文档

- Home 展示登录进度、取消 / 重试、账户摘要和授权摘要；账户详情放在未来设置入口，先确认页面范围，不扩展当前菜单。
- 区分未登录、已认证但无权限、服务不可用、安全存储失败与离线租约到期，并给出对应恢复动作。
- 审计记录账户、事件结果、受控资源与关联 ID，不保存密码、token、code、verifier、cookie 或完整 claims。
- M0 决策后更新认证授权架构、App 状态边界与控制面专题；协议或缓存变更同步对应版本说明。本文不复制资产 API 全文或现有架构长篇细节。

## 验收与验证计划

| 验收面 | 最小验证及通过条件 |
| --- | --- |
| 协议 | 正常登录；错误 issuer / audience / 签名、过期、state / nonce / PKCE 不匹配、回调重放、发现 / JWKS 失败均拒绝，且不写入成功身份 |
| 账户与授权 | 同一外部身份并发首登只产生一个有效绑定；同 email 不同 subject 不合并；未准入、禁用、无权限和跨账户资源访问均拒绝 |
| 会话与凭据 | 取消、刷新失败、重启恢复、退出后晚到请求、切换账户与安全存储失败均有确定行为，失败不恢复旧身份或明文落盘 |
| 缓存与离线 | 旧 schema 处理可预测；主体不匹配、租约过期和重连撤销阻止受控资产访问；本地基础建模与项目保存 / 重开不依赖远端服务 |
| 用户与真实环境 | 系统浏览器到 Studio 的成功 / 失败恢复可复现；每个目标平台分别验证回调、凭据读写删除和退出，不由单平台推断跨平台通过 |
| 数据暴露 | UI、日志、错误、缓存和证据产物中无原始凭据；拒绝认证 / 授权时无非预期业务、下载或租约副作用 |

开发时先做领域与协议的确定性测试，再做 HTTP / 持久化 / 原生存储集成，最后执行真实 Radish browser smoke。跨模块改动回到当时有效的仓库基线；涉及兄弟项目注册、数据库、部署和真实测试环境的写入须在该阶段明确授权。

本次规划只执行文档治理、链接、体量与文本检查。设计完成、测试 issuer 闭环、真实联调和生产可交付是不同结论，分别留证。
