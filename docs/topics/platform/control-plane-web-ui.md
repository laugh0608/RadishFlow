# Control Plane Web UI 后端管理台专题

更新时间：2026-09-12

> 本文定义该专题的能力、开发范围与验收要求；具体迭代切片和优先级以 [当前状态](../../status/current.md) 为准。

## 用途

用途：定义 RadishFlow 后端 Web 管理台的目标页面、角色边界和进入设计前的准备口径。
读者：负责控制面管理 UI、授权运营、物性资产管理、版本 / 租约管理和审计页面的开发者、用户、AI / Agent。
不包含：Studio 桌面工作台、公开营销站、完整 BI 报表、Radish.Auth 管理台和 Control Plane API 实现细节。

## 专题层级

- 层级：二级功能
- 父专题：`docs/topics/platform/control-plane-service.md`
- 关联专题：`docs/architecture/studio-ui-topic-plan.md`、`docs/architecture/auth-entitlement-architecture.md`

## 专题目标

- 后端 Web UI 是控制面管理页面，不是 Studio 桌面建模界面。
- 第一轮只明确页面职责、角色权限、数据来源和不做项。
- 当前不进入实现，除非 Control Plane 后端服务先进入近期主线。

## 范围

本专题纳入：

- 用户授权和订阅状态管理。
- 物性资产 / 派生包清单。
- 版本、租约和分发状态。
- 下载票据、撤销和审计摘要。
- 运维状态和失败排查入口。

本专题不纳入：

- 桌面 flowsheet 编辑。
- 在线求解工作台。
- 完整财务 / 订单 / 客服系统。
- Radish.Auth 自身的用户系统管理。
- 完整 BI 平台。

## 设计边界

### 数据与状态

- 管理台只读取 Control Plane 服务端数据。
- 不直接读取用户本地项目文件。
- 不展示或导出高价值原始物性资产明文。

### 命令与接口

- 所有管理操作必须有权限校验和审计。
- 危险操作需要确认和可追踪记录。
- 不通过管理台直接修改桌面端项目语义。

### UI 与交互

- 管理台应采用密集、克制、可扫描的后台页面风格。
- 优先表格、筛选、详情页、状态 chip 和审计记录。
- 不做营销式首页或 Studio 工作台复制品。

| M2 | 设计稿 | 产出控制面管理 UI 设计稿或 brief |
| M3 | 最小实现 | 只在 Control Plane API 已稳定后实现 |

## 验收标准

- 管理台不承担桌面建模职责。
- 授权、资产、租约和审计能追溯到服务端事实源。
- 高风险操作有权限、确认和审计。
- 页面设计不提前承诺尚未实现的控制面能力。

## 验证计划

- 设计阶段：评审页面职责和权限矩阵。
- 实现阶段：补 UI smoke、权限测试和 API contract test。
- 暂不需要当前仓库级 Rust 验证，除非影响桌面端共享 DTO。
