# 公共 API 与访问控制专题

更新时间：2026-09-14

状态：`Draft / 规划方向已确认 / 未排期`

## 用途

用途：定义 RadishFlow 外部调用的凭据、资源权限、API key 生命周期和资源配额，为实施切片提供范围与验收依据。
读者：负责统一 API、插件宿主、自动化、控制面与运行管理的开发者、项目所有者和 AI / Agent。
不包含：已冻结 HTTP schema、已部署服务、完整身份系统、计费方案或新的软件许可授权。

2026-09-14 项目所有者确认将本文方向纳入规划。公共 API 是可供外部集成的接口，不默认匿名、公网可达或远端求解；具体协议和部署边界在 M0 决策。当前基础功能优先级不变。

## 专题层级与目标

- 层级：二级功能。
- 父专题：[Control Plane 后端服务](control-plane-service.md)，承接远端访问控制部分；本地工程 API 的领域边界由 [模拟平台长期规划](../../architecture/simulation-platform.md#统一-api-的目标形态) 拥有，不归控制面执行求解。
- 关联专题：[账户与联合登录](account-and-federated-login.md)、[项目生命周期](../project-lifecycle-storage.md)、[CAPE-OPEN 适配](../capeopen-pmc-adapter.md)；当前不新增子专题。
- 目标：用户和集成程序以最小权限访问工程能力；管理员可以识别、限制和撤销调用方，任务及结果始终属于明确主体和资源作用域。

## 当前实现快照

- 已有 `rf-ffi` engine / JSON 窄接口、`.NET` CAPE-OPEN 桥接和文档命令 / 历史；完整变量 / 动作树、COM Automation 和通用插件运行时仍是目标。
- Studio 已有控制面 Bearer 客户端、授权 DTO、缓存和租约编排；服务端和真实账户闭环的缺口见父专题与账户专题。
- 公共 API key 签发管理、服务账号、统一资源权限、服务限流和远端求解任务服务尚未由本专题交付；现有客户端测试不能作为这些能力的验收证据。

## 用户路径与范围

1. 用户或管理员为脚本 / 服务创建独立凭据，选择资源范围、允许动作、有效期和配额；创建者不能授予自身无权委托的能力。
2. 调用方通过相应安全通道携带凭据，发现允许访问的节点，读取数据或提交受控动作。
3. 长任务返回任务身份；调用方按权限查询状态、取消并读取结果，重复提交按幂等契约处理。
4. 权限不足、凭据过期、资源超限或计算失败返回可定位的结构化错误，不伪造成功或留下半成品结果。
5. 管理者查看脱敏使用记录、轮换或撤销凭据；失效凭据不能继续创建任务或读取受保护数据。

纳入规划：本地与远端信任边界、身份映射、资源授权、key 生命周期、任务限额、审计和验收。首版不同时建设所有认证方式、完整管理台、计费平台、公开匿名计算、通用云求解或插件市场。录制器、插件和 HTTP 适配不得另造一套文档写入或授权语义。

## 凭据与调用场景

| 场景 | 规划方向 | 边界 |
| --- | --- | --- |
| 本机库、CLI、COM 自动化 | 使用操作系统身份、文件 / IPC 访问控制和本地会话边界 | 不强制申请云端 API key；进程内库没有独立于宿主的安全隔离，本地监听服务也不能仅凭 loopback 地址信任请求 |
| Studio 登录远端服务 | 延续 OIDC Authorization Code + PKCE 和 Bearer access token | 桌面不嵌入长期 client secret，不用 ID token 访问 API |
| 用户自己的脚本 | 有期限、可撤销、限定资源与动作的个人 API token | 绑定用户，权限不超过该用户当前可委托权限；用户禁用时同步拒绝 |
| 服务器集成 | 独立服务账号绑定 API key；按企业需求评估 OAuth client credentials | 不共用管理员个人凭据；不能把 client secret 放在桌面或公开客户端 |
| 第三方应用代表用户操作 | OAuth 用户委托授权 | 用户明确授予范围，不要求交出长期个人 key |
| 宿主内插件 | 独立插件身份和显式授予的能力 | 安装不是全权授权；需要远端访问时另获受限凭据，不继承用户完整 token |

OAuth 协议设计以 [RFC 9700](https://www.rfc-editor.org/info/rfc9700/) 为安全依据；本表不替换既有桌面契约，也不提前冻结尚未实现的服务账号或产品账户 schema。

## 权限、数据与状态

- 请求通过条件同时包括：凭据有效、主体有效、凭据 scope 允许、主体当前资源权限允许、所需产品 / 资产权益有效、资源预算允许。授权取这些条件的交集；没有产品权益要求的基础能力不凭空新增门槛。
- 资源范围至少能表达项目及其对象、受控资产、任务与结果；组织作用域在组织模型确认后加入，不静默重解释现有 `tenant_id`。接口不能仅依赖调用方传入的项目 ID 决定归属。
- 统一保护浏览树枚举、搜索、元数据、订阅、批量请求、下载和缓存结果，防止只拦写入却泄露其他主体数据。长连接、排队任务及权限变化后的重新校验时机在契约中明确。
- API key、个人 token 和 OAuth access token 最终映射到明确主体与授权上下文，复用同一资源判断；插件有效权限同时受安装授予及当前调用作用域限制。
- 应用宿主 / 服务入口负责授权、限额和审计，领域层继续负责工程校验与状态一致性；Rust 求解器只接收输入快照、明确预算和取消信号，不访问 token、账户库或远端鉴权。
- 凭据与许可材料不进入 `FlowsheetDocument`、项目导出、录制脚本或计算结果。写入继续沿用命令、revision 和结果旧化，任务输出提交前核对输入版本，不能覆盖已变化的当前工程。

## API key 生命周期

- 使用高熵随机秘密，区分可显示的 key ID / 前缀与秘密；完整值仅签发时显示一次。服务端保存安全验证摘要及元数据，使用成熟随机数和密码学组件，不自创算法。
- 元数据包括主体、资源范围、scope、创建 / 过期时间、状态、签发者和最后使用记录。key 管理本身需要独立权限；创建、扩权、轮换与撤销均留审计。
- 通过 HTTPS 请求头传递，不放入 URL；客户端保存在系统安全存储或部署 Secrets 设施，日志、错误、遥测和示例只记录脱敏标识。
- 支持单 key 撤销、到期、轮换和必要的短重叠窗口；主体禁用独立生效。缓存校验必须有明确失效传播及最大延迟，不宣称撤销后仍有效的长缓存为即时撤销。
- 撤销后拒绝新请求；排队任务开始前重新授权。已运行任务、长连接和旧结果的后续处理在 M0 / M1 定义，不假定任意数值调用可瞬时中断；新结果查询始终重新检查权限。
- key 有效只证明持有该凭据，不代替资源授权或软件许可。安全传输、每请求授权和错误语义参考 [OWASP REST Security](https://cheatsheetseries.owasp.org/cheatsheets/REST_Security_Cheat_Sheet.html)。

## 限流与计算配额

| 限制面 | 规划要求 |
| --- | --- |
| 请求速率 | 同时按 key、用户 / 服务账号以及适用组织汇总；来源 IP 用于辅助防滥用，不作为唯一身份，多个 key 不能绕过主体总限额 |
| 任务准入 | 限定并发、排队数量及预算；跨副本的配额预留 / 释放需要一致性设计，单进程限流不得宣称全局有效 |
| 计算预算 | 限定运行时间、CPU / 内存及模型规模等有实际成本依据的指标；精确范围和值在测量后确定，不预设无依据数字 |
| 输入与输出 | 限定请求体、批量大小、上传资产、结果大小、分页和订阅积压，不能通过一次巨型请求绕过速率保护 |
| 重试与幂等 | 有副作用或昂贵任务定义幂等键作用域、保留期、请求摘要和重复返回行为；同键不同输入明确拒绝，不重复扣费或重复占用任务预算 |
| 超限与回收 | 明确排队、拒绝、超时 / 取消及额度释放；硬资源隔离由宿主 / 运行设施保证，合作式取消不冒充强制内存或时间限制 |

HTTP 绑定中区分无效凭据 `401`、权限不足 `403`、可重试限流 `429`（带 `Retry-After`）和其他预算 / 计算失败，敏感对象的存在性隐藏策略另行固定。审计包含主体、key ID、资源、动作、任务 / 请求关联 ID、授权结果和必要消耗，不记录凭据或完整工程输入。

## UI 与契约交付

未来凭据管理入口展示名称、资源范围、权限、到期时间、最后使用和撤销 / 轮换操作；秘密显示后无法再次读取，只能重新签发。插件授权页面明确新增能力，不能用技术字段堆替用户判断。具体放在 Studio 设置或控制面管理台，由首版部署与操作者决定，本轮不添加菜单占位。

协议交付需提供版本化 schema、错误对象、兼容 / 弃用规则、脱敏示例，以及凭据签发到资源访问和撤销的完整文档。现有资产 API 的 paths、DTO、scope 与缓存版本若需变更，先定义迁移方案，不默默改变旧语义。

## 分阶段切片

| 阶段 | 目标 | 退出标准 |
| --- | --- | --- |
| M0 范围与信任边界 | 选定首个本地 / 远端消费者、主体来源、首版凭据、许可政策依赖及部署范围 | 明确哪些能力无须远端服务；冻结授权归属、撤销传播、运行任务处置与验收范围；远端求解另行决策 |
| M1 契约与权限模型 | 定义资源 / scope、key 管理、任务配额、版本与审计 | 可评审 schema、威胁边界、兼容方案和正反向验证矩阵，不提前实现所有认证模式 |
| M2 最小受控闭环 | 一个真实消费者完成签发、访问、限额拒绝、撤销 | 资源隔离和生命周期集成测试通过；若只有只读或本地能力，明确尚未验证远端任务能力 |
| M3 外部交付 | 完成真实传输、持久化、管理入口和部署验证 | 安全存储、撤销、并发配额、故障恢复有真实证据；公开发布 / 部署按独立流程验收 |

## 验收与验证计划

| 验收面 | 最小证据 |
| --- | --- |
| 权限 | 正常访问；错误凭据、过期、禁用、scope 不足、跨项目 / 主体 / 任务 / 结果均拒绝；树搜索、订阅和批量接口无旁路 |
| 生命周期 | 一次显示、摘要验证、轮换、撤销缓存失效、排队重验和在途任务策略；退出 / 切换或删除 key 后不恢复旧授权 |
| 资源 | 多 key 共用主体总限额；并发准入不超发；任务结束、失败和取消释放预算；若部署多副本则验证全局配额 |
| 一致性 | 重试不创建重复任务；幂等键输入冲突拒绝；GUI 与 API 相同事务效果，取消 / 旧 revision 不误提交结果 |
| 数据与离线 | 凭据不进入日志、项目、录制或导出；合法基础本地能力不依赖官方服务；受控资产沿用有效租约边界 |
| 真实交付 | 实际消费者、TLS / IPC 和 Secrets 存储走通；单元测试、测试 issuer、真实联调和公网可交付分别留证 |

实现按领域权限测试、凭据 / HTTP / 存储集成、任务并发与故障测试、真实客户端 smoke 递进；每个切片仅执行相关验证，再按影响面进入当时仓库基线。仅文档阶段执行治理、链接、文本和体量检查。
