# 诊断工作台与多处联动

更新时间：2026-09-23

读者：Studio、画布、字段控件和可访问性维护者。
不包含：色值与主题 token 定义、已完成的新 Pencil 稿及消息生命周期第二份定义。

## 用户路径与工作台

底部“运行与诊断”为设计候选，默认左侧当前问题、右侧计算过程；可调整比例、最大化，窄窗口使用标签切换。全局、画布、模块提供渐进摘要；现有底部多个标签如何迁移由 R0 / R1 评审，不直接按旧布局增加另一套常驻面板。

1. 输入后查看当前缺项 / 冲突，点击定位到字段或连接；可选空项不当作必填错误。
2. 启动运行，查看实际执行步骤；出现问题时联动对象、当前问题和对应事件。
3. 展开证据、实际数值、单位、影响及建议。定位只导航；修复须重验前置条件，经正式事务并支持撤销。
4. 完成后检查结果有效性与警告；相关输入变化后旧问题 / 结果明确失效，重检、重跑建立新结论。
5. 支持运行控制后，从步骤 / 对象 / 变量进入停止条件编辑；命中后查看现场，再继续或结束运行。缺少支持时说明能力边界。

交互要求：

- 默认列表突出对象、问题、影响和动作，公式、方法、原始信息按需展开；按严重程度、对象、阶段、运行、工况筛选并搜索。默认当前上下文，历史切换始终可见。
- 当前列表避免每次更新重排导致点击目标移动；新问题不抢焦点、不清草稿。用户向上浏览过程时停止自动跟随，提示新事件数量；停止“跟随显示”不暂停计算。
- 右键提供快捷操作，同时保留可见菜单 / 按钮及键盘入口。普通成功不弹模态框，需用户作决定的阻断才使用相应对话；读屏通知按重要性控制，不能逐迭代抢读。
- 颜色配合文字、图标和线型，遵守 V0；“指定值带错误”“已求解带警告”可组合。新消息不得遮盖单位、焦点或已有诊断。

## 入口、详情与能力表达

| 入口 | 用户首先看到 | 后续动作 |
| --- | --- | --- |
| 全局摘要 | 当前工程 / 运行范围、运行状态、结果资格、问题计数 | 打开相应问题或过程，不汇总无关工程历史 |
| 画布标记 | 对象相关最高关注级别与数量 | 定位模块及对应问题；摘要不创建新的问题身份 |
| 模块面板 | 本模块活动问题与受影响字段 | 展开原因、证据、影响和合法修复动作 |
| 当前问题区 | 可扫描列表与过滤条件 | 定位、展开、重检；过滤后仍可看到未过滤总量 |
| 计算过程区 | 实际执行树、当前选中步骤及事件 | 查详情、回到最新；后续按能力设置停止点 |

空状态分别表达“无活动问题”“尚未检查”“未采集过程”“筛选后无匹配”，不统一显示为空白或绿色成功。历史运行和当前工程的导航范围始终明确；不存在的目标保留可读信息并解释无法定位。

定位首先保留原字段草稿，使用现有草稿处置规则处理离开；不能通过跳转悄悄提交 / 丢弃。修复动作显示实际影响，执行前重验目标和修订；失效建议应解释原因，不能操作另一个同名对象。

消息模板、本地化单位和技术详情分开；复制内容带对象、运行及单位上下文。对焦点、选择、诊断与数值来源分别预留表达，不用闪烁、抢焦点或每次弹窗表达普通迭代。

[开发者诊断](developer-diagnostics-and-model-validation.md) 按工程摘要→模型上下文→数值证据→技术详情渐进展开；独立模型 / 物性实验可直接进入。大载荷通过表格、曲线或附件查看，不刷满当前问题区。N0 评审阅读深度与能力缺失路径，具体探针和实验界面随 N2 / N4，尚无新画板。

- D-07：N0 局部画板实施前审定旧底部标签迁移、默认展开与排序、最小窗口宽度、错误 / 空 / 未采集状态，以及原生键盘 / 读屏路径；这些不是已经冻结的坐标与控件。
- 验证见 [S-18—S-22](scenarios-and-acceptance.md#交互与多处联动)。Pencil 检查信息层次，真实窗口检查焦点、草稿、滚动、键盘与高频刷新，两者不能互相替代。
