# 执行追踪与收敛诊断

更新时间：2026-09-23

## 用途与状态

用途：维护真实执行过程、嵌套迭代和采集能力边界。
读者：求解器、运行事件和收敛视图维护者。
不包含：新求解算法、完整性能指标、重启检查点实现。

- 层级：二级功能；父专题为 [运行、消息与诊断](../runtime-messages-and-diagnostics.md)。
- 状态：Draft / 规划方向已确认，细化决策与实现尚待所属切片；现有能力不能直接算作新增要求已验收。
- 范围、依赖与 N0—N5 顺序以父专题为准；[需求追踪表](requirements-traceability.md) 记录要求、阶段、场景及证据。

## 当前基础与用户路径

现有 `SolveSnapshot` / `StepSnapshot` 可复用成功步骤证据，但不能代替开始、失败和终止事件。用户从运行进入执行树，选中步骤查看诊断；循环能力到位后查看对应层级残差，再定位实际变量。

## 执行追踪与收敛观察

执行树由实际运行计划产生：运行→检查→执行组 / 循环→迭代→设备或方程求解→结果校验。单元可以重复执行；设备树、画布树和求解树不要求同构。EO、黑箱和并行执行只暴露所支持粒度，不能强制伪造成按设备串行。

节点按能力提供状态、耗时、工况、输入 / 输出观察值、残差、容差、归一化定义、相关事件与监视入口。现有顺序求解先记录真实步骤，不填虚构迭代数、进度百分比或剩余时间。失败步骤也应留下开始、失败位置及已知上下文，不能只有成功快照才有过程证据。

收敛曲线明确循环 / 内外层、迭代坐标及残差缩放；不同物理量的原始数值不直接比较严重程度。未来显示最难收敛变量和停滞 / 振荡时，必须给判据及适用层级；无判据不把趋势外观当数值结论。

简要 / 正常 / 详细显示与采集级别分开。运行前明确采集范围，事后不能凭空恢复未采集数据。内存有界、界面批量刷新、普通高频 trace 可采样；错误、停止命中、恢复和终止证据不能被静默丢弃。容量或记录失败须报告截断 / 丢失范围，不反过来改变物理求解结论；无记录时不承诺完整复现。

## 事件顺序与观察边界

- 步骤开始与终止记录配对；失败后未进入的步骤显示“未执行”，不伪造开始 / 耗时。重试保留独立尝试身份，与同一对象多次执行区分。
- 事件保留运行内顺序和因果 / 父子关联；未来并行只承诺已知顺序，不靠墙钟排序制造不存在的先后关系。接收重复、迟到、缺段时须有明确处理策略，不重复计数或吞掉缺口。
- 观察值携带变量、单位语义、输入身份、试算 / 接受值及采集位置。残差缺失表示未采集 / 不支持，不能补零；耗时基准与未来仿真时间分别定义。
- 采集和显示订阅有各自容量边界。慢视图不能无限撑大运行内存；关键证据的记录失败应可见。具体背压、落盘和采样策略在 N2 决策，当前不承诺无损无限记录。

算法步长、导数检查、模型调用上下文与结构化大载荷见 [开发者诊断](developer-diagnostics-and-model-validation.md)。它们复用本专题的层级、采集与容量边界；可能增加模型求值的检查作为独立实验，不能暗改正式求解。

## 切片、待决策与最小验证

- N2 先真实顺序步骤运行后审阅，再按后台能力实时显示；N4 接入真实循环、残差和有身份的运行比较；N5 再接真实时间事件。退出依据为 MSG-07—MSG-10。
- D-02：N2 实施前定义事件粒度、运行内序号、重复 / 迟到 / 缺段策略、缓冲上限、背压、记录失败处置和采集档位；容量目标选实际负载测量。
- D-03：N4 实施前由求解领域定义残差、缩放、容差、层级、试算与接受值，以及停滞 / 振荡判据。不能用 UI 趋势代替判据。
- 验证见 [S-07—S-10](scenarios-and-acceptance.md#执行过程)：包括失败步骤、重复尝试、嵌套 / 黑箱能力以及超容量与缺段。
