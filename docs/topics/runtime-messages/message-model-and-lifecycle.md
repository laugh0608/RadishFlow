# 消息模型与问题生命周期

更新时间：2026-10-11

## 用途与状态

用途：维护消息分类、身份、状态转换和多处汇总的唯一语义。
读者：领域检查、应用状态、诊断和消费者维护者。
不包含：具体 Rust 类型、序列化 schema、UI 布局与求解算法。

- 层级：二级功能；父专题为 [运行、消息与诊断](../runtime-messages-and-diagnostics.md)。
- 状态：Draft / 规划方向已确认，细化决策与实现尚待所属切片；现有能力不能直接算作新增要求已验收。
- 范围、依赖与 N0—N5 顺序以父专题为准；[需求追踪表](requirements-traceability.md) 记录要求、阶段、场景及证据。

## 当前基础与用户路径

已有诊断代码、严重程度、对象定位和恢复入口；统一生命周期与跨运行身份仍属规划。用户发现缺项，定位修正并重检；消息从活动转为解决，历史保留发生过程。来源修订与状态分别参与判断，不能靠关闭面板完成修复。

## 信息分类与事实来源

| 类别 | 回答的问题 | 所有权与生命周期 |
| --- | --- | --- |
| 当前问题 | 现在仍缺什么、违反什么或哪里失败 | readiness、模型 / 规格、求解与应用服务产生事实；按输入及运行身份投影活动问题 |
| 过程事件 | 本次发生过什么 | 执行者记录开始、完成、迭代、重试、恢复、停止命中和终止；历史事件不因当前问题消失而改写 |
| 工程检查结论 | 哪个范围通过、未通过或未检查 | 所属领域提供方法、依据、工况与有效性；不能由日志颜色或收敛推导 |
| 应用通知 | 保存、导出等操作是否成功 | 应用操作作用域；导出失败不改成设备求解失败 |

统一语义不等于所有信息进入一个无边界列表。正式来源负责检查和状态变化，消息层索引、关联与呈现；不重算物性、不从自然语言解析动作或收敛结论。工程问题与应用通知明确作用域，开发日志按需进入技术详情，不直接刷满工程问题区。

面向工程 / 模型开发的阅读深度独立于严重程度、阻断性和可恢复性；隐藏技术详情不隐藏影响工程有效性的事实。具体开发上下文、探针与实验要求见 [开发者诊断](developer-diagnostics-and-model-validation.md)，复用本专题身份与生命周期。

### 身份与关联

设计上需要稳定问题身份 / 代码、来源与版本、严重程度、是否阻断 / 可恢复、对象 / 流股 / 端口 / 字段目标，以及文档身份 / 修订、工况、运行、步骤、迭代层级和快照关联；字段按事件类型适用，不要求每条应用通知都伪造求解身份。保留发生顺序与时间，未来动态另有仿真时间，不能用墙钟替代。

消息正文采用可本地化模板与结构化参数；数值、单位和基准来自统一目录，原始技术信息可展开。问题提供说明、影响、证据及定位 / 建议动作。GUI、CLI、后续报告与 Agent 消费同一语义，但外部 DTO 须单独版本化；本轮不改 CLI v1 / v2 或 SI 契约。

### 问题生命周期

- 区分活动、待重检、已解决、已恢复、历史 / 过期；模型更改后按依赖失效，不未经重检自动宣布解决，也不让旧诊断阻断一个无关联的新工程。
- 同一问题在画布、模块和全局仅计一次。重复发生按代码、对象、工况及检查范围等有意义身份聚合，保留次数、首次 / 最近位置和原始事件；不同运行与不同物理问题不按相似文本误合并。
- 迭代中允许恢复的局部失败保留历史；只有执行者确认恢复后才能退出活动问题。致命 / 终止性错误不能为了显示成功被降级，后续未执行步骤明确标“未执行”。
- 已读、收起、过滤、暂不提醒与解决分别管理。它们不解除硬约束、不修改严重程度，不让全局无过滤计数变成零；清空可见日志不清除工程事实或改写运行结论。
- 有明确依赖时，突出导致连锁阻断的问题并折叠受影响对象；无证据只能标可能相关，不把启发式相关性宣称为根因。对象删除后历史仍可辨认，但不跳转到另一个同名对象。

## 运行、数值、结果与问题分维度表达

| 维度 | 规划状态示例 | 约束 |
| --- | --- | --- |
| 运行生命周期 | 未开始、检查中、计算中、正在暂停、已暂停、完成、失败、已取消 | 请求与已生效分开；仅展示执行者支持的状态 |
| 数值结论 | 未判断、满足准则、未收敛、不适用 | 来自实际求解器和判据；已走完步骤不自动证明收敛 |
| 结果可用性 | 无结果、当前完整结果、调试中间值、历史 / 过期 | 数据身份和有效性决定可查询 / 可导出范围 |
| 当前问题 / 检查 | 阻断、错误、警告、无活动问题；未检查 / 不支持另列 | 无活动错误不代表所有工程检查通过 |

可组合显示“计算完成 · 当前结果可查询 · 2 项警告”“R-101 后暂停 · 仅有中间值”“数值收敛 · 设备约束校核未通过”。若称“收敛但有错误”，必须指明错误属于设备检查、应用输出或哪个作用域；本次终止性求解错误不能与本次完整求解成功混成绿灯。汇总按相关问题身份与检查范围生成，不只取全部日志中最高严重程度。

N1 / N2 保持当前 latest-current 快照契约：旧结果不冒充当前结果，运行失败不开放正式结果读取。未来调试中间值需独立入口，标明运行 / 步骤 / 迭代、完整性与有效范围；不混入正常结果表或正式报告，也不以局部成功推导全流程成功。部分结果、历史比较与检查点须在后续切片单独验收。

## 转换责任与实现前约束

下表是要求的细化，不是已发布枚举或状态机 API。严重程度、阻断性和可恢复性分别表达：warning 是否阻断必须由检查策略给出，不能由 UI 颜色决定。

| 触发 | 当前问题的处理 | 历史与关联 |
| --- | --- | --- |
| 来源检查发现问题 | 新建或更新同一检查范围内的活动问题 | 保留发生记录及对应修订 |
| 相关输入改变、Undo / Redo | 标记待重检 / 过期；重新计算是否仍属于当前输入 | 不用正文匹配来迁移身份 |
| 同范围重检明确通过 | 标记已解决 | 保留原问题与解决依据 |
| 执行者确认可恢复失败已恢复 | 标记已恢复 | 失败与恢复事件都保留 |
| 删除对象或切换工程 | 退出不相关的当前投影 | 保留原目标身份，不指向同名新对象 |
| 已读、过滤、清空可见记录 | 不更改工程事实 | 仅变更呈现状态 |

“待重检”不等于已通过：readiness 应由当前检查决定，不可因隐藏旧问题而放行未知状态。重检失败或未完成也不能伪造已解决；具体重检触发与门禁策略见 D-01。

聚合有两个层次：同一工程事实在多个 UI 位置只计一次；同一运行内重复事件可以折叠但保留次数。跨运行对比只能建立显式关联，不合并为一条无来源历史。

## N1 随 A1 的首批细化

2026-10-11 为 [A1 首批](../modeling-assistance-and-specifications.md#a1-首批范围与实现)审定 D-01 必要子集。A1-I1 建立带身份的只读事实报告，I2 在局部 UI 与 Pencil 静态门禁通过后接通问题键、失效、重检及定位；[实现与证据](../modeling-assistance-and-specifications.md#a1-i2-实现与验收状态2026-10-11)不代表完整 N1 或跨端 DTO / 事件模型已交付。

| 项目 | 首批契约 |
| --- | --- |
| 问题键 | 工程 ID + 会话代次 + 规则 ID / 版本 + 检查范围 + 稳定目标引用 + 类型化原因；字段 / 端口区分不同问题，正文和名称不参与键。输入修订属于本次检查证据，不用每次修订生成无法关联的新规则身份 |
| 检查身份 | 每份报告带输入修订与检查代次；真实求解问题另带已有运行 / 快照身份。重开即换会话代次，不能因工程 ID 和修订相同而接受旧回调或建议 |
| 去重与排序 | 同一事实在运行提示、模块及问题入口共享一条记录；沿用确定的规则 / 对象 / 字段顺序。运行错误只有结构化规则 / 目标及来源能对应时才关联，不通过相似文案合并；旧外部首错顺序由兼容投影保持 |
| 失效策略 | 首批采用明确的整份文档检查范围：任意工程输入 / 拓扑修订或 Undo / Redo 使报告待重检，所有旧建议失效；避免未建立完整依赖图时漏失效。语言、显示单位、焦点及过滤不失效工程结论 |
| 重检触发 | 初次打开 / 切换工程、正式提交、Undo / Redo、删除 / 连接变更后及显式运行前同步重检；仅编辑草稿不改变正式报告，运行仍受既有草稿保护。选用物性 / 模型上下文变化即使未增加输入修订，也使对应检查上下文失效 |
| 状态转换 | 发现问题为活动；输入变化为待重检；仅同范围当前检查明确通过才已解决。检查失败保留过期依据和未完成范围，不发布空问题集冒充通过。对象删除退出当前投影并禁止旧定位，同名重建按新身份检查 |
| 不完整检查 | 分开未检查、待运行检查、不支持。待运行检查只限明确由正式执行负责的上下文规则；拓扑 / 必需输入缺失仍阻断。未实现的全局 DOF 不作为当前 SM 的额外门禁，不显示已通过 |
| 运行投影 | 预检已知冲突可显示为当前问题，运行仍在原阶段以共享规则判定；未归一 blocked、连接 / 步骤参数 failed 等旧分类保持。界面不得另设一套与正式入口冲突的“可运行”判断 |
| 存储与副作用 | 当前报告为可重建会话状态；不写项目、sidecar、输入修订或 Undo，不新建历史库。可呈现本会话旧问题的过期依据，不承诺 N2 事件历史 / 持久审计；重开重新分析 |

定位只导航，保留单位草稿并走既有离开保护；建议接受归 A2，N1 不执行领域规则或直接修改参数。暂不提醒 / 已读只影响呈现，全局阻断计数不据此减少。单元来源错误、应用导出失败、求解失败分别归作用域，结果是否 current 继续由原快照契约判断。

报告以已检查范围回答“这些规则是否通过”，不由“无活动问题”推导“全流程可解”。发生两个不同运行的同类错误时只建立关联，不合并其历史事实。首批同步检查不引入后台任务，但入口仍以工程 / 会话 / 修订拒绝不匹配结果，为真实生命周期隔离服务。

验证由 [A1-V10—14](../modeling-assistance-and-specifications.md#a1-首批验收矩阵) 落到 S-02 / 03 / 05 / 19 / 21 / 26 的适用子集；完整多视图迁移、事件重复计数 / 时间、恢复运行和持久历史仍属后续 N1 / N2，不能用本批替代完整 MSG 验收。

I2 的会话所有者为 GUI `ReadyAppState` 中的 `ModelingProblemsState`；同一会话供当前问题与 Run Panel 使用。当前规则只读工程，现有组分 / 物性包选择通过正式输入修订触发重检；未来引入不增加修订的外部检查上下文时，必须补入失效身份，不能复用旧结论。检查目前同步执行，代次拒绝机制以自动测试验证，不宣称新增后台回调。

当前运行诊断没有完整的 A1 规则身份，因此保留独立的“运行诊断详情”，不将其加到规格问题计数或模糊关联；原 Inspector 的运行诊断和画布标记仍各守来源。已解决 / 目标移除仅展示本次检查变化，未完成范围的旧依据继续保留；不会写入项目或 sidecar，也不提供已读 / 忽略 / 历史管理的新动作。

## 切片、待决策与最小验证

- N0 评审四类信息、独立状态维度和代表组合；N1 实现当前问题闭环，N2 / N3 再接入真实运行事件。退出依据为 MSG-01—MSG-06。
- D-01：在 N1 实施前定义问题键、检查范围 / 版本、失效依赖、重检触发和阻断策略；同时明确无结果、待重检、未执行的结构化表达。
- 验证见 [S-01—S-06](scenarios-and-acceptance.md#消息与生命周期)：活动 / 解决 / 恢复、删除和同名重建、Undo / Redo、过滤、重复发生及状态组合。应断言来源身份与门禁，不只断言文案。

A2 首批动作与忽略 / 预览 / 接受生命周期已于 2026-10-11 获审定，真相源见[建模辅助方案](../modeling-assistance-and-specifications.md#a2-首批实施方案2026-10-11已审定)。I1 应用基础、I2 接线及 I3 自动 / macOS 代表验收已完成；问题详情、建议区和画布共享同一推荐会话，旧接受命令先打开预览，正式事务成功与重检结果分别返回。A1 问题计数和结果门禁不因忽略或动作已执行而减少 / 放行；完整 N1 与 I5 未验项保持。
