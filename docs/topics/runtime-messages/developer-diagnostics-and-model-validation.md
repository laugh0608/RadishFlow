# 开发者诊断与模型验证

更新时间：2026-09-23

## 用途与状态

用途：定义算法、单元模块、物性及扩展开发所需的诊断证据、分层阅读和对照验证路径。
读者：数值算法、设备模型、物性方法 / 参数、插件和自动化维护者，以及编写自定义模型的工程师。
不包含：另一套消息生命周期、求解算法或参数回归实现、通用源码调试器、已发布插件 SDK、冻结接口 / 文件格式及工业准确性证明。

- 层级：二级功能；父专题为 [运行、消息与诊断](../runtime-messages-and-diagnostics.md)。
- 状态：Draft / 2026-09-23 方向已确认；新增范围待实现、待验证，接口与载荷按切片审定。
- 需求及证据唯一入口为 [MSG-28—MSG-33 / D-11—D-12](requirements-traceability.md)，验收见 [开发者诊断场景](scenarios-and-acceptance.md#开发者诊断与模型验证)。不改变 U2 优先级，不要求完整调试器作为模型开发前置。

## 当前基础与用户路径

已有诊断代码、对象关联、恢复动作和步骤快照可复用；尚无本专题定义的完整调用证据、开发诊断视图、参数对照实验或诊断包。内部日志存在不等于这些要求已验收。

用户从工程问题或独立模型 / 物性测试进入，选择调用及输入版本，逐层查看模型上下文和数值证据，提出修改，再在可比条件下运行新实验。原记录保留，比较说明改动、改善与退化；必要时按明确范围导出复现材料。独立物性 / 模块测试不必伪造流程图对象或正式流程运行。

## 消费者与事实边界

工程视图、模型视图、数值详情与实现日志是按任务选择的阅读深度，不是固定人员权限或新的严重程度。对象问题、运行事件及工程检查仍采用 [消息模型](message-model-and-lifecycle.md) 的分类、身份和生命周期；开发详情通过运行 / 实验、调用及父子关联挂接，不从文本重新推导状态。

- 同一物性失败可在工程视图说明影响，在模型详情显示输入与方法，在数值详情显示采集到的迭代，在技术详情显示实现版本与异常信息。各视图引用同一证据，不分别产生一条冲突的工程事实。
- 面向对象、严重程度、阻断性与可恢复性分别表达；日志 Debug 等级不等于“只影响开发者”。模块返回非有限值、违反接口契约或导致结果无效时，负责该契约的领域 / 执行方须产生可见诊断，工程视图保留影响；关闭开发详情不得解除门禁。
- 开发日志用于排查实现细节，不能作为正式收敛、生命周期或结果资格的唯一来源。推测的原因与已确认的失败位置分开；无法识别根因时保留证据，不生成确定性解释。
- 插件或第三方只暴露其声明的能力；内部迭代、导数、调用栈不可获得时明确未采集 / 不支持。外部 DTO、授权和数据暴露按 [跨端消费](records-storage-and-consumers.md) 审定，不把内部对象图或源码位置变成稳定 API。

## 开发场景与按能力提供的证据

| 场景 | 需要回答的问题 | 诊断证据与边界 |
| --- | --- | --- |
| 算法开发 | 哪一层停滞、步骤为何拒绝、按什么条件终止 | 迭代层级、残差 / 缩放、容差、步长或阻尼、接受 / 拒绝原因、初始化及线性求解状态；具体字段由算法声明，不伪造通用收敛指标 |
| 单元模块开发 | 规格、方程、接口与收支是否一致 | 端口 / 输入输出契约、规格模式、方程与变量身份、有效范围、初始化顺序及有定义的守恒残差；没有方程结构时不冒充已完成结构自由度分析 |
| 物性方法与参数调整 | 差异来自数据、物理方法还是数值求解 | 组分与相、状态条件、组成基准、方法 / 参数集身份与版本、参考态、适用范围、闪蒸层级及导数来源；未知信息如实标明，不给缺失参数隐式默认值 |
| 插件与集成开发 | 失败发生在哪个边界，返回值是否有效 | 实现 / 插件版本、调用关联、能力声明、输入输出校验、异常映射与耗时；第三方原始信息可展开，COM 语义仍留在适配层 |

调用证据关联有效输入、实现 / 数据版本、方法与计算设置、开始 / 终止、子调用和已知输出；字段按实际调用适用。重试、同一模块重复执行和不同实验有独立身份。独立测试任务使用自己的上下文，可在以后关联工程运行，不强制每次调用都携带不存在的设备身份。

## 诊断数据与采集

残差序列、变量 / 方程表、参数差异和大型矩阵分别按数据组织；消息提供摘要与证据引用，不将全部载荷序列化成长正文。大载荷按需采集 / 导出，具体限额、截断、保留及失败行为复用 [执行追踪](execution-trace-and-convergence.md) 与 [记录存储](records-storage-and-consumers.md)，不得新增无界缓存。

开发探针按计算领域声明能力和采集粒度；普通观察不修改输入、算法容差、物性选择或随机状态。可能额外调用模型的导数检查、扰动试算和对照实验作为显式独立任务，采用独立输入 / 状态，不能悄悄插入正式求解并改变其行为。线程时序、性能开销及适用范围须测量，不能承诺开启诊断后逐位一致。

导数检查说明被微分变量、固定条件、偏导 / 全导数含义、解析 / 自动微分 / 数值方法及扰动尺度。有限差分是对照方法之一，受步长、精度与非光滑或相边界影响；差异不能直接证明某一实现错误。矩阵秩 / 条件估计和病态判断也需给出方法与阈值，缺能力时不输出伪精确数字。通用残差、试算 / 接受值及层级语义仍归执行追踪专题。

## 可比较的模型实验

对照记录由相应模型 / 参数回归任务计算，消息系统只关联异常、事件和结果。新旧方法或参数集作为独立版本运行，不覆盖原证据；记录有意改变的因素及其他差异，不把混合变更归因于单个参数。

- 对齐输入、组分顺序与组成基准、相定义、参考态、模型 / 数据版本、求解设置及目标量；不兼容时展示差异和限制，不能直接给误导性的数值改善结论。
- 指标说明公式、权重、尺度、容差和数据来源。参数拟合区分用于拟合与独立验证的数据；没有独立数据时说明证据范围。拟合误差降低不代表外推或其他性质必然改善。
- 比较同时保留成功、失败、不支持、缺数据和适用范围变化，显示原可收敛工况的退化；只对双方支持且可比的部分形成指标，报告覆盖范围。
- 验证依据可来自解析案例、独立实现、公开数据或实验 / 供应商资料，但需分别说明独立性、精度与适用条件。复用同一实现生成期望、仅看日志无错误或仅与另一软件一致，都不能代替物理准确性验证。

## 诊断包与复现

诊断包按选定运行 / 实验及调用范围组织输入、设置、版本、事件与已采集载荷，并列出文件清单、完整性及缺失项。具体格式、校验方式与兼容策略在实施前审定；导出行为遵循 [MSG-27](requirements-traceability.md)，不在此复制存储或协议规则。

外部物性包、专有数据或环境不能随包提供时，列明依赖与复现限制；匿名化 / 删减影响复现时明确标记。导出预览范围，不自动上传或附带无关凭据。包内原始数据与调试值不自动获得正式报告资格；仅有记录不承诺检查点恢复或逐位重现。

- D-12：在首个比较 / 开发诊断包实现前定义可比条件、指标与独立预期、数据版本、载荷和依赖清单；存储 / 外部兼容分别衔接 D-08 / D-09，数值判据衔接 D-03。
- 验收按 S-28—S-33 分阶段记录；先覆盖契约失败与基础调用，不以合成 trace 证明真实算法集成，不把文档评审写为开发工作台已交付。
