# 消息系统场景与验收矩阵

更新时间：2026-11-26

## 用途与状态

用途：把需求变成可观察、可回归的行为场景。
读者：实现者、测试者、设计评审者和后续协作者。
不包含：虚构的测试通过证据、独立需求状态副本与数值准确性证明。

- 层级：二级功能；父专题为 [运行、消息与诊断](../runtime-messages-and-diagnostics.md)。
- 状态：Draft / 规划方向已确认，细化决策与实现尚待所属切片；现有能力不能直接算作新增要求已验收。
- 范围、依赖与 N0—N5 顺序以父专题为准；[需求追踪表](requirements-traceability.md) 记录要求、阶段、场景及证据。

## 当前基础与验证策略

场景表给出操作与独立预期。已完成的切片在相应验收段链接测试和实窗记录。每次实施从追踪表选择涉及要求，先补适用输入与独立预期，再记录实际命令 / 测试位置、平台、日期与结果。

单元测试验证身份、状态、单位及规则；集成测试验证事件、事务、保存和消费者边界；Pencil 评审信息层级，已告知的原生实窗验证焦点、滚动、键盘和读屏。无后台 / 循环 / 动态能力时，只能验证已具备层级，不以模拟事件测试宣称真实求解集成完成。

| S-02 / MSG-02 | 重复检查同一对象，再检查同名不同身份对象并切换语言 | 同范围去重；不同目标不误合并；代码及定位不随文案改变 |

### S-09 固定温压单撕裂回流

下表为 Studio 固定温压回流首批的验收标准。两例绝对容差均为 1e-10 mol/s，缩放容差均为 1e-10（无量纲）。表中读数为简写，判断使用报告原值。[两份 CLI 报告](../../devlogs/2026-11/2026-W48.md#2026-11-26-d-03-固定温压回流报告对照) · [界面改动范围](execution-trace-and-convergence.md#s-09-界面改动范围)

| 操作与位置 | 用户应能读出的结论 |
| --- | --- |
| 0.90，在结果区打开回流块 | 迭代 228 的最大绝对残差 1.03384e-10 mol/s 超限，缩放值 2.06768e-11 达标。迭代 229 的 9.30456e-11 mol/s 和 1.86091e-11 首次同时达标，成为候选。复核 1 的 8.37375e-11 mol/s 和 1.67475e-11 均达标，运行最终为 Current。 |
| 在复核详情核对乙烷，再定位流股 | 乙烷假设入口与返回出口常规显示均约 25.2 mol/s，展开精确值可复算 +8.373746140932781e-11 mol/s；尺度为 5 mol/s。正式流股入口定位本次快照的 `s-recycle`，总流量为 44.99999999865418 mol/s。迭代 229 只有汇总，组分明细标明未采集。 |
| 0.99，直接查看失败详情 | 默认可见最后试算 500、复核未执行、本次无正式结果。末次两项分别为 0.01839735 mol/s 和 0.00367947，均超限；展开后用乙烷差值除以 5 mol/s 可复算缩放值。可定位 `s-recycle` 排错。展开完整轨迹才出现 500 个样本。 |
| 运行条在复核开始时刷新 | 对照 0.90 检查点，正在执行为「独立复核 1」，最近完成为「迭代 229」；复核完成才可将其读数标为「独立复核 1」。进度合并允许跳过中间帧。 |

交互验收需用中英文、400 点窄区及大字号检查数值、单位、容差和文字结论可读，Tab／Enter 可展开明细及轨迹。切换工程、改变输入或重跑后，旧行的结果入口须重检来源和资格。[可操作交互稿](../../architecture/designs/reviews/2026-11-26-studio-s09-recycle-residuals/README.md)已核对两例的代表读数、键盘操作和来源变化。获认可的三处交互已接入 Studio，两份工程的[macOS 实窗验收记录](../../devlogs/2026-11/2026-W48.md#2026-11-26-s-09-studio-回流残差实窗验收)包含真实运行读数及验证条件。

| S-17 / MSG-17 | 对照墙钟、仿真时刻、结果回放与兼容 / 不兼容检查点 | 真实时间与回放分开；观察记录不宣称可重启；黑箱恢复能力明确 |

### N3 无回路稳态首批验收

D-04 首批针对 Studio 可编辑工程的无回路稳态计划。双进料 Mixer 使用 N2 已核对的 2 和 3 mol/s。先由普通运行得到 5 mol/s 的 Current，再用同一工程显式启动「运行并在首步前暂停」。后台测试以握手控制先后顺序，原生窗口使用产品入口，避免用延时猜测停点。

| 场景 | 操作与独立预期 |
| --- | --- |
| S-11 停点确认 | 首次确认前显示正在暂停；首步前为 0/3。另用可阻塞的单元调用发起普通运行，在调用中请求暂停并暂缓 UI 读进度。释放后成功则停在下一单元前，失败则保留下层错误。取消先到时仍能唤醒。 |
| S-12 单步边界 | 连续两个停点依次为第二股 Feed 前 1/3、Mixer 前 2/3。每次放行后用求解事件核对恰好新增一个开始和完成。对同一停点重复单步、晚发继续或来自旧菜单的动作均不多走一步。从 Mixer 前继续及单步末项分别得到 5 mol/s，新运行只被接收一次。 |
| S-12 终态与结果 | 第二股缺乙烷时单步该股，保留第二步失败及准确流股组成目标，Mixer 未开始。另在第二步前取消，旧 Current 仍归前次运行。交换最后完成与暂停／取消的先后，执行终态和接收处置分别与真实次序一致。覆盖零可执行步或未形成计划、首步前取消、故障与通道断开。 |
| S-13 资格与文档生命周期 | 暂停时编辑草稿、切语言或看历史后可回原停点。提交第二股为 4 mol/s 后立刻发送旧继续，即使尚未轮询也须拒绝并唤醒。旧结果按修订失效，重新运行得到 6 mol/s。另覆盖修改计划再撤销、撤权、打开失败、切换／重开、只读覆盖和确认关闭。关闭后返回不会重启已取消任务，join 后才能再次受理。 |
| S-11—13 UI 与能力 | 在活动栏和键盘命令面板对准同一运行及停点；用户查旧记录时能分辨当前结果归属。检查 400 px、中英、大字号下控件可达；不支持的计划或任务无法放行，包括同用序贯求解器的 SinglePhase。普通 Run／F5、自动运行、CLI 和 FFI 沿原基线回归。 |

[后台竞争测试](../../../apps/radishflow-studio/src/workspace_run_owner/tests/unit_control.rs)使用通道控制数值调用的先后。[Studio 回归](../../../apps/radishflow-studio/src/studio_gui_shell/tests/background_run.rs)覆盖重复起跑、旧命令、键盘与计划能力。macOS 实窗已核对三处停点、旧结果归属、失败、切工程、编辑和关闭，见 [W48](../../devlogs/2026-11/2026-W48.md#2026-11-25-n3-无回路单步产品验收)。Windows、Linux 原生窗口与实际读屏仍待复核。

### N4 出口温度监视首批验收

以下是[已确认 D-05](run-control-and-watch-conditions.md#d-05-无回路稳态出口温度监视提案)的实施判据。使用仓库的[双进料 Mixer → Flash 工程](../../../examples/flowsheets/feed-mixer-flash-binary-hydrocarbon.rfproj.json)，监视 `mixer-1.outlet` 对应的 `stream-mix-out`。两股流量为 2、3 mol/s，第一股为 300 K。本例 Mixer 按流量加权，独立预期为 `(2 × 300 + 3 × T_B) / 5`。工程模板始终为 300 K。下表的出口数值已经普通 CLI 求解复核。macOS Studio 实窗核对了临界值、停点、末步命中和上游失败。成功步骤的缺流股或无效温度由后台故障注入覆盖。[产品验收记录](../../devlogs/2026-11/2026-W48.md#2026-11-25-n4-出口温度监视产品验收)

| 第二股温度 K | 出口求解值 K | 按「出口 > 38.85 °C」运行的预期 |
| ---: | ---: | --- |
| 300 | 300 | 未命中，正常结束 |
| 319.999999 | 311.9999994 | 未命中，正常结束 |
| 320 | 312 | 与阈值相等，正常结束 |
| 320.000001 | 312.0000006 | 命中，在第 4 步 `flash-1` 前停下。与上一行显示为两位小数时相同 |

| 要求 | 操作与独立预期 |
| --- | --- |
| S-14 单位与来源 | 同一工程分别输入 38.85 °C、312 K，切换显示单位并重跑四组工况。逐项核对上表。另以第二股 320 K、阈值 35 °C 验证明显越界。停点显示已完成 3/4、Mixer 出口的本步实测值、Flash 尚未开始。比较一次继续与一次单步末项，两次均与普通求解得到相同的出口值及流量。 |
| S-15 配置与缺值 | 无快照时可选择已连接的出口。分别重连、删除再同名重建目标，输入温差单位、NaN、非正 K，或提交多条规则，均应在受理前返回原因。另在后台测试注入成功步缺流股、非有限温度，核对源步和「监视值不可用」，后继单元未开始、旧 Current 归属保持。对上游模型失败核对原诊断。 |
| S-16 一次求值与终态 | 隐藏日志、Ready 放行后暂缓 UI 轮询，或将步骤明细截断，命中与步序一致。已请求手动暂停或正在单步时命中，只确认一个停点。重放旧继续不得多走一步。改为监视末步 Flash 的气相出口，阈值 25 °C，本例 300 K 命中并正常结束，停点数为零。 |
| S-13／16 结果隔离与入口 | 先普通运行得到 Current，再显式带规则运行。停点取消保留上次结果。正式改输入后旧结果过期，旧命令不能继续。重新显式带规则运行方可再度命中。核对重复提交、编辑中的规则草稿、普通 F5、自动运行、只读及其他计划的入口。 |

### 测试层次与退出证据

1. **AF3a**：纯状态 / 事务测试使用可控执行器和精确顺序，不用固定 sleep 赌竞争；可越过调度注入 A / B 乱序回包检验守卫，生产单 worker 配额仍禁止同时执行 A / B；验 AF3-V01—04 的身份 / 接收部分，以及 V08 / V11 的领域隔离。原设备迟到回归继续保留，新增流程对称案例；无线程通过不代表停止或回收已实现。
2. **AF3b**：用 barrier / latch、注入加载器与失败 worker 精确覆盖 V04—07、V09—10、V12；验证跨线程类型满足实际 Send 要求、单槽配额、Ready 取消和终态回收。另走真实顺序求解与 AF2b 包装配，不能只用假结果证明后台链路。
3. **AF3c**：连接设备命令、局部 UI 及生命周期，覆盖 V08、V10—14 的产品部分；保留保存失败、未知 v3 只读、设备矩阵 / 采纳 / 导出、headless 与 FFI 的既有回归。跨 crate 收口执行 `./scripts/check-repo.sh`，随后记录 macOS Home / Workbench / Equipment、运行中编辑 / 切换 / 取消 / 退出代表证据。
4. **响应性建议目标（待确认，不是已测性能）**：受控长任务阻塞 worker 2 秒时，GUI 仍可连续重绘和编辑；纯调度测试在一次事件 drain 内返回提交 / 取消回执。macOS 指定机器与构建做 20 轮代表操作，记录从输入到回执呈现的时延，目标 p95 ≤ 250 ms；不把取消实际生效时间或原生 picker 模态等待计作可保证的 UI 回执时延，另记录安全点返回延迟。超标先定位，不静默放宽门槛。
5. **资源建议目标**：V12 的计数上限是硬门禁；内存记录运行前后及峰值、worker / 句柄 / 缓存 guard 数量回归，核对无持续增长。输入和最终求解结果规模另按已有模型容量，不用 OS RSS 恰好归零作为释放判据；不宣称全平台固定内存字节上限。
6. **保留未验项**：Windows / Linux 原生组合、I5 与 PME 按既定节点补验并明确记录；没有改变 C ABI 也仍需保留其回归，macOS 通过不替代其他平台。AF1 若仍触发原生面板异常，应独立记录现场，不把 AF3 的后台完成当作 AF1 修复证明。
