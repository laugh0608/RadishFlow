# 消息系统场景与验收矩阵

更新时间：2026-10-24

## 用途与状态

用途：把需求变成可观察、可回归的行为场景。
读者：实现者、测试者、设计评审者和后续协作者。
不包含：虚构的测试通过证据、独立需求状态副本与数值准确性证明。

- 层级：二级功能；父专题为 [运行、消息与诊断](../runtime-messages-and-diagnostics.md)。
- 状态：Draft / 规划方向已确认，细化决策与实现尚待所属切片；现有能力不能直接算作新增要求已验收。
- 范围、依赖与 N0—N5 顺序以父专题为准；[需求追踪表](requirements-traceability.md) 记录要求、阶段、场景及证据。

## 当前基础与验证策略

现有测试与实窗记录继续作为回归基础；下表均是新增规划的待执行场景，不是通过记录。每次实施从追踪表选择涉及要求，先补适用输入与独立预期，再记录实际命令 / 测试位置、平台、日期与结果。

单元测试验证身份、状态、单位及规则；集成测试验证事件、事务、保存和消费者边界；Pencil 评审信息层级，已告知的原生实窗验证焦点、滚动、键盘和读屏。无后台 / 循环 / 动态能力时，只能验证已具备层级，不以模拟事件测试宣称真实求解集成完成。

## 切片评审与退出

- N0：审阅分类、状态组合、工作台与消息 / 单位 / 颜色叠加路径，保留待决策清单；不把画板通过当作产品实现。
- N1—N5：逐项执行本切片适用场景；跨阶段要求拆记已覆盖与未覆盖部分，不能因前半段通过把整项标为已验证。
- 旧 SI CLI、当前结果门禁、输入事务 / Undo、保存重开和既有诊断恢复按影响面回归。新增风险和平台差异必须留证据。
- D-10：各切片实施前选择测试载荷、可接受时延 / 内存指标、平台及辅助技术，建立可重复条件；本规划不编造已测性能数字。
- 新缺陷先关联既有要求 / 场景；确属新行为时新增编号。回归失败或语义改变应撤销相应验证结论，保留历史证据。

### 测试层次与退出证据

1. **AF3a**：纯状态 / 事务测试使用可控执行器和精确顺序，不用固定 sleep 赌竞争；可越过调度注入 A / B 乱序回包检验守卫，生产单 worker 配额仍禁止同时执行 A / B；验 AF3-V01—04 的身份 / 接收部分，以及 V08 / V11 的领域隔离。原设备迟到回归继续保留，新增流程对称案例；无线程通过不代表停止或回收已实现。
2. **AF3b**：用 barrier / latch、注入加载器与失败 worker 精确覆盖 V04—07、V09—10、V12；验证跨线程类型满足实际 Send 要求、单槽配额、Ready 取消和终态回收。另走真实顺序求解与 AF2b 包装配，不能只用假结果证明后台链路。
3. **AF3c**：连接设备命令、局部 UI 及生命周期，覆盖 V08、V10—14 的产品部分；保留保存失败、未知 v3 只读、设备矩阵 / 采纳 / 导出、headless 与 FFI 的既有回归。跨 crate 收口执行 `./scripts/check-repo.sh`，随后记录 macOS Home / Workbench / Equipment、运行中编辑 / 切换 / 取消 / 退出代表证据。
4. **响应性建议目标（待确认，不是已测性能）**：受控长任务阻塞 worker 2 秒时，GUI 仍可连续重绘和编辑；纯调度测试在一次事件 drain 内返回提交 / 取消回执。macOS 指定机器与构建做 20 轮代表操作，记录从输入到回执呈现的时延，目标 p95 ≤ 250 ms；不把取消实际生效时间或原生 picker 模态等待计作可保证的 UI 回执时延，另记录安全点返回延迟。超标先定位，不静默放宽门槛。
