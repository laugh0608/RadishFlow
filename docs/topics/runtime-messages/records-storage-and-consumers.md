# 记录存储与跨端消费

更新时间：2026-09-23

## 用途与状态

用途：维护消息证据、配置、呈现偏好和外部消费者的所有权与兼容边界。
读者：应用任务、项目存储、CLI、适配层和未来自动化维护者。
不包含：具体数据库 / 文件格式、远端服务、认证实现与当前协议变更。

- 层级：二级功能；父专题为 [运行、消息与诊断](../runtime-messages-and-diagnostics.md)。
- 状态：Draft / 规划方向已确认，细化决策与实现尚待所属切片；现有能力不能直接算作新增要求已验收。
- 范围、依赖与 N0—N5 顺序以父专题为准；[需求追踪表](requirements-traceability.md) 记录要求、阶段、场景及证据。

## 当前基础与用户路径

工程存储和当前快照规则、CLI v1 / v2 最终响应继续有效；尚无本专题的新历史库或实时订阅协议。未来用户保存监视规则、查看某次运行证据、选择范围导出，重开后重新检查当前工程，而不是复活内存任务。

## 存储、消费者与架构边界

- 求解与模型提供诊断 / 执行事实，应用运行层拥有任务身份、事件关联与控制请求，消息查询层投影当前问题和历史；GUI 不通过字符串推导控制或工程状态。模块位置及 DTO 在实施切片决定，不新增空管理框架。
- 项目可复用的监视规则拟归运行配置，执行时捕获规则版本；视图筛选、展开与跟随属于呈现偏好。运行记录和调试观察值属于运行证据，不按每条消息修改工程文档、计算修订或 Undo 历史。具体保存方式、脏标记、保留期限与迁移由 N2 / N3 和 [存储专题](../project-lifecycle-storage.md) 审定。
- 旧工程无监视配置保持原行为；重开不自动恢复内存暂停运行，历史问题不能直接作为当前检查结论。目标删除 / 变更、未知规则版本不静默忽略，须保留信息并明确不可用。
- 现有 CLI v1 / v2 仍为一次请求最终响应；未来实时订阅、运行控制和历史导出单独设计版本 / 能力协商，不往现有 stdout JSON 中插入过程文本。Rust Core 不引入 COM，适配层映射诊断并保留第三方能力限制。
- 未来 Agent 使用同一变量、事件、问题与正式动作；当前只建设确定性消费者，不接入大模型。诊断导出应明确数据与技术详情范围，不能顺带导出认证令牌等无关敏感信息。

## 所有权与一致性核对

| 数据 | 事实来源 / 建议归属 | 生命周期要求 |
| --- | --- | --- |
| 当前问题投影 | 检查与执行事实 | 可以重建，重开后不直接信任旧结论 |
| 执行事件与观察值 | 运行证据 | 标识采集范围与缺段，按保留策略管理 |
| 监视规则 | 拟归工程运行配置 | 稳定目标 / 单位身份和版本；执行捕获当时规则 |
| 过滤、展开、跟随 | 呈现偏好 | 不修改工程事实与求解修订 |
| 可恢复检查点 | 后续求解 / 任务能力 | 独立兼容与恢复验证，不从观察值推导 |

规则本身的修改、运行证据写入与视图偏好变化不能共用一个模糊的“工程已修改”事件。具体脏标记及保存策略由存储专题与 D-08 决定；不在此提前规定文件格式。

导出说明当前 / 历史、完整 / 截断、已采集字段及数值单位；技术详情按所选范围输出。复现还依赖输入、模型 / 物性与算法版本，只有日志不能保证完整复现。未来订阅若支持续传，须明确游标、缺口、重复事件和版本不支持时的行为，不靠解析文本补偿。

[开发诊断包](developer-diagnostics-and-model-validation.md#诊断包与复现) 复用本专题保存、导出与兼容规则，额外明确实验 / 调用范围、依赖清单及可比条件；D-12 衔接 D-08 / D-09，不另立历史库或默认外传路径。

## 切片、待决策与最小验证

- N1 先保证身份隔离与当前语义；N2 审定运行记录；N3 / N4 审定规则保存、控制和消费者版本；N5 再检查点。退出依据为 MSG-23—MSG-27。
- D-08：N2 首次持久化前确定记录格式 / schema、容量、保留 / 清理、写入失败和工程保存独立性；N3 / N4 保存规则前确定脏标记、迁移与未知规则往返策略。
- D-09：新外部协议实施前确定 DTO / 能力版本、订阅顺序 / 续传、控制权限边界和兼容验证；当前 CLI stdout 不插入事件流。
- 验证见 [S-23—S-27](scenarios-and-acceptance.md#存储与消费者)：旧工程、未知规则、规则版本、损坏 / 缺段记录、导出资格及 GUI / CLI 一致性。
