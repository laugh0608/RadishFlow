# 单位系统与输入显示

更新时间：2026-09-17

## 用途与状态

用途：定义量与单位元数据的唯一真相、统一转换、单位集、输入显示和跨消费者验收。
读者：维护变量元数据、Core、Studio、存储、自动化和结果输出的协作者。
不包含：完整行业单位目录、尚未实施的项目呈现 schema、物性计算实现和完整报告系统。

- 层级：一级轨道；上位规划：[模拟平台](../architecture/simulation-platform.md)。
- 关联：[变量与动作](studio-main-workflow.md)、[结果](results-review-diagnostics.md)、[存储](project-lifecycle-storage.md)、[单位参考](../reference/units-and-conventions.md)。
- 状态：Active / U1 定义、转换与首批变量元数据接入已实现；U2 单位集、字段交互和偏好持久化尚未实现。

## 目标与当前基础

2026-09-16 确认单位系统为核心基础能力。核心数值保持 SI；GUI、变量树、CLI、导出、报告及未来 Agent 共用量与单位定义及转换方法。支持固定显示单位下切换显示并换算数值，也支持输入时临时选择单位、提交后回到显示单位。

当前 SI 字段、正式输入事务和变量描述保持。U1 新增 `rf-types::units`，变量浏览元数据改为引用量类型并派生规范单位；GUI 浏览器和 CLI 标签消费该目录。其他 Inspector / 结果表的既有 SI 标签在 U2 / U3 逐步接入，不声称全界面已支持切换。CLI v1 / v2 仍只接受对应字段的 SI 数值，JSON 字段和数值解释均不变。

## 唯一真相与职责

| 所有者 | 内容 | 消费方式 |
| --- | --- | --- |
| 量与单位定义 | 稳定量 / 单位 ID、量纲、物理语义、规范单位、符号、别名与转换规则 | 全部消费者引用同一份定义；本地化标签不作为身份 |
| 变量元数据 | 所属物理量、质量 / 摩尔等基准、约束、可用单位及来源 | 引用量和单位 ID，不复制转换系数；同量纲不自动等于同语义 |
| 单位集 | 各物理量默认显示单位与格式；内置集及后续自定义集 | 只选择已有定义，不另存系数；解析出唯一有效选择 |
| 统一转换服务 | 兼容性、转换、上下文要求与结构化错误 | GUI、自动化、导出、报告共用，无控件或模板私有公式 |
| 工程值与呈现 | 已提交 SI 值、编辑草稿、显示格式及偏好 | 工程值与显示值分离；结果转换不重新执行物性或求解 |

U1 将单位基础放在已有 `rf-types::units` 模块，不新增 crate 或依赖。编译期固定目录拥有定义；`QuantityKind` 表达语义，`MeasurementUnit` 表达计量单位，与设备 `UnitId` 分开。稳定字符串 ID 不依赖枚举序号或本地化符号；元数据引用量类型，规范单位、可用单位和符号从同一目录派生。新增定义须验证身份、别名歧义、量纲和系数；物性资产或插件不能静默覆盖核心定义。

## 转换契约

普通线性 / 仿射单位采用 `q_SI = X_u * q_u + C_u`；反向为 `q_u = (q_SI - C_u) / X_u`。a 到 b 经规范单位计算，不维护所有单位对的转换表。

| 语义 | 单位 | 规范单位 | X | C |
| --- | --- | --- | --- | --- |
| 绝对温度 | °C | K | 1 | 273.15 |
| 温差 | °C | K | 1 | 0 |
| 绝对压力 | bar | Pa | 100000 | 0 |
| 摩尔流量 | kmol/h | mol/s | 1000/3600 | 0 |

上表为目录中的代表规则，首批目录见下节；X 必须为正有限值，C 为有限值，当前通过常量求值校验。绝对温度、温差与复合单位中的温度因子分别处理；不能把绝对温度的偏移施加到热容或传热系数。单位转换后再按领域检查物理值合法性；非法单位、非有限输入、溢出和不兼容量均明确拒绝。转换精度与显示有效位数分别定义，显示舍入值不反写核心。

以下属于需要上下文的基准转换，不能只凭固定 C / X 猜测：

- 表压 / 绝压：显式参考压力，不默认把所有工况的大气压力固定为同一常数。
- 质量 / 摩尔流量及组成：所需组分、组成与摩尔质量必须完整；不静默归一化或改变现有组成提交契约。
- 标准 / 实际体积流量：明确温压、组成、相及采用的状态关系；`Nm³` 等符号本身不足以唯一确定基准。
- 焓熵参考态变更：交由对应物性能力，不能当成能量单位缩放。

首版不交付上述完整上下文转换，但必须能明确拒绝并说明缺少条件；其未来实现仍经同一入口分派。参考态变化、参数物理解释变化属于工程语义变更，与纯显示切换区别管理。

## U1 实现范围与调用

| 量语义 | 规范单位 | 支持的其他表示 |
| --- | --- | --- |
| 绝对温度 | K | °C |
| 温差 | K（独立计量单位 ID） | °C（零偏移） |
| 绝对压力 | Pa | kPa、MPa、bar |
| 摩尔流量 | mol/s | kmol/s、mol/h、kmol/h |
| 组分摩尔分率 / 摩尔相分率 | mol/mol | mol%；两种量语义独立，复用单位定义 |
| 摩尔焓 | J/mol | kJ/mol；只做尺度转换，不改参考态 |

目录共 7 类量、16 个可换算单位身份，另识别 3 个上下文单位身份用于拒绝诊断。温度和温差共享符号但身份、可用单位及偏移规则不同；同量纲不自动允许转换。`bar(g)` / `barg`、`kg/s`、`Nm³/h` / `Nm3/h` 分别提示参考压力、混合物摩尔质量、标准体积基准与状态关系；目前无上下文执行 API，不把“识别”标为“支持计算”。其他未登记单位返回 UnknownUnit。

- `resolve_unit(quantity, token)`：按量语义解析稳定 ID、符号或登记别名；大小写敏感，忽略两端空白，不猜缩写。歧义与不兼容量明确报错，支持菜单只使用 quantity.definition().units。
- `convert(value, quantity, from, to)`、`to_canonical`、`from_canonical`：共享转换入口。拒绝非有限值及规范 SI 中间值 / 输出溢出；相同单位也先验证语义和有限性，然后原样返回，避免无意义往返引入精度损失。
- 转换不舍入显示位数，不读取或改变文档、历史、物性或快照。物理正值、组成范围等由正式变量约束 / 写入事务在转换后校验；负 K 可以被数学转换得到，但不能借转换绕过输入检查。
- `VariableField::quantity` 拥有字段到量的映射，`VariableDescriptor::canonical_unit` / `unit_symbol` 从目录派生；名称字段没有物理量。原描述符的独立 unit 字符串已移除，内部消费者已迁移，CLI 仍输出原 unit 字符串，不新增协议字段。

这不是自动单位输入功能；当前实际消费者先接通元数据和标签。非 SI 编辑、显示、保存恢复和现有导出转换分别在 U2 / U3 落地。

## 显示偏好所有权与兼容设计（U2 待实现）

U1 确定以下边界，具体 DTO、版本迁移和交互在 U2 审定 / 实现；当前不新增持久化字段或空状态模块。

| 状态 | 所有者与持久化方向 | 生效规则 |
| --- | --- | --- |
| 项目显示单位集 | 项目呈现配置；拟与 document 并列随工程文件保存，独立于 flowsheet 输入及求解修订 | 保存量 ID → 单位 ID 和格式选择，不保存转换系数；不是机器专属布局 sidecar |
| 个人默认 | 应用偏好 | 仅初始化新工程的项目显示配置；不覆盖已打开工程，也不让旧工程随机器偏好漂移 |
| 临时输入单位 | 字段草稿 | 与原始文本一起保留到提交 / 取消，不改变项目显示单位；提交转换为 SI 后回到有效显示单位 |
| 临时显示覆盖 | 当前视图的显式呈现状态 | 仅在用户明确选择时覆盖该视图的项目默认；不进入求解输入，首版不承诺逐字段持久化 |
| 输出单位选择 | 输出任务配置 | 显式选择优先，否则捕获本次项目单位集；模板不自行定义系数，完整报告配置以后落地 |

有效显示为“明确的视图覆盖，否则项目单位集”；不叠加个人偏好作隐藏 fallback。旧工程没有呈现配置时按完整 SI 集解释，显式选用其他集后再保存；未知单位 ID / 不兼容量要提示并保留原信息，不能静默替换成 SI。具体旧版本读取和往返策略在 U2 格式变更前验证。

显示偏好变更有独立的保存脏标记，复用项目安全保存流程，不调用物理输入命令、不增加计算修订、不使快照过期。定义中的系数属于代码版本；工程只引用稳定身份，后续定义变化需兼容策略，不允许同名单位悄悄改变含义。

## 输入与显示主路径

2026-09-17 确认 U2 同步纳入 [V0 颜色与状态语义](../architecture/studio-visual-system.md#工程字段与状态语义v0-规划)：可编辑性、来源、草稿、缺项、时效和诊断分别映射。切换显示单位不能把计算量改成用户指定量，也不能把未提交草稿标成已完成；非法单位和物理约束拒绝须保留原文及原因。结果数值与后续色带图例共用转换，物理阈值不随显示单位变化；V1—V4 可视化不作为 U2 前置条件。

1. 按变量元数据和单位集显示值；核心和求解快照保持 SI。
2. 用户可以在当前显示单位输入，也可以为本次输入选择兼容单位。
3. 有效输入先转换、校验，再走正式输入事务；提交后以显示单位呈现。
4. 切换显示单位只重绘数值；例如输入 `300 K`、显示 °C 时呈现 `26.85 °C`，核心仍为 `300 K`。
5. 保存重开恢复选定的单位偏好和工程值，导出明确标注单位、基准与结果身份。

有效草稿在切换单位时保持同一物理量；未完成或非法草稿应保留原文本及输入单位，阻止会重新解释文本的切换并提示先修正 / 取消。输入单位是解释文本的依据，显示单位是呈现选择，不能混为一个可变标签。焦点、提交、撤销、取消和本地化小数点等行为在 U2 一并验收。

纯显示切换不推进用于求解的输入修订、不触发重算、不使快照过期；偏好修改可以独立产生保存需求。不得为了保存单位集而复用物理参数事务，导致结果无故 stale。项目级默认、个人默认、字段临时选择及报告选择按上节分别管理；具体存储迁移在 U2 落地。旧 SI 工程无单位配置时保持原有解释，不更改既有 `_k` / `_pa` 等字段含义。

API 默认保留现有 SI 契约。未来带单位写入必须同时给出稳定单位身份，带单位读取必须返回单位和基准；不得只把 JSON 数字换成显示值而沿用原字段口径。录制保存足够的单位身份 / 上下文以重放，不依赖录制时的界面偏好。

工程公共条件、输入来源和工况覆盖由 [工程基础专题](engineering-basis-and-cases.md) 管理；统一转换需保留原值 / 原单位到采用值的依据，不把换算或估算后的数据重新标成实测。数据不确定度的表示转换、绝对温度与温差尺度分别处理，不能把单位偏移加到温度不确定度上；完整传播按后续统计方法定义。

## 验证与后续

U1 验证覆盖规范值与反向转换、目录一致性、维度 / 语义拒绝、绝对温度与温差、有限值 / 溢出、换单位后的物理范围检查，以及显示精度和核心精度分离。GUI 与非 GUI 的等价输入应得到容差内一致的 SI 值；同值写入处理需明确浮点比较策略，不能引入宽松阈值吞掉真实编辑。当前仍使用既有精确同值事务；U2 对未编辑的显示文本保留原始 SI 值，有效草稿以全精度规范值重绘，不能反复解析舍入后的显示值造成漂移。

U2 / U3 做输入→切换→提交→运行→导出→保存重开的主路径和失败路径，覆盖 Undo / Redo、stale / missing、跨消费者结果与偏好独立保存。真实窗口前告知，平台证据按当前状态管理。进入实现时执行相关定向测试和正式仓库基线。

下一步：U2 单位集、输入 / 显示和保存恢复；字段控件与设置入口先通过 [UI 重设计](../architecture/studio-ui-topic-plan.md) 的相应局部评审。完成全部 UI 重设计不是纯转换逻辑实现的前提。
