# 模型目录、发现与运行实例

更新时间：2026-09-29

## 用途与状态

用途：定义内建和扩展单元 / 物性模型的发现、工程绑定、运行装配与恢复边界，以及分阶段验收。
读者：维护模型、求解器、物性包、模块面板、项目存储与互操作适配的协作者。
不包含：具体插件 ABI、运行时选型、完整 SDK、市场、安装器或第三方 CAPE-OPEN 宿主实现。

- 状态：Draft / 2026-09-29 方向已确认，新增能力尚未实现。
- 层级：二级功能；父专题为 [流程图建模与求解](../flowsheet-modeling-and-solve.md)，关联 [物性基础](../property-basis-and-components.md)。
- 总体扩展与权限原则归 [平台规划](../../architecture/simulation-platform.md#插件系统)，实施依赖归 [路线图](../../radishflow-mvp-roadmap.md#模型装配与物性上下文的配套切片)，当前优先级归 [当前状态](../../status/current.md)。

## 目标与用户路径

用户应能从模型目录了解可用模型、支持的规格和适用范围，创建工程对象并绑定物性，运行后审阅可追溯结果；重开工程时能解释缺失或不兼容模型，而不是静默替换实现。GUI、CLI 和未来自动化消费相同领域描述与命令，模块面板不是独立模型注册源。

典型路径为：查看模型描述 → 选择模型并创建工程实例 → 配置参数、端口和物性绑定 → 检查能力与规格 → 运行装配并计算 → 审阅结果 → 保存重开。内建模型不要求先安装插件，第三方模型还需经过装载、兼容性与权限检查。

## 当前实现与缺口

| 对象 | 当前事实 | 尚缺能力 |
| --- | --- | --- |
| 单元类型与描述 | `rf-unitops::BuiltinUnitKind` 固定六类；`UnitOperationSpec` 描述规范端口 | 开放模型身份、版本、参数 / 规格与能力描述 |
| 工程实例 | `rf-model::UnitNode` 保存 ID、kind、端口和出口温压参数 | 任意模型配置、版本绑定与缺模型恢复契约 |
| 计算实例 | `rf-solver::instantiate_operation` 按 kind 分支构造；`UnitOperation::run` 接收输入和服务 | 由领域目录 / 工厂解析实现；实例与任务的显式生命周期 |
| 物性包 | `PropertyPackageProvider` 枚举 manifest、装载 `ThermoSystem`；支持内存与本地缓存来源 | 可替换计算实现的工厂及能力协商；现有数据包不等于可执行插件 |
| 物性上下文 | 流程保存一个 package ID；Studio 构造固定 provider / TP Flash，一次求解共享一套服务 | 工段 / 单元多物性绑定、明确映射和跨包基准一致性 |
| CAPE-OPEN | 自有单元 PMC 可由外部 PME 发现和调用 | RadishFlow 作为宿主发现、激活第三方单元或物性包 |

实现定位：[单元契约](../../../crates/rf-unitops/src/lib.rs)、[实例化与调度](../../../crates/rf-solver/src/lib.rs)、[物性装配](../../../apps/radishflow-studio/src/solver_bridge.rs)。当前固定枚举和温压参数是 MVP 范围，不应被包装成已稳定的第三方模型协议。

## 模型定义、工程实例与运行实例

| 概念 | 所有权与内容 | 生命周期 |
| --- | --- | --- |
| 模型定义 | 所属领域提供稳定模型 ID、版本、来源、参数 / 端口描述、支持的计算模式与适用域 | 随实现或数据版本发布；可供目录查询 |
| 工程实例 | 工程拥有设备 / 单元 ID、选用模型引用、用户配置、连接与物性绑定 | 经文档命令创建和修改，保存、撤销、重开 |
| 运行实例 | 运行任务基于输入快照解析模型，持有计算对象、工作区和可变上下文 | 装配、校验、计算、完成 / 失败 / 取消后释放 |

模型 ID、工程对象 ID、插件 ID 和 COM CLSID 不互相替代；一个插件可以提供多个模型，同一模型可以有多个工程实例。显示名可改变，不能作为持久身份。COM 标识与领域身份的映射由适配层维护。

模型参数应按领域表达类型、量 / 基准、读写条件、边界、默认值来源及互斥规格，不能把所有参数塞进无校验字符串字典。参数描述、校验与公开变量元数据共享领域真相，但浏览树不直接反射内部对象；具体类型与序列化在实施前确定。

运行读取冻结输入，局部试算不修改活动文档；出口与诊断显式返回，成功结果按运行及输入修订发布。实现可复用不可变数据；可变缓存和外部组件引用按任务 / 实例隔离，不能因共享物性包而共享未定义的可变状态。

## 发现、装载与创建

```mermaid
flowchart LR
    Sources[内建描述或扩展来源] --> Discover[发现模型描述]
    Discover --> Check[身份与兼容性检查]
    Check --> Catalog[领域模型目录]
    Catalog --> Create[命令创建工程实例]
    Create --> Assemble[运行解析与工厂创建]
    Assemble --> Bind[绑定物性与输入]
    Bind --> Calculate[校验与计算]
    Calculate --> Results[结果与诊断]
```

图为目标职责，不表示已有动态加载器。内建实现可以先静态登记描述与构造函数；“目录”按领域和应用实例拥有，避免全局可变注册表或任意服务定位器。求解器负责编排依赖和执行，不继续吸收每种设备的构造、参数解释及物理校验分支。

发现描述、加载可执行实现、创建工程实例和创建计算实例是不同操作。可先读取可信元数据时，不为展示目录启动全部计算实例；需要组件调用才能枚举的外部机制应明确其副作用与隔离范围。装载来源、格式与信任策略在首个真实扩展切片确定。

- 静态内建和动态扩展复用领域能力契约，不强制内建模型动态化。
- 安装 / 启用只表示实现可用，不证明适用于当前工况；运行仍检查组分、相态、规格和计算模式。
- 不兼容、缺模型或不支持能力应返回可定位原因；不能用另一模型、近似算法或成功占位代替。
- 运行中禁用 / 升级需停止接收新任务，并按所选运行时完成排空或取消及释放；不得卸载正在调用的实现。
- 项目保留模型引用与未知配置原件，缺模型时限制相关操作并说明原因，不能丢弃后覆盖保存。精确版本 / 兼容范围、迁移和数据保留方式须在写入新格式前确定。

## 物性上下文与单元契约

单元消费物流状态与热力学服务，局部模型拥有设备方程，流程求解器拥有单元间依赖与耦合。物性配置与计算上下文的所有权归 [物性专题](../property-basis-and-components.md#物性配置与运行上下文规划)，Stream / Material Object 的区别归 [物流股专题](material-stream.md#物流状态与热力学服务)。

后续目录应能表达 TP / PH 等支持规格、可用物性、相态、组分限制、局部求解或残差 / 导数等能力。能力逐项出现，不让稳态黑箱单元假装支持 EO 或动态。缺物性与数值不收敛分别诊断；既有简化模型不得随接口统一升级为工程准确性声明。

多包绑定不是首个目录切片的前置。若实际工段需要不同物性包，应先定义绑定优先级、组分映射、相标签、单位 / 基准与焓参考态，再决定如何跨边界传递状态和验证衡算；不能只给流股增加一个任意 package 字符串。

## 分阶段切片

| 切片 | 范围 | 退出标准 |
| --- | --- | --- |
| MC0 契约与场景 | 以现有单元和一个真实扩展需求确定描述、身份、实例所有权与兼容策略 | 记录现有分支与消费者、成功 / 拒绝案例及待决策；不新建空框架 |
| MC1 内建目录与工厂 | 静态组合已有模型，逐步从 solver 移出模型构造与专属参数解释 | GUI / CLI、保存重开和六类单元行为保持；未知模型明确拒绝；无动态依赖要求 |
| MC2 物性装配与上下文 | 分开包解析 / 缓存 IO 与数值求值，按任务装配服务 | 同一输入跨消费者一致，任务间无状态串扰；缺包 / 不兼容明确失败；按实际需要替换计算实现 |
| MC3 首个外部模型 | 与既有“首个可安装插件”切片合并实施，选定单元或物性场景 | 完成真实装载、生命周期、版本恢复及故障验证；若选择 CAPE-OPEN，再独立确定宿主侧接口和平台范围 |

MC0—MC3 是细化模型装配的切片，不另建平行插件路线；与 P2 / P3 及物理验证的依赖见路线图。MC2 不预先要求多物性包，MC3 不同时承诺原生 DLL、WASM、独立进程和 COM 四套运行时。

进入实现前须确定：首个消费者、模型描述 / 配置表示、旧 kind 与新身份映射、版本和迁移规则、工厂所有权、物性上下文粒度；外部加载还需确定 ABI / 消息契约、线程与进程模型、释放责任和性能指标。当前文档不冻结这些技术选型。

## 验收与最小验证

| 场景 | 验收依据 |
| --- | --- |
| 内建迁移 | 原有六类单元的创建、端口、参数拒绝、求解、Undo / Redo、保存重开结果不回退；沿用已有回归 |
| 描述与能力 | 目录声明与实际实现一致；不支持的规格 / 相态 / 计算模式在执行前明确拒绝 |
| 实例隔离 | 同一模型两台设备与两个任务参数独立；中间试算不改入口和工程输入；只共享明确不可变的数据 |
| 物性装配 | 组分顺序、相标签与基准映射可追踪；缺包 / 到期 / 不兼容不回落到默认包；更换配置导致结果旧化 |
| 存储恢复 | 未知 / 缺失 / 禁用模型、旧版本和失败迁移保留原项目；恢复所需版本后能继续工作 |
| 外部故障 | 激活、校验、计算、取消及释放失败可定位；不提交半成品；重入 / 线程与开销按所选运行时实测 |
| 工程准确性 | 独立基准、适用域、物料 / 能量残差按 [热力学模型验证](../../thermo/mvp-model.md#验证证据与缺口) 和具体单元专题验收 |

文档阶段只执行仓库治理、链接、文本和体量检查；实现按切片运行定向测试及必要的跨层基线。CAPE-OPEN 对外 PMC、未来宿主加载和物理准确性各自保留证据，不用一个成功 smoke 替代三类结论。
