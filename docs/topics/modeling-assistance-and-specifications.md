# 规格分析与建模辅助

更新时间：2026-09-16

## 用途与状态

用途：定义当前确定性建模辅助、规格完整性 / 自由度分析，以及未来 Agent 复用边界。
读者：维护模型、求解检查、诊断、Studio、自动化和工作流的协作者。
不包含：当前大模型接入、Agent 运行时、通用脚本沙箱、所有设备的完整方程分析。

- 层级：一级轨道；上位规划：[模拟平台](../architecture/simulation-platform.md)。
- 关联：[建模求解](flowsheet-modeling-and-solve.md)、[Studio](studio-main-workflow.md)、[单位](units-and-quantity-system.md)、[结果与诊断](results-review-diagnostics.md)。
- 状态：Draft / 规划已确认 / 单位基础后按模型能力推进。

## 目标与当前基础

近期智能化由确定性规则、规格检查和固定工作流提供。用户应能知道缺少哪些条件、规格为何冲突、可以采取哪些操作，并在执行后得到与手工操作一致的结果。未来 AI Agent 可读取同一份元数据和诊断、调用同一套动作，不另建可以越过校验的写入路径。

当前已有 readiness、结构 / 参数诊断、画布本地候选、恢复定位、B3-1 变量描述、B3-2 输入事务、B3-3 受控动作和 B3-4 CLI。它们提供可复用基础，尚不等于通用规则服务、完整自由度分析或脚本录制。规则归领域层，界面负责呈现；未来重整模块位置需服务真实复用，不预建庞大规则语言。

## 检查层次与语义

| 层次 | 判断内容 | 不可冒充的能力 |
| --- | --- | --- |
| A 输入就绪 | 必填输入、有限性、范围、连接基本条件 | 字段填满不等于自由度为零 |
| B 规格完整性 | 当前模型与计算任务需要的规格、可替代项、互斥组合、尚可指定项 | 规格模板的计数不等于通用方程结构分析 |
| C 结构自由度 | 未固定变量、活动方程、连接约束、结构匹配和欠 / 过指定位置 | 计数为零不证明独立性、可解性或唯一性 |
| D 数值诊断 | 局部秩 / 奇异性、缩放、残差、初始化与收敛问题 | 结构可解不等于任意初值都能收敛 |

近期先交付 A / B 的完整用户路径；C / D 随变量 / 方程和导数能力进入 P3 / P4。黑箱模型只提供其声明的局部规格契约，未覆盖的全局结构返回 `未分析 / 不支持`。结果须带分析范围、方法、模型版本和输入修订，不用一个绿色“0”替代这些信息。计数型指标的参考见 [IDAES 模型统计](https://idaes-pse.readthedocs.io/en/stable/reference_guides/core/util/model_statistics.html)。

设计、校核、稳态与动态可能有不同的固定量 / 未知量；规格契约由模型和任务共同决定。比如目标出口温度和热负荷是否可同时指定，应由该模型的规格关系判断，不能仅按字段非空作判断。未来循环、设计规格和连接约束参与全局分析，不能把设备局部自由度简单相加。

## 推荐做法与固定工作流

首批可围绕已有单元完成：

- 指出缺失的 Feed 温压流量与组成、未提交的单元参数，定位正式输入控件。
- 解释连接候选与阻塞原因；执行时重新枚举候选，不使用过期 UI 缓存。
- 指出非法范围、互斥规格与不支持的模型能力；提供合法操作而非偷偷修改假设。
- 组织检查→修正→运行→读取结果的确定性步骤；后续参数扫描复用任务与自动化能力。

推荐和硬约束分别标识。必需条件不能因用户忽略建议而跳过；启发式推荐不能伪装成数学证明或安全结论。自动计算的候选值必须说明公式、来源、条件与适用范围。缺少物性或设备数据时报告缺项，不以经验默认值填成已确认工程输入。

推荐至少包含稳定规则 ID / 版本、严重程度、目标对象 / 字段、触发依据、说明、建议动作与参数、适用文档修订。规则输出和动作描述使用结构化字段，不能通过解析提示文本执行操作。相互冲突的建议需显示冲突或选择条件，不能靠任意顺序反复覆盖输入。

规则执行不直接修改模型。用户或已授权工作流调用正式动作后，再检查当前前置条件、执行事务、更新历史与结果状态；只接受部分步骤时逐项返回回执，明确失败后的已完成部分。没有真实需求时不提前实现规则 DSL、任意代码执行或插件运行时。

## UI 与未来 Agent 边界

对象附近显示相关缺项 / 冲突，工作区提供汇总和定位入口；与现有 Run Panel、诊断和候选连接统一，避免新增互相矛盾的“可运行”状态。界面区分待输入、规格冲突、未分析、不支持、求解失败、建议已失效。UI 承载位置由 [重设计计划](../architecture/studio-ui-topic-plan.md) 决定。

未来 Agent 的预留能力为：发现对象 / 变量 / 单位 / 动作，读取结构化诊断与建议，提出带身份和修订的操作，调用统一命令，等待任务并查询有来源的结果。变更预览、权限、事务 / 撤销、失败回执和资源界限随真实消费者建立；可查询能力必须与实际支持一致。当前不增加聊天占位页、大模型 SDK、提示词系统、云端依赖或空 Agent 模块。

软件自动化等待任务完成，动态配方等待仿真时间 / 事件，两者不混同。建模辅助、操作录制和未来 Agent 分别是同一命令能力的消费者。

## 分阶段切片与退出标准

| 切片 | 范围 | 退出标准 |
| --- | --- | --- |
| A1 输入与规格诊断 | 盘点现有六类单元，定义其真实规格契约，复用 readiness / 诊断 | GUI / CLI 对同一输入给出一致缺项及冲突；模板 / 默认显示值不冒充已提交规格 |
| A2 可执行推荐 | 统一规则身份、依据、定位与动作；复用现有候选和修复 | 接受、忽略、过期、对象删除和冲突路径可验证；操作可追溯、遵守原事务 |
| A3 固定工作流 | 按真实场景串接检查 / 操作 / 运行 / 结果，可参数化 | 手工与工作流得到一致工程输入和结果；部分失败与停止行为明确 |
| A4 结构与数值分析 | 随模型增加方程结构、匹配、局部秩与残差分析 | 欠 / 过指定、等计数但相关方程等基准得到正确分层结论；不支持明确返回 |
| A5 Agent 消费 | 待实际接入时确认运行时、授权与交互 | 使用同一元数据 / 命令 / 诊断，不生成第二套工程真相；当前未排期 |

## 验证与后续

规则回归须覆盖触发和不触发、边界、缺少上下文、冲突和旧修订；验证正常输入不被多余阻塞，建议不会偷偷修改文档。设备规格在不同计算模式下分别验证，不用重复实现同一规则生成测试期望。结构分析采用已知独立、欠定、超定和相关方程案例，数值分析单独验证。

集成验证覆盖诊断定位→修改→Undo / Redo→重检→运行→结果，GUI / CLI 结果一致，旧建议拒绝执行，保存重开按当前模型重新分析而非信任旧缓存。实现按相关 crate 定向测试及仓库基线收口；界面切片另做已告知的实窗验收。
