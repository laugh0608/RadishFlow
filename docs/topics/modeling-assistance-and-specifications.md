## 目标与当前基础

近期智能化由确定性规则、规格检查和固定工作流提供。用户应能知道缺少哪些条件、规格为何冲突、可以采取哪些操作，并在执行后得到与手工操作一致的结果。未来 AI Agent 可读取同一份元数据和诊断、调用同一套动作，不另建可以越过校验的写入路径。

当前已有 readiness、结构 / 参数诊断、画布本地候选、恢复定位、B3-1 变量描述、B3-2 输入事务、B3-3 受控动作和 B3-4 CLI。它们提供可复用基础，尚不等于通用规则服务、完整自由度分析或脚本录制。规则归领域层，界面负责呈现；未来重整模块位置需服务真实复用，不预建庞大规则语言。

## 检查层次与语义

| 层次 | 判断内容 | 不可冒充的能力 |
| --- | --- | --- |
| A 输入就绪 | 必填输入、有限性、范围、连接基本条件 | 字段填满不等于自由度为零 |
| B 规格完整性 | 当前模型与计算任务需要的规格、可替代项、互斥组合、尚可指定项 | 规格模板的计数不等于通用方程结构分析 |
| C 结构自由度 | 未固定变量、活动方程、连接约束、结构匹配和欠 / 过指定位置 | 计数为零不证明独立性、可解性或唯一性 |
| D 数值诊断 | 局部秩 / 奇异性、缩放、残差、初始化与收敛问题 | 结构可解不等于任意初值都能收敛 |

近期先交付 A / B 的完整用户路径；C / D 随变量 / 方程和导数能力进入 P3 / P4。黑箱模型只提供其声明的局部规格契约，未覆盖的全局结构返回 `未分析 / 不支持`。结果须带分析范围、方法、模型版本和输入修订，不用一个绿色“0”替代这些信息。计数型指标的参考见 [IDAES 模型统计](https://idaes-pse.readthedocs.io/en/stable/reference_guides/core/util/model_statistics.html)。

设计、校核、稳态与动态可能有不同的固定量 / 未知量；规格契约由模型和任务共同决定。比如目标出口温度和热负荷是否可同时指定，应由该模型的规格关系判断，不能仅按字段非空作判断。未来循环、设计规格和连接约束参与全局分析，不能把设备局部自由度简单相加。

## 推荐做法与固定工作流

首批可围绕已有单元完成：

- 指出缺失的 Feed 温压流量与组成、未提交的单元参数，定位正式输入控件。
- 解释连接候选与阻塞原因；执行时重新枚举候选，不使用过期 UI 缓存。
- 指出非法范围、互斥规格与不支持的模型能力；提供合法操作而非偷偷修改假设。
- 组织检查→修正→运行→读取结果的确定性步骤；后续参数扫描复用任务与自动化能力。

推荐和硬约束分别标识。必需条件不能因用户忽略建议而跳过；启发式推荐不能伪装成数学证明或安全结论。自动计算的候选值必须说明公式、来源、条件与适用范围。缺少物性或设备数据时报告缺项，不以经验默认值填成已确认工程输入。

推荐至少包含稳定规则 ID / 版本、严重程度、目标对象 / 字段、触发依据、说明、建议动作与参数、适用文档修订。规则输出和动作描述使用结构化字段，不能通过解析提示文本执行操作。相互冲突的建议需显示冲突或选择条件，不能靠任意顺序反复覆盖输入。

规则执行不直接修改模型。用户或已授权工作流调用正式动作后，再检查当前前置条件、执行事务、更新历史与结果状态；只接受部分步骤时逐项返回回执，明确失败后的已完成部分。没有真实需求时不提前实现规则 DSL、任意代码执行或插件运行时。

## 工程检查与求解任务的衔接

[工程基础与工况](engineering-basis-and-cases.md) 提供共享条件、来源、假设和适用工况，规则可据此提示来源未记录、估算输入、超适用域或待确认条件。未知不等于错误或通过，启发式提示不替代用户指定的硬约束。

未来 [工程检查面板](results-review-diagnostics.md#工程检查与交付规划尚未实现) 分别消费输入 / 规格、数值收敛、守恒、物性适用性和设备约束；检查由所属领域产生，不能在面板重新推算。未实现能量模型时不得显示能量收支已通过。数据不确定度、设计裕量与求解容差分别说明，不能聚合成无依据的可信评分。

[设计规格求解](flowsheet-modeling-and-solve.md#设计规格求解规划尚未实现) 由求解领域拥有。推荐可以引导用户建立目标 / 可调变量，但规则执行不偷偷启动参数搜索，也不把一次可行解标成最优；后续固定工作流通过正式动作调用该任务。

## UI 与未来 Agent 边界

2026-09-23 [运行与诊断 N1](runtime-messages-and-diagnostics.md) 与 A1 / A2 衔接：规则产生结构化问题 / 建议，消息层关联、去重、显示及定位，不再检查一遍规格。已知依赖导致的下游阻断可归组，无证据的因果只标可能相关；忽略 / 已读不解除硬约束。修改输入后按依赖进入待重检，执行建议前重新验证身份和条件。条件监视只观察与请求停止，不能借“智能修复”偷偷截断变量或改写模型。

对象附近显示相关缺项 / 冲突，工作区提供汇总和定位入口；与现有 Run Panel、诊断和候选连接统一，避免新增互相矛盾的“可运行”状态。界面区分待输入、规格冲突、未分析、不支持、求解失败、建议已失效。UI 承载位置由 [重设计计划](../architecture/studio-ui-topic-plan.md) 决定。

未来 Agent 的预留能力为：发现对象 / 变量 / 单位 / 动作，读取结构化诊断与建议，提出带身份和修订的操作，调用统一命令，等待任务并查询有来源的结果。变更预览、权限、事务 / 撤销、失败回执和资源界限随真实消费者建立；可查询能力必须与实际支持一致。当前不增加聊天占位页、大模型 SDK、提示词系统、云端依赖或空 Agent 模块。

软件自动化等待任务完成，动态配方等待仿真时间 / 事件，两者不混同。建模辅助、操作录制和未来 Agent 分别是同一命令能力的消费者。

## A1 首批范围与实现

本节以 2026-10-11 基于 `b98d3207` 的盘点为起点，范围已审定；实现和验证状态见本节末尾。目标为六类现有稳态单元提供同源、可定位、可重检的输入 / 规格结论；范围只含前述 A / B 层。分析只读，不触发物性计算、不修改工程、不替用户确认输入。完整结构自由度与数值可解性明确为未分析。

### 六类单元的真实契约

下表的“必需”指 Studio / CLI 正式建模路径；底层单元默认行为另列，不能混成同一门禁。T、P、F、z 分别为 K、Pa、mol/s、总体摩尔分率。所有 canonical ports 为 material，必须绑定存在的流股；终端产品流可以没有下游 sink。

| 单元 | 端口与正式输入 | 已有约束及计算行为 | A1 必须保留的边界 |
| --- | --- | --- | --- |
| Feed | `outlet`；源流股 T/P/F/z；单元 T/P 参数可选覆盖 | readiness 检查有效 T/P 与源 F 有限且大于零；求解装配优先使用单元显式 T/P；非空组成进入当前工程组成检查 | 不新增 Feed 必填单元参数。必须区分源流股数值与单元覆盖；零流量的 Studio 门禁不推广为所有底层流股门禁 |
| Heater | `inlet/outlet`；显式 `outlet_temperature_k`、`outlet_pressure_pa` | T/P 有限且大于零；P 不高于入口；F/z 从入口传递；当前按指定出口 T/P 调节 | 当前没有强制出口温度高于入口的规则，没有热负荷与温度二选一规格，不能自行添加 |
| Cooler | `inlet/outlet`；显式出口 T/P | 与 Heater 共用温压模型和压力约束；温压以外来自入口 | 当前没有强制降温规则；缺显式参数时，画面上的默认数值不算提交 |
| Flash Drum | `inlet/liquid/vapor`；显式出口 T/P | T/P 有限且大于零，进行 TP flash；两相出口均须绑定流股 | 当前没有 P 不高于入口的约束；缺失相可以产生零流量出口，不要求两个出口都大于零；尺寸、停留时间、液位不属于当前规格 |
| Mixer | `inlet_a/inlet_b/outlet`；显式出口 P | P 有限且大于零、不能超过两入口最低 P；入口流量非负、总流量大于零；温度为流量加权近似 | 两入口都要有有效上下文，不能仅凭已连接的一股宣布压力检查通过；不新增出口 T 或焓平衡规格，不扩为任意多入口 |
| Valve | `inlet/outlet`；显式出口 P | P 有限且大于零且不高于入口；保持入口温度、流量和组成 | 当前为温度保持模型，不增加等焓、Cv 或开度规格；P 等于入口允许 |

组成的应用检查当前遍历所有非空文档流股组成：组分须属于项目，分量有限且在 `[0,1]`，`abs(sum(z)-1) <= 1e-9`；源 Feed 的空组成另报缺项。非 Feed 输出模板的空组成不属于必填缺项。项目组分为空和流股引用项目外组分分别报告，不把缓存 / 授权失败混入组成错误。

### A1 的事实来源与兼容决策

1. **已提交与来源。** 对非 Feed 必需单元参数只认正式 `Some(value)`；未应用草稿、模板和结果不能补齐 `None`。Feed 以已存文档源流股及可选单元覆盖建立有效输入，保留现有单元覆盖优先级，同时列出覆盖来源。无来源元数据的已有数值只称“文档输入”，不称“人工确认”。不引入项目 schema 或逐字段确认标记；更完整来源归 G0。
2. **检查范围。** 先建立端口 / 引用 / 无回路适用性，再检查组分、源输入和显式参数。拓扑失败保留原错误，依赖该拓扑的检查标“未检查”，独立的本地字段检查仍可执行。对适用且独立的输入问题一次返回全部，不在第一个缺参数后停止。空工程返回放置单元任务；物性选择、缓存与授权仍归应用运行前置条件，不重复实现。
3. **上下文与压力。** 纯正数检查不依赖上游。压力比较必须带来源：可从有效 Feed 输入或上游已提交出口 P 确定时使用该正式输入；Mixer 必须取得两股来源。已有模板只供编辑参考，不作为报告通过 / 冲突的事实依据；无法证明的入口标“待运行检查”，正式求解在真实 consumed streams 上重验。不读取 stale 结果、不为了预检运行热力学或暗算流程。UI 与求解复用同一比较规则，分别传入有来源的上下文。
4. **行为影响。** 有效 Feed T/P 与旧 readiness 单看源模板可能不一致；首批统一为 solver 的有效输入优先级：合法显式覆盖不再被未使用的非法源 T/P 误拦截；非法显式覆盖由参数规则报告，并保留原步骤参数失败，不能改成源流股缺项。无覆盖的非法源值仍由应用阻断。UI 压力约束消除模板造成的误拦截 / 误放行，缺完整上下文时允许保留局部合法参数，但不声称压力关系已通过。上述两项行为校正已获批准，并以冲突输入回归验证；不增加 Heater 升温、Cooler 降温、Flash 降压等新物理规则。
5. **底层兼容。** Studio / CLI 的 Feed 正流量、组成显式归一和参数提交要求保持。底层 `rf-unitops` 允许非负流量、局部归一及默认参数的已有接口保持；由调用方选择明确的建模 / 执行检查范围，不能用多层 fallback 掩盖差异。FFI / COM 不被迁入 Studio 门禁。
6. **运行与 CLI。** 新报告可在运行前展示已知问题；除上述明确的输入来源校正外，旧运行入口的 blocked / failed 分类、退出码、首个错误选择顺序和 SI DTO 保持。例如连接失败仍为 solver 失败，未归一仍为原 blocked code，压力越界仍保留 `solver.step.parameter`。既有运行各阶段消费共享规则，不另写第二套判断。完整问题集合先由应用内部与 GUI 消费，CLI v1 / v2 只映射原摘要；不承诺旧协议能查询全部问题。新增检查命令 / DTO 另走 D-09。

“待运行检查”只表示已知规则缺运行上下文，允许交给正式求解检查；“未检查”用于前置范围受阻，“不支持”用于能力缺失。三者均不等于通过。全局结构自由度未分析不作为当前 SM 运行硬阻断；不支持单元 / 环路则按当前求解能力阻断。GUI、CLI 一致性指同一文档及同一应用 / 物性前置条件下的规则事实和运行结果，不要求两端呈现形态相同。

### A2 首批实施方案（2026-10-11，已审定）

项目所有者已批准以下范围及三项行为选择：保留模板初值并完整预览、写入遇草稿先暂停、连接只覆盖现有候选能力。先同步正式文档并提交，再实施 A2-I1；A2-I2 先提供局部 UI 方案另行审定，不直接接线。I5 沿用既定安排，开工不代表发布放行。

#### 首批动作与非目标

| 动作 | 触发与预览 | 执行边界 |
| --- | --- | --- |
| 定位补输入 | 复用 A1 缺温压、组成、项目组分及压力冲突的依据和稳定目标 | 只导航，不写工程、不补默认参数、不自动截压 |
| 显式组成归一 | 正式组成非空、各分量合法、总和有限且大于零、偏离 1 超过 `1e-9`；逐项显示原值、新值与 `xᵢ / Σx` | 一次事务更新整个组成；空、全零、负数、非有限或项目外组分只提供定位 |
| 补建出口流股 | 现有六类单元本地规则可枚举的缺出口候选；展示新流股、源端口和全部初始值 | 创建与绑定原子提交；不自动串接后续修复 |
| 接受连接候选 | 现有本地规则可枚举的源流股—目标端口；明确两端和生成条件 | 用户逐条选择，执行前重新枚举；占用、方向错误、自环 / 成环不可接受 |

Feed 出口沿用 298.15 K、101325 Pa、1 mol/s 与已选组分等分组成，预览逐项标明模板初值；接受后成为文档输入，不宣称逐字段人工确认。其他出口也展示实际创建内容，模板不代替非 Feed 必需显式参数或正式运行结果。无项目组分时仍显示空组成，创建不暗加组分。

现有规则在部分场景只枚举唯一源，Mixer 按固定顺序配对；排序和 confidence 不是工程意图或唯一性的证明。首批不扩张任意多源配线：展示现有候选的准确端点，用户逐条选择；没有可接受候选时说明范围并定位连接编辑。争用同一端口 / 流股的不同建议不得连续自动执行。应用接受仍需精确匹配唯一候选，不把“存在多个不同候选”误当成同一动作身份重复。

不纳入批量接受、连续自动修复、接受后自动运行、参数猜测、设备选型、自动优化、完整多源配线规划器、新 CLI 推荐协议、规则 DSL 或 N2 持久历史。A1 规则和既有 GUI / CLI SI、blocked / failed、退出码保持。
