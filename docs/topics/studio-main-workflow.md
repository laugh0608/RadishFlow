# Studio 主工作台与空白项目建模主路径

更新时间：2026-09-16

> 本文定义该专题的能力、开发范围与验收要求；具体迭代切片和优先级以 [当前状态](../status/current.md) 为准。

## 用途

用途：定义 Studio 主工作台从启动、物性配置、流程图建模、运行、结果审阅到保存 / 重开的主路径开发边界。
读者：负责 Studio UI、window model、command surface、主路径验证和真实窗口 smoke 的开发者、用户、AI / Agent。
不包含：完整视觉系统、自动布线、完整报表、控制面管理 UI 和发布计划；超出现有受控连接的设计由建模专题承接。

## 专题目标

- 普通空白项目不再围绕某个 demo case 或 UI 小补丁推进，而是以用户可复现的完整建模路径为验收对象。
- 用户可以从 Home 新建项目，进入 `物性`，选择内置 package 和项目组分，再进入 `流程图` 放置单元、补齐输入、运行、审阅结果、保存、重开和 rerun。
- 本专题把 Studio UI 实现从“第 N 刀”改为主路径能力切片；局部 UI 调整只有影响主路径判断时才进入。

## 用户路径

1. 启动 Studio，在 Home 判断环境、登录 / 授权状态、当前工作区和最近项目。
2. 新建普通空白项目，进入独立 `物性` 页面。
3. 选择内置 `binary-hydrocarbon-lite-v1` package 和 methane / ethane 项目组分。
4. 进入 `流程图`，从左侧 `模块` 放置 Feed、Heater / Cooler / Valve、Mixer、Flash Drum。
5. 通过 Canvas suggestion、Inspector 和模块设置补齐连接、Feed source stream、composition 和单元参数。
6. 运行求解，在右侧模块结果、底部结果表、状态汇总和诊断中审阅同一份当前 `SolveSnapshot`。
7. 保存、重开、rerun，确认结果和旧快照状态一致。

## 范围

本专题纳入：

- Studio 主工作流的页面职责、入口关系和区域分工。
- 普通空白项目主路径所需的 UI 状态展示和正式 command 消费。
- 影响主路径的 Home、Property、Workbench、Run、Result 页面衔接。
- 真实 blocker 的 UI / DTO / command 修正。

- 自动布线与完整拖拽布局；更自由的连接 / 端口选择由建模专题明确设计，本专题只负责用户路径集成。
- 完整参数表、完整报表、跨快照报表、模板、打印和批量导出。

- 控制面运营后台和移动端编辑体验。

## 设计边界

### 数据与状态

- 项目标题、脏状态、revision 来自当前 workspace document。
- 物性选择来自 `workspace_document.property_package_choices` 和 `project_component_choices`。
- 建模输入缺口来自 shared modeling readiness。
- 运行和失败状态来自 Run Panel / workspace control model。
- 当前结果来自当前 revision 的 latest `SolveSnapshot`。
- Workbench 不维护第二套项目、物性、运行或结果状态。

### 命令与接口

- UI 操作通过正式 command id 或 driver 入口派发。
- Canvas 放置、连接 suggestion、Inspector focus、run、result focus、保存和关闭确认都必须走既有 command / driver 边界。
- 若需要新增入口，先明确它属于 Home、Property、Canvas、Inspector、Run Panel、Result Review 还是 Document Lifecycle。

### UI 与交互

- Home 是开始和返回工作区入口，不是营销页。
- `物性` 是独立页面，不退回侧栏。
- 左侧 `模块` 负责放置，左侧 `项目` 负责项目输入扫读、对象树和审阅状态。
- 中央 Canvas 负责建模主舞台，不重复对象树和完整结果表。
- 右侧栏负责当前对象输入、模块设置和模块结果。
- 底部负责消息、运行日志、收敛、建议、诊断、结果表和状态汇总。

## B3-1：变量与动作描述、只读浏览

2026-09-15 经项目所有者确认进入本切片。Windows / Linux 原生路径累积到阶段节点集中验证；P1 未测项继续保留，不能据此宣称全平台收口。

- 目标：普通用户在“工具 → 变量浏览器”按单元 / 流股查看已提交输入、已有求解结果和动作描述，搜索对象 / 变量 / SI 单位，并定位既有检查器。
- 应用查询置于不依赖窗口库的 `rf-ui::variable_browser`，借用当前 `FlowsheetDocument` 与同一工作区的 current / stale `SolveSnapshot`；Studio 使用接管快捷键的模态浏览窗口，仅保存窗口开关、搜索词和所选身份，不保存第二份工程值。对象列表不预先展开全部变量，搜索按需扫描当前受控工程。
- 身份由 DocumentId、UnitId / StreamId、输入 / 结果分区和类型化字段共同构成。显示名称不参与身份；跨项目引用、删除对象和消失字段分别返回结构化错误。该 Rust 内部契约不冻结公共 DTO / ABI 或序列化路径。
- 单元覆盖六种现有类型实际支持的温压参数；流股覆盖 T/P/F、摩尔组成和已有快照中的相分率、相组成及摩尔焓。单元端口引用同一流股对象，不复制结果。未实现的 duty、自由度分析和任务动作不注册。
- 值描述包含数值 / 文本类型、标量形状、SI 单位 / 摩尔基准、来源、单值有效性与写入入口；单值有效不等于组成归一化或整个模型已就绪。未显式指定参数保持未指定，不能用 Inspector 默认值冒充输入；草稿不进入查询；流股模板明确区别于求解结果。结果按快照 ID / revision / sequence 标识，过期值不作为当前数值返回，缺结果明确显示缺失。
- 描述既有参数设置、重命名、创建、连接、断开和运行的参数、前置条件、文档影响、撤销能力与返回语义；首版只读描述，不提供写入或动作调用。当前求解仍同步，不承诺后台任务或取消。后续调用必须复用正式命令及实时可用性检查。
- 非目标：新增依赖、项目 schema、COM 注册、公共 API 传输、插件运行时、脚本、任务调度或全量对象反射。
- 验收：参数缺失 / 非法值、草稿隔离、压力约束、当前 / 过期 / 缺结果、同名对象与重命名身份、删除 / 跨项目引用、保存重开查询一致性、结果只读及搜索定位有定向回归；macOS 实窗验证入口和结果状态，阶段收口执行正式仓库基线。

## B3-2：统一变量写入与输入事务

2026-09-15 经项目所有者确认推进 B3-2。该切片交付应用内 Rust 写入边界；B3-1 浏览窗口仍只读，现有 Inspector 是 GUI 编辑入口。

- `rf-ui::variable_commands` 提供 `VariableWriteRequest` / `VariableWriteReceipt` / `VariableWriteError`，由 `AppState::write_variable` 消费。请求携带 B3-1 的文档 / 对象 / 分区 / 类型化字段身份、必填 `expected_revision` 和数值 / 文本值；数值直接使用变量描述中的 SI 单位及摩尔基准，不做字符串类型转换或单位猜测。
- 首个可写范围：单元名称与六类单元实际支持的出口温压；流股名称、T/P/F 和项目组分摩尔分数（包含尚未显式填写的项目组分）。结果分区始终只读，不以结果快照中的值覆盖输入。
- 执行顺序：校验文档身份和预期修订、对象及字段、只读边界、未处理草稿、值类型和项目组分；再进入现有字段与压力约束校验。跨项目、旧修订、对象 / 字段缺失、结果写入、草稿冲突、类型错误及领域拒绝分别返回结构化错误。领域拒绝保留原始 `RfError`，支持标准 Rust error source。
- 非 GUI 调用不改变选择或 Inspector 焦点；存在任何保留字段草稿时返回 `PendingDrafts`，由调用者先显式提交或丢弃。不会自动消耗用户草稿。Inspector 继续管理自己的草稿生命周期，双方共用 `WorkspaceState::commit_input_document_command` 的准备与提交逻辑。
- 共享路径先在文档副本上验证、应用全部值，再记录一条既有 `DocumentCommand` 及 before / after 历史。任一值拒绝时文档、历史、草稿、快照不变；成功修改只增加一次修订，沿用出口模板同步、建议失效、结果旧化和保留单元草稿重验。批量流股提交、组成归一化和添加组成项也复用此路径，原组成编辑 / 运行校验规则保持不变。
- 完成校验后的相同输入若不改变文档，返回当前修订且 receipt 的 `command` 为 `None`，不新增历史、不旧化结果；非法持久化值不能借相等比较绕过校验。GUI 的相同输入事务也遵循此规则；缺失的显式单元参数仍须真正写入，不能因为出口模板已有同值而跳过。
- 对外首版为单变量写入；不新增跨对象批处理、创建 / 连接 / 运行调用协议、自动求解、COM / HTTP / 脚本适配、录制器、任务取消、依赖或项目 schema。既有低层 `commit_document_change` 保持内部调用兼容，不把它作为新增外部调用边界。
- 验收：GUI / 非 GUI 对六类单元及流股字段的文档、命令历史和求解状态一致；拒绝原子性、修订冲突、草稿保留、压力约束、相同值、Undo / Redo，以及写入后正式保存 / 重开 / 重新求解有回归。界面未新增操作，复用既有 shell 闭环回归；其他平台原生验证继续按阶段集中执行。

## B3-3：受控创建、连接与运行调用

2026-09-15 经项目所有者确认推进 B3-3。`radishflow-studio::modeling_actions` 提供不依赖窗口的应用内 Rust 动作入口，衔接 B3-1 查询和 B3-2 写入；浏览窗口继续只读。

- `dispatch_modeling_action` 接受 `ModelingActionRequest`：文档身份、必填预期修订和类型化 `CreateUnit` / `Connect` / `Run`。所有动作先拒绝跨文档、旧修订、任何未处理字段草稿及待完成画布编辑；拒绝不改变应用状态。执行后返回文档身份、当前修订及对应动作结果，领域拒绝保留 `RfError` source。
- 创建覆盖现有 Feed、Heater、Cooler、Valve、Mixer、FlashDrum，复用身份分配与标准端口；调用者不指定或用显示名称推导身份。画布放置与动作入口共享 `AppState::create_builtin_unit`；新身份在当前会话删除或撤销后不会被复用。
- 连接先通过只读 `available_material_connections` 枚举当前本地规则候选，按流股身份、源单元 / 端口及可选目标单元 / 端口选择。执行时重新生成候选，要求唯一匹配，不读取界面缓存建议，也不接受调用者提供新流股内容；允许现有规则控制的源流股 / 出口模板创建。候选不能表达任意拓扑，多上游歧义仍按现有规则拒绝；完整拓扑和求解合法性继续在运行链路校验。
- 创建和连接先在副本上准备，再写入一条既有 `CreateUnit` / `ConnectPorts` 命令、修订及 before / after 历史，复用端口方向 / 类型 / 占用和源汇约束、结果旧化、Undo / Redo。`commit_material_connection` 是与 GUI 建议接受共享的低层事务；文档 / 修订与编辑冲突、当前候选授权由上层调用入口负责。GUI 继续单独管理选择、Inspector 焦点与交互日志。
- Run 接受显式包选择或 `Preferred`，通过既有 `dispatch_workspace_control_action_with_auth_cache` 执行正式 readiness、同步求解、诊断与 Run Panel 反馈，返回完整 `WorkspaceControlActionOutcome`。返回 receipt 只表示调用已处理，不表示求解收敛；其中可能为 `Blocked` / `Failed` / `Skipped`，沿用的 `Started` 名称也不表示新增后台任务。消费者应同时检查 outcome、控制状态及当前快照。运行不修改文档和历史，不可撤销。
- B3-1 创建 / 连接 / 运行描述已对齐本轮调用参数；文档身份和预期修订属于通用请求外层。动作描述不是持久化命令格式：例如创建请求仅指定 kind，历史命令记录分配后的 unit_id；连接请求选择端点，历史继续使用原有命令结构。
- 配置物性包和项目组分继续使用现有应用入口。未新增任意对象工厂、任意连接、统一断开 / 删除协议、外部传输 / COM 适配、录制器、后台任务 / 取消、依赖或项目 schema。
- 验收覆盖六类创建与画布文档 / 历史一致、删除后身份保留、请求冲突和草稿隔离、候选过期 / 歧义 / 非法端口原子拒绝、连接 Undo / Redo，以及空白 Feed–Heater–Flash 创建→写入→连接→求解。成功、阻塞与求解失败均与既有运行入口比较；界面没有新增执行操作，沿用 shell 回归，其他平台原生仍按阶段集中验证。

## B3-4：首个无界面参数化运行消费者

2026-09-15 经项目所有者确认推进。范围为现有 Studio 可执行程序的 `--headless inspect <project>` 和 `--headless run <request.json>`：查询项目身份 / 变量，按请求顺序写入现有参数，同步运行一次并读取指定变量。沿用 B3-1 / B3-2 / B3-3 和正式项目装载；CLI DTO 与内部 Rust 模型分离，不改变项目 schema。

- 请求使用带版本的严格 JSON，固定输入项目身份与修订；相对路径相对于请求文件目录。未知字段、未知版本、类型不符和任一写入拒绝均停止本次执行，不运行后续步骤。
- 每次启动独占本次内存文档，写入只影响本次运行；不保存项目、sidecar、偏好或认证信息。物性只从显式本地缓存索引 / 根目录加载，不自动登录、下载或创建演示缓存。
- 标准输出为单个 JSON 响应，包含状态、文档修订、变量来源与有效性、运行诊断；非成功返回非零退出码。阻塞、求解失败与调用失败分开表达，不输出伪造的当前结果。标准输出错误也返回非零退出码。
- 首版不接入创建 / 连接脚本、操作录制、循环 / 批量调度、COM、网络服务、保存覆盖和后台任务；命令行是本地消费者，不表示稳定公共 API 或完整 P2 已完成。
- 命令、请求示例与退出码见 [无界面接口参考](../reference/headless-cli.md)。
- 验收：真实文件与进程验证 inspect→参数修改→运行→JSON 读回，比较统一应用入口结果；覆盖身份 / 修订冲突、非法参数、未知协议字段、缓存缺失、模型阻塞 / 求解失败、结果查询错误和输入文件字节不变。执行 macOS 离线全仓基线，其余平台继续阶段集中验证。

## B3-5：无界面创建、连接与步骤身份引用

2026-09-16 经项目所有者确认推进。现有 `--headless run` 增加显式 v2 请求，加载已配置组分 / 物性的工程后，顺序创建六类内建设备、选择实时连接候选、写入 SI 参数，最后同步求解并读取结果。v1 的写入请求和响应字段保持兼容，工程文件 schema 不变。

- 协议与执行分别由 `headless::request` / `headless::workflow` 承担；领域仍由 `modeling_actions`、统一变量写入和正式运行入口拥有，不在 CLI 复制连接约束、身份分配或求解器。
- 每步有唯一非空白步骤名。创建回执绑定 UnitId，连接回执绑定 StreamId；之后可通过明确的已有 ID 或此前成功步骤引用。写入不产生新身份；前向 / 未知 / 类型错用引用拒绝，不用显示名或 ID 拼接猜测对象。
- 连接按 source、可选 sink / stream 匹配当前唯一候选，并由正式动作再次检查；省略 sink 表示规则允许的未接下游出口，不表示任意自动布线。现有多上游歧义和端口 / 占用限制保持。
- 每一步使用当前实际修订调用既有事务；失败步骤不修改模型，响应保留此前成功步骤、最新修订和失败 index，后续操作与求解停止。单步原子性不代表整个请求自动回滚；所有修改仅在本次内存中生效。
- 全部步骤完成后沿用运行状态与诊断，不把动作回执视为收敛。reads 支持步骤引用，返回稳定 ID 和快照来源；任一查询失败不返回部分变量，阻塞 / 求解失败保留步骤回执。
- 严格解析原始 JSON，拒绝未知 / 重复字段和混用版本；不经过丢失重复键的中间 Value。未形成版本化执行上下文的错误和 inspect 继续返回 v1。
- 未新增单位换算、依赖、保存覆盖、组分配置、任意拓扑、录制 / 调度、后台任务、COM 或公共 API。新请求格式是本地消费者契约，不等于完整 P2 或工业数值能力交付。
- 验收：真实 CLI 进程从空流程构建 Feed–Heater–Flash，温压 / 流量及快照修订正确；覆盖重复运行、磁盘保护、旧 v1、身份修订冲突、引用错用、无效候选、部分失败、同值写入、结果只读和缺缓存。六类创建的文档 / 历史与正式应用事务一致。命令示例和字段见 [接口参考](../reference/headless-cli.md)，本机验证记录见 W38；Windows / Linux 继续阶段集中验证。
