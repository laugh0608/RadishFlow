# 统一变量与对象浏览器

更新时间：2026-10-31

## 用途与状态

用途：定义工程分类浏览、变量树、路径访问及共享读写入口的产品目标、领域边界、实施切片与验收。
读者：负责 Studio、变量 / 动作描述、CLI、后续自动化及工程对象扩展的设计与开发者。
不包含：最终 UI 画板、冻结的路径语法 / DTO / ABI、COM 激活方式、完整脚本运行时或新的项目格式。

- 层级：二级功能；父专题为 [Studio 主工作流](studio-main-workflow.md)，跨端边界遵循 [统一对外 API](../architecture/simulation-platform.md#对象变量与动作树)。暂不拆子专题。
- 状态：部分实现。AF4a 工程发现、AF5a 结果查询和 AF4b 正式动作已完成；AF4c 新版 CLI 已完成；完整浏览工作区、路径协议和关注项仍待后续切片。
- 定位：一个变量工作区提供工程视图与变量树视图，共用稳定身份、领域描述、查询和正式命令。覆盖所有公开工程变量与动作，逐步纳入非画布对象。
- 顺序：U2-I1—I4 与 U3 首批已接通，I5 按确认节点补验；VB0 纳入 R0 / R1 及 G0 关系设计，VB1 衔接 U3，VB2 依赖 U2 编辑闭环，VB3 按 P2 与领域能力扩展。依赖和排期入口见 [路线图](../radishflow-mvp-roadmap.md#变量与对象浏览器的配套切片)。

## 用户路径与交互

### 一个工作区、两种视图

目标为可停靠的浏览器，允许展开为完整工作页，与流程图和 Inspector 对照使用。具体位置、尺寸、窄窗口降级与入口由 R0 / R1 局部评审确定，现有模态窗口在替代路径验收前保持可用。

- 工程视图：按实际能力组织组分与物性、单元、流股、设计基础、工况与运行结果；同类对象可表格对照。分类为导航投影，不复制可变工程数据。
- 变量树视图：按对象、输入 / 结果、变量或集合展开，支持路径跳转、复制稳定引用及元数据详情。动作与变量区分呈现，标明参数、条件、撤销能力与调用结果。
- 两视图共享变量选择和读取上下文；过滤和折叠只改变呈现，不改变对象身份、结果资格或全局问题计数。
- 工程、模型、工况和运行结果上下文保持可见；当前仅显示已支持的文档 / 快照上下文，不提前提供无功能选择器。

候选布局为“上下文与搜索 + 分类 / 树 + 变量表 + 可展开详情”。主表优先显示对象、变量、值、单位和状态；路径、说明、约束、来源及关联置于详情。身份始终可查看，不要求普通用户记忆底层字段名。

### 核心操作

1. 搜索名称、变量、量或路径，筛选输入 / 结果、未指定 / 异常、对象类别和关注项。搜索结果保留对象、分区与上下文，避免同名变量混淆。
2. 从变量定位画布对象和 Inspector 字段；Inspector 提供反向打开变量的入口。非画布对象定位到其正式页面；没有目标时明确说明，不伪造画布节点。
3. 对同类对象查看相同字段；缺字段、未指定、无结果与不支持分别呈现，不用零填表。
4. 单值输入在支持后就地编辑；组成、互斥规格等组合通过专用编辑器提交。输出保持只读。
5. 将变量加入关注列表，在修改和运行后审阅；保存的是稳定引用及显示偏好，不是第二份值。关注列表不等于 N4 的条件监视或求解控制。
6. 分别复制数值、带单位数值、可读路径和稳定引用。结果复制 / 导出遵守 [当前结果门禁](results-review-diagnostics.md)，旧值不作为当前数值输出。

键盘可完成展开、搜索、选择、定位和编辑；右键操作同时提供可见入口。异步刷新不抢焦点或覆盖草稿，导航和切换上下文按 U2 的草稿规则处理，不自动提交或丢弃。浏览器切换不隐式运行、保存或创建对象。

### 代表性验收路径

在受支持流程中搜索所有出口温度→区分显式输入与结果→定位 H-101 的温度字段→按指定单位修改→Undo / Redo→正式运行→审阅关注变量→保存重开后恢复引用。H-101 仅为示例显示名；引用实际绑定稳定身份。VB1 先验收只读子路径，完整编辑路径在 VB2 验收。

## 身份、路径和读取上下文

### 稳定身份与路径

保留现有类型化身份；路径层负责解析和展示，解析结果通过同一查询 / 命令入口访问。人类导航路径和可持久引用明确区分。以下仅示意，尚未冻结协议：

```text
可读导航：主流程 / 单元 / H-101 / 输入 / 出口温度
稳定路径：/documents/{document_id}/units/{unit_id}/inputs/outlet_temperature
```

- 重命名、分类调整和视图切换不能破坏稳定引用；名称路径有歧义时返回候选或错误，不能任选一个。跨文档引用、删除对象与字段消失分别返回结构化失败。
- 路径编解码需明确版本、保留字符 / Unicode 转义、大小写、集合索引、别名与弃用策略；Rust `Debug` 输出、显示文案及单位符号不能作为稳定协议。
- 输入和结果是不同变量分区；设备端口中的流股入口引用同一流股，不复制对象。分类树、流程图与求解执行树不要求同构。
- 保存重开须能解析同一身份；另存为、复制模型、导入、删除后重建及跨工程回放的身份规则需要与生命周期专题审定。录制重放通过创建回执绑定新身份，不硬编码原案例 ID。

### 变量定义与取值上下文

变量定义描述“什么量、属于谁、如何访问”；取值带明确文档 / 修订及快照来源。后续扩展到模型、工况和运行身份时，外部调用显式指定上下文，界面选择只能生成请求，不能成为隐藏的取值前提。

AF4a 的工作区查询通过会话与输入身份检查快照归属，revision 本身不证明归属；旧的独立文档 / 快照构造仍要求调用者提供同一工作区数据。历史运行不能被当前文档值覆盖，跨工况不能串值，过期结果不降级成 current 返回。

当前 `ValueState` 与 `ValueSource` 保持；未来来源、输入合法性、结果时效、诊断严重度和可编辑性按各自语义组合，不扩大成互斥的大状态枚举。未指定、缺失、过期、不支持、未分析及数值零分别表达，草稿不冒充已提交工程值。

## 描述、数据与命令边界

### 共享描述与领域所有权

| 描述内容 | 责任与用途 |
| --- | --- |
| 稳定字段标识、名称、说明、分类 | 所属领域 / 应用描述提供；用于枚举、搜索、导航和协议映射 |
| 类型、形状、命名坐标轴 | 按模型实际需求扩展布尔、枚举、数组、组成、级数、时间和空间坐标 |
| 量类型、规范单位与基准 | 引用统一单位目录；质量 / 摩尔、表压等上下文转换遵守单位专题 |
| 可写条件、约束、选项与拒绝原因 | 由领域提供；“变量可写”与当前规格方案允许指定分别判断 |
| 值来源、修订、快照 / 运行身份 | 输入与结果所有者提供；浏览器不推断求解成功或工程可信度 |
| 导航目标、对象引用与动作描述 | 应用层映射正式页面 / 字段和命令；执行时重验实时条件 |

浏览器是领域数据的访问投影，不建立全局可变变量仓库，不把任意内部字段反射为公共写入入口。Core、对象模型、求解与结果各自拥有数据和行为；Rust Core 不承担 COM 语义。

现有变量枚举部分借用了 Inspector 字段函数。新增消费者时，应按实际复用将稳定字段描述归入共享应用描述，让 Inspector、浏览器与 CLI 消费；不为此预建插件注册框架或新增空 crate。公共传输 DTO 与 Rust 内部模型分离，已有 CLI v1 / v2 不被静默改义。

目录枚举、搜索和读取可分别执行；大集合按需展开、分页或范围读取，时空结果提供带坐标和来源的切片。只读界面按文档修订与结果身份刷新，避免每帧枚举并取出全部值；缓存仅为可失效投影。分页 / 订阅期间的修订一致性和资源限额随 VB3 消费者定义。

### 写入与批量事务

统一路径为：解析身份与上下文→单位 / 基准转换→修订、草稿及权限检查→类型与领域校验→正式输入事务→历史与结果旧化→返回回执。具体检查顺序复用既有应用入口，不在 GUI 或传输适配器复制领域约束。

- 单变量写入复用 B3-2 与 U2 数值会话。原始文本、临时输入单位、精度、冲突和提交 / 取消由同一草稿机制管理，不新增浏览器私有工程草稿。
- `write_via` / 元数据不能替代执行时检查；非 GUI 写入仍受 `PendingDrafts` 和 `expected_revision` 保护，不通过清草稿绕过冲突。
- 结果始终只读。改变显示单位只改变呈现，不增加物理输入修订或旧化结果；既有 CLI 继续按 SI 解释数值。
- 跨对象批量编辑须先建立正式批量事务：在一致输入上校验整个集合，一次提交、一次文档修订和一次撤销；任一失败不部分落地，失败定位具体变量。组合约束校验最终集合，不能靠顺序单写临时非法中间值。
- 多个副作用不同的动作不混成变量批量事务；Run、Save、创建、连接分别使用正式动作契约。现有 CLI 有序步骤的逐步回执 / 失败停止语义继续保持，不追溯改为整体原子执行。
- 相同有效输入继续返回无变化回执，不制造历史或旧化结果；真正修改后沿用统一失效与运行触发策略，不在循环写入时逐字段意外求解。

## AF4c 新版 CLI 契约（2026-10-26，已确认）

目标：让已有流程与独立设备能力通过本地无界面入口被发现、正式修改、检查、计算和读取，验证 GUI 与 CLI 的同源语义。以下完整批次契约已获所有者确认，AF4c-1—4 已完成：查询、正式输入 / 确认、同步运行、C1 采纳、公开示例及真实进程验收已接通。可用命令见[接口参考](../reference/headless-cli.md)，正式验证与未验平台见 [W44](../devlogs/2026-10/2026-W44.md)。

### 版本、命令与磁盘边界

- 新增 `--headless query <request.json>` 与 `--headless execute <request.json>`，请求 / 响应 `schema_version: 3`。前者只读，后者执行显式有序步骤；`execute` 不在结尾隐式 Run。版本号与工程 schema 独立，新入口接受受支持的工程 v1 / v2 / v3。
- 旧 `inspect`、`run` 的 v1 / v2 解析、响应、退出码、SI、逐步失败和所有 v3 文件的预操作拒绝保持；旧 `run` 收到新版请求仍拒绝，不按项目版本自动切换协议。
- 每次进程建立独立内存工作区，退出丢弃输入修改、历史、运行结果与待确认状态。首版保持磁盘只读：不提供 Save / Save As、工程 JSON 下载、CSV / JSON 文件导出、sidecar、最近项目或偏好写入；stdout 的协议 JSON 可由调用方保存为独立证据，不能当工程文件导入。磁盘持久化另行设计覆盖、升级确认、并发与失败恢复，不借新版版本号默认开放。
- 查询和纯编辑不需要缓存；流程 Run 才要求显式本地缓存根目录、索引和选包策略。独立设备检查 / 计算使用工程中已有依据，不强制装载流程物性包。沿用现有资格与授权，不自动登录、下载、生成演示物性或修改缓存。
- 新协议仍由 Studio 在 GUI 初始化前分派，复用现有桌面依赖；本批不拆独立 CLI crate，也不引入第三方依赖或修改 lockfile。设备同步执行不应为了满足旧函数签名伪造物性缓存，允许在应用层整理必要的资源参数边界。实现已提取 `execute_equipment_run_action`，既有缓存签名保持委托；采纳准备暴露实际设计来源及复制来源映射供摘要归一化，不从分配字符串反推身份。

### 输入身份与请求结构

共同必填字段为 `schema_version`、`project`、`queries`；所有路径相对请求文件目录，空路径拒绝。`query` 使用带唯一 `id` 的 `queries`，种类限定为 objects / fields / record / actions / results；根 objects 查询可无目标，其余查询显式指定范围。`execute` 另必填 `expected_project` 和有序 `steps`；只有含流程运行步骤时必填 `flow_resources`。query 不接受执行字段，无关资源字段拒绝。步骤和查询允许空数组，不接受 null 或省略；可选字段省略，不从 GUI 当前选择补值。

- `query` 返回 `document_id`、工程 schema、流程 revision 和 `file_sha256`；`execute.expected_project` 必须包含 `document_id` 与该指纹。指纹为实际读取的整个工程原始字节的 SHA-256，不忽略设备、未知能力、呈现配置或空白变化；不同内容即冲突，包括同 ID / 同流程 revision 的设备独立变更和工程分叉。这是保守的文件快照条件，不是身份认证或跨进程会话令牌。
- 每次装载只读一次工程字节，指纹与解析必须来自同一份字节，避免校验后再次读取产生竞态；之后本次任务针对该冻结内存输入执行，外部修改文件不被自动并入。可提取既有生命周期的纯解析 / 装配入口及 store 的通用字节摘要，保留既有物性摘要 golden，不复制 SHA 实现或把工程伪装成物性 payload。
- 文件条件只在入口校验。步骤执行前分别捕获并验证 `FlowEditContext` / `EquipmentActionContext`；查询使用 `ProjectQuery` 与结果资格入口。流程写入沿文档 revision，设备更新沿所属正式记录 revision；后续步骤可引用前序回执的版本，不能用捕获当前版本覆盖调用方提交的旧版本。设备不借用流程 revision，没有独立 revision 的 Sizing case 沿其 task 版本，不虚构新版本系统。
- 对象引用使用类型化 JSON：unit / stream、equipment task、含 task 与 case 的成员、geometry、basis、source；每个引用归请求的文档。字段使用显式领域枚举，量类型与规范单位来自共享目录；不发布 Rust Debug、显示名称、指针、checkpoint 或当前画布选择。此处不冻结完整字符串路径语言。
- 步骤为 `{id, action, confirmation?}`，`id` 非空白、唯一、大小写敏感。已有对象按稳定 ID 引用，新对象按 `{step, output}` 引用前序成功创建的具名输出，例如 task / case / source / unit / stream。禁止前向引用、重复 ID 和类型错配；绑定真实分配身份，不承诺分配字符串在两次运行相同。命令回执给出实际对象身份和前后版本。
- 顶层与嵌套字段均严格解析；拒绝重复键、未知字段 / 版本 / 枚举、错误数值类型与非有限数。先从原始字节严格反序列化，不能先转 JSON map 吞掉重复键。数值输入为规范 SI，不接受任意单位标签或字符串数字；直接值、依据引用和有理由的覆盖值分别映射已有 `InputBinding`，不丢弃来源。

### 影响确认与一次性进程

复用领域准备 / 确认，公开协议不直接序列化 `EngineeringCheckpoint`，也不接受 `force` / `confirm: true`。

1. 步骤触发影响确认或几何采纳时，先在本次工作区准备提案，输出 `confirmation_required`、结构化 `preview` 和 `confirmation_digest`；该步未提交，后续步骤不执行。前序成功的编辑和显式计算已经发生在本次内存中，预览不是“所有步骤只读试跑”。
2. 调用方审阅后，在原步骤中填回 `confirmation: {digest: ...}`，重新提交请求。新进程从相同工程快照重放前序步骤、重新计算所需候选并重新准备提案；摘要匹配才使用**本次新生成**的内存确认 key 提交。旧运行身份和旧 key 从不恢复。多次确认可逐步补齐，之前已确认步骤仍各自重验。
3. 摘要覆盖版本化命名空间、原工程指纹、当前步及前序动作的类型化内容、相关资源选择、实际目标 / 记录版本、全部影响与能力升级、旧 / 新输入；采纳还覆盖方法、候选数值、输入与来源证据、调整和旧 / 新几何。排除 confirmation 字段本身、显示文案、耗时、本次执行时间与临时运行 ID，但不能因此遗漏影响资格或采纳内容的字段。固定历史证据中的日期和审阅信息仍完整保留。
4. 同一版本以专用规范 DTO 编码摘要：对象键按字典序、紧凑 UTF-8、数字使用确定性有限数编码（负零归零）、字符串保留原值；有序步骤和成员顺序保留，语义集合按类型化身份排序。新建对象按创建步骤及具名输出归一化，包括采纳中即将新建的记录，不能依赖分配字符串碰巧重复。摘要算法使用 SHA-256，前缀 `af4c-confirm-v1:`；算法或审阅内容契约变化需新命名空间并拒绝旧摘要。
5. 摘要缺失返回待确认；不匹配返回 `confirmation_mismatch` 和新预览，保持该步未提交；本次没有确认需要却携带摘要也拒绝。摘要只是调用方对具体影响的明确同意，不是安全凭据；执行始终重验正式资格。实现需先在隔离副本准备并比较，再原子发布，不能在发现不匹配后留下该步的输入变更。

若上述跨进程重放无法稳定表达真实采纳证据，必须回到此契约修订，不能忽略证据、容差放宽摘要或偷偷跳过确认来让流程通过。

### 回执、失败与输出

- stdout 恰好一个最终 UTF-8 JSON；输出序列化 / 写出失败用 stderr 报告并返回 5。运行日志不混入 stdout；不发布流式事件、后台任务服务或跨进程取消承诺。直接终止进程不保证完整 JSON 终态。
- 响应包括协议版本、装载工程快照标识、按顺序的步骤回执、查询结果、停止位置和结构化错误。步骤保留 Committed / Unchanged、前后领域版本与影响；计算分别给出受理 / 启动失败、执行终态、接收处置与读取时结果资格。运行引用为本请求内 step 关联，内部 RunId / CalculationId 可通过本次输出的明确作用域映射关联来源，不导出指针或宣称是持久任务句柄。
- 第一处拒绝、失败或待确认停止后续动作；已成功步骤仅在本次内存生效，响应保留回执，不回滚成伪造的整体原子事务。最终 `queries` 对停止时的正式状态执行，每项独立返回值或错误；首个动作失败优先决定顶层状态，查询错误不掩盖原故障。查询本身不运行物性、刷新缓存或改变正式输入。
- 查询 Missing / Stale / Failed 是有效结果状态；单独检查返回问题列表也是成功调用。显式计算失败返回失败终态；rate 算法完成但校核不通过属于有效结果，不能从退出码 0 推断“设备合格”或物理准确。
- 新版退出码：0 为请求完成；2 为请求 / 装载 / 身份 / 版本冲突 / 查询错误；3 为只读、草稿、前置输入或能力等执行门禁拒绝；4 为已尝试计算的启动 / 执行失败；5 为响应输出失败；6 为待确认或确认内容变化。`error` 固定包含 `stage`、`code`、`step_id` / `query_id`（适用时）、类型化 `target` 和说明；程序不得解析说明文字。固定协议码包括 `unsupported_version`、`invalid_request`、`project_io`、`different_document`、`project_conflict`、`record_conflict`、`unsupported_capability`、`read_only_project`、`unknown_reference`、`reference_kind_mismatch`、`confirmation_mismatch`；领域原因通过显式枚举映射保留。
- 未知设备能力沿 `StudioProjectOpen::ReadOnly` 整份保护。query 只提供既有可安全读取的工程头、流程输入、任务数及只读原因；设备内部记录标记不可用，不把未知任务投影成已知类型。execute 在任何步骤前拒绝，即使只要求改流程部分。未知外层 schema、损坏结构直接装载失败，不丢弃设备区降级运行。
